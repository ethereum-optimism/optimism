This guide shows you how to enable and configure snap sync for your node. For an overview of how snap sync works and its benefits, see the [Snap Sync feature page](/node-operators/reference/features/snap-sync).

## Enable snap sync for your node

With snap sync, `op-node` tells the execution client to snap sync, and the EL downloads the state at tip via DevP2P, then switches to inserting blocks one by one once complete.

Snap sync requires no datadir on most OP Stack networks. For OP Mainnet, the [bedrock datadir](/node-operators/guides/management/snapshots) is required when using an execution client without a pre-Bedrock state import.

<Info>
  All EL clients should expose port `30303` TCP and `30303` UDP for inbound peer connections (sequencers and transaction ingress nodes excepted). If you override the default port on your EL, open the matching TCP and UDP ports.
</Info>

## Configuration

Each section below shows the flags needed on both `op-node` and your chosen execution client. The `op-node` flag `--syncmode=execution-layer` is required in all cases and is not the default — it must be explicitly configured.

### op-reth

op-reth snap-syncs by default via the engine API — no EL-side flag is required.

Set on `op-node`:

```shell
--syncmode=execution-layer
--l2.enginekind=reth
```

### Nethermind

Set on `op-node`:

```shell
--syncmode=execution-layer
```

Set on `Nethermind`:

```shell
--config op-mainnet
--Sync.SnapSync=true
```

<Warning>
  A single restart of Nethermind during snap sync may extend the sync time by up to 2 hours because Nethermind has to rebuild the caches by reading millions of values from the database.
</Warning>

### op-erigon

Set on `op-node`:

```shell
--syncmode=execution-layer
--l2.enginekind=erigon
```

op-erigon's default sync behavior works with op-node's execution-layer sync mode out of the box.

### op-geth

<Warning>
  **op-geth reaches end-of-support on 2026-05-31 and will not support the L1 Glamsterdam hardfork.** New deployments should use op-reth. See the [op-geth deprecation notice](/notices/op-geth-deprecation) for the full migration plan.
</Warning>

Set on `op-node`:

```shell
--syncmode=execution-layer
```

The following flag is the default setting for op-geth to enable snap sync, so you don't need to set it explicitly:

```shell
--syncmode=snap
```

## Alternative sync modes

Snap sync is the recommended sync mode for most node operators, but other sync modes are available depending on your needs:

*   **Archive nodes**: If you need to maintain complete historical state, see the [Archive Node guide](/node-operators/guides/management/archive-node)
*   **Consensus-layer sync**: For independent L1-based verification without P2P networking, see the [Consensus-Layer Sync reference](/node-operators/reference/consensus-layer-sync)
