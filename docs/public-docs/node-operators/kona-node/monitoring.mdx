This guide covers observability for a running `kona-node`: adjusting
log verbosity, filtering log targets, and collecting Prometheus
metrics into Grafana dashboards.

## Logging

<Unreleased component="kona-node" />

`kona-node` logs to stdout only, and only with `--logs.enabled`
(`KONA_NODE_LOGS_ENABLED=true`). To keep its logs in a file, redirect stdout.
`--logs.format` (`KONA_NODE_LOGS_FORMAT`) sets their format: `full` (the
default), `json`, `pretty`, `compact` or `logfmt`.

`kona-node` chooses which logs to keep with the `--logs.filter` flag, or the
`RUST_LOG` environment variable when the flag is not set. It defaults to
`info`. The filter uses the
[`RUST_LOG` syntax of the tracing_subscriber crate][tracing-env]: a
comma-separated list of directives, each a level, or a log target and the level
to log it at.

A level on its own applies to every log target. From the least detailed to the
most, the levels are:

- `error`: only error logs
- `warn`: warning and error logs
- `info`: informational logs, and the levels above
- `debug`: logs meant to print debugging information, and the levels above
- `trace`: very verbose logs that provide a detailed trace

`off` turns logging off. To log at the `debug` level, run the node like so:
`kona-node node --logs.enabled --logs.filter debug`.

### Filtering Log Targets

A directive for a log target sets the level for that target alone. For example,
`--logs.filter info,engine=debug` (or `RUST_LOG=info,engine=debug`) prints
`INFO` logs, and `DEBUG` logs from the `engine` target too. A target without a
directive of its own logs at the level on its own, so without one,
`--logs.filter engine=debug` prints only the `engine` target's logs.

When directives name the same target, the later one wins. `kona-node` puts
`discv5=off` before the filter, so discovery logs are off unless the filter
names `discv5`. This comes in handy say for when we would like to debug Kona's
P2P stack: `--logs.filter info,discv5=debug,libp2p=debug` adds debug logs from
the `discv5` and `libp2p` targets.

An invalid directive stops the node at startup. An empty filter, such as an
empty `RUST_LOG`, keeps no logs.

## Metrics

The `kona-node` can serve Prometheus metrics, which are disabled
by default. To turn them on, pass the `--metrics.enabled` cli flag, or set
`KONA_NODE_METRICS_ENABLED=true`.

Unless otherwise specified with the `--metrics.port` flag, metrics
are exposed on port `9090`. `--metrics.port` and `--metrics.addr` apply only
while metrics are enabled, so `--metrics.enabled=false` turns metrics off
without unsetting them.

To grab a snapshot of the metrics, you can visit `0.0.0.0:9090`
or `curl` the url.

```
curl 0.0.0.0:9090
```

The output should be raw text mapping metrics with their values.

Remember, this is just a snapshot of the metrics at that point
in time. To record and visualize the metrics, we'll use
[Grafana and Prometheus](#grafana-and-prometheus).


## Grafana and Prometheus

Prometheus is a simple service that scrapes metrics at a predefined
interval. Grafana then uses Prometheus as a "Data Source" to
visualize the collected metrics.

The Reth book provides a great overview to setting up [Prometheus
and Grafana][setup]. Visit the Reth docs to follow along.

The `kona-node` comes shipped with a default Grafana dashboard
for the `kona-node`. To import the dashboard to grafana, click
the `+` icon > `Import Dashboard` > paste the contents of [kona's
dashboard][dashboard] in the textbox > `Load`.
