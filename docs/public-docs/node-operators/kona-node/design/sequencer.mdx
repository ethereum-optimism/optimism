The Kona node can operate in **sequencer mode** to build and produce new L2 blocks. In this mode, the node acts as the sequencer for an OP Stack rollup, building L2 blocks on top of the current unsafe head and extending the L2 chain.

This page explains the design of sequencer mode and how to configure it programmatically through the Node SDK. To run `kona-node` as a sequencer from the command line, follow the [run a sequencer node](/node-operators/kona-node/run/sequencer) guide.

## Overview

When running in sequencer mode, the Kona node:

- **Builds L2 blocks** by collecting transactions from the mempool and constructing new blocks
- **Selects L1 origins** for new L2 blocks from confirmed L1 blocks, through the origin actor
- **Manages block production timing** and ensures proper sequencing constraints
- **Integrates with conductor services** for leader election in multi-sequencer setups
- **Handles recovery scenarios** when the sequencer needs to catch up with L1

The sequencer uses the same core derivation pipeline as validator nodes but operates in reverse - instead of deriving L2 blocks from L1 data, it produces L2 blocks that will later be derivable from L1.

## Core Components

### `NodeMode`

The node's operational mode is expressed by the `NodeMode` enum, the `mode` of the node's `RollupNodeConfig`:

```rust
pub enum NodeMode {
    /// Validator mode.
    Validator,
    /// Sequencer mode.
    Sequencer,
}
```

### `SequencerActor`

The core actor responsible for block production. It:

- Builds L2 blocks using the attributes builder
- Manages timing, and asks the origin actor for each block's L1 origin
- Handles admin RPC commands for sequencer control
- Coordinates with conductor services for leader election

### Origin actor

The origin actor, in `kona_node_actors::origin`, keeps the sequencer's next L1 origin ready, so that block production never waits on L1. It holds a window of L1 blocks: the L1 origin of the engine's unsafe head, then the canonical L1 blocks after it that are `l1_conf_delay` blocks below the L1 head. It follows the engine's published state and the L1 actor, does all of the L1 reads, and drops the blocks L1 reorgs out.

The sequencer asks `origin::Handle::next` for the L1 origin of the child of its unsafe head. The handle answers from the window without waiting: the child stays on its parent's origin until its timestamp reaches the next L1 block, and must move to the next block once past the sequencer drift. It fails with `OriginError::Unavailable` when there is no origin to build on yet, because the window does not hold the parent's origin yet, such as right after an engine reset, or because the child would pass the drift and L1 has no next origin yet; the sequencer retries on its next tick. It fails with `OriginError::Reorged` when L1 reorged out the parent's origin, on which the sequencer resets the engine. The sequencer never waits on L1, so it keeps serving its admin commands.

### `SequencerConfig`

Sequencers start stopped. Enable the admin API and issue `admin_startSequencer` to begin block production. Sequencer behavior is configured through the `SequencerConfig` struct:

```rust
pub struct SequencerConfig {
    /// The Url for the conductor RPC endpoint. If Some, enables the conductor service.
    pub conductor_rpc_url: Option<Url>,
    /// The confirmation delay for the sequencer.
    pub l1_conf_delay: u64,
}
```

## Programmatic Configuration

### Using the RollupNodeConfig

To configure a Kona node programmatically for sequencer mode, set the `RollupNodeConfig`'s `mode` to `NodeMode::Sequencer` and give it a `SequencerConfig`:

```rust
use kona_node_service::{
    NodeMode, RollupNode, RollupNodeClients, RollupNodeConfig, RollupNodeEndpoints, SequencerConfig,
};

// Configure sequencer settings
let sequencer_config = SequencerConfig {
    conductor_rpc_url: Some(            // Optional conductor integration
        Url::parse("http://conductor:8080").unwrap()
    ),
    l1_conf_delay: 4,                   // L1 origin confirmation delay
};

// A sequencer needs a block signer: `p2p_config.gossip_signer` must be
// `Some`, or `start` fails.
// `chain` is a `ChainSpec`: the rollup config, the L1 chain config and the
// interop dependency set.
let config = RollupNodeConfig {
    version,
    chain,
    mode: NodeMode::Sequencer,
    p2p_config,
    rpc_config,
    sequencer_config,
};
// Where the L1 and L2 endpoints are. Pass your own `RollupNodeClients`
// to `RollupNode::new` instead to connect to them differently.
let endpoints = RollupNodeEndpoints {
    l1_rpc,
    l1_beacon,
    l2_engine,
    l2_jwt_secret,
    derivation_delegate: None,
};
let clients = RollupNodeClients::connect(&endpoints)?;
RollupNode::new(config, clients).start().await?;
```

### Configuration Options

| Field | Description | Default |
|-------|-------------|---------|
| `conductor_rpc_url` | Conductor service endpoint for leader election | `None` |
| `l1_conf_delay` | Confirmation delay for L1 origin selection | `0` |
