The entry-point for the `kona-node` is the [`RollupNode`][node] service,
which encapsulates the core wiring for the node. A `RollupNode` is
created from a [`RollupNodeConfig`][config], plain data saying what the
node does, and a [`RollupNodeClients`][clients], the clients it talks to
L1 and L2 with, which `RollupNodeClients::connect` builds from the
[`RollupNodeEndpoints`][clients] saying where those are. Its
[`start` method][start] handles connecting the different components of
the node and running its actors in spawned tasks.

Most actors are built with a builder that hands out the actor's handle
before its dependencies exist, and expose a lifetime future that the
service spawns. The node stops when any actor reports a fatal error,
the RPC server stops, or the node shuts down.

Kona provides implementations for all actors required to run a
`RollupNode`. Actors are defined in the [`kona-node-actors`][actors]
crate, and the `RollupNode` wiring lives in the [service][service]
module of the `kona-node-service` crate.


### Actors

The architecture of `kona-node` is a web of actors that share
state through message passing, using channels, rather than using
shared memory.

The [`RollupNode`][node] builds and starts the following actors.

- **Derivation Actor**: Orchestrates the derivation pipeline,
  deriving L2 payload attributes from L1 blocks. Payload
  attributes prepared this way are forwarded to the Engine
  Actor to be executed. The [derivation][derivation] docs
  dive deeper into how the derivation actor works.
- **Discovery Actor**: Finds peers with `discv5` and passes
  them to the network actor to dial. See the [network][p2p]
  docs.
- **Engine Actor**: Brokers the connection to the execution
  layer client (or "execution engine"). The engine actor
  turns messages from other actors into engine "tasks"
  that are executed one at a time, in arrival order, against
  the EL client.
  Read-only engine queries are served directly by `RollupRpc`.
  The [engine][engine] docs expand on this.
- **L1 Actors**: Poll head, safe, and finalized blocks and
  publish the latest observations through watch channels.
  Derivation, finality, sequencing, and rollup RPC subscribe
  directly.
- **Finality Actor**: Finalizes derived L2 blocks once the
  L1 blocks they were derived from finalize, following the
  engine's published state. See the [derivation][derivation]
  docs.
- **L1 Signer Updater Actor**: Keeps the unsafe block signer
  current from the `SystemConfig` contract, for gossip
  validation and the signer actor.
- **Network Actor**: Runs the libp2p gossip swarm. It
  publishes the sequencer's signed blocks, passes the
  blocks it receives to the engine actor, and dials the
  peers the discovery actor finds. Visit the [network][p2p]
  docs for more detail.
- **Sequencer Actor**: The sequencer actor extends the
  `kona-node` to be run as a sequencer. Sequencing is
  periphery to the basic rollup node operation. See
  the [sequencer][sequencer] docs.
- **Signer Actor**: Runs alongside the sequencer actor.
  It signs each block the sequencer builds, in order,
  and passes it to the network actor to gossip.

The node also runs a JSON-RPC server, which is not an actor:
jsonrpsee dispatches requests straight to the registered
modules, including `RollupRpc`, which serves the rollup methods
required by the [OP Stack Specs][specs]. The modules read the
state the actors publish and send requests to their handles.
