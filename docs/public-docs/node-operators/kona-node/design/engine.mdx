The engine actor in `kona-node-service` owns execution mutations and resets. The
`kona-engine` crate supplies the Engine API client, state, ordinary execution operations,
and canonical reset traversal. The independent `kona-node` binary connects to an external
execution client such as op-reth through the Engine API.

## Execution ownership

Producers use a concrete `EngineHandle`. Its messages and reply channels stay private to
the service. Sequencing starts a build, retrieves its payload, obtains conductor acceptance when configured unless local recovery override is enabled,
then canonicalizes that exact payload.
Derivation submits attributes and waits for the actual accepted result. Gossip uses
bounded best-effort admission; reliable payload admission waits for capacity.

The owner serializes mutations and publishes one atomic `EngineState` snapshot before
acknowledging an attempt. The snapshot includes unsafe, local-safe, safe and finalized
heads, the pending-safe parent of an incomplete span, a reset epoch, and the current phase: initializing, syncing, resetting or ready.
The historical `el_sync_finished` flag records that a valid Engine API response has been
seen; it does not by itself mean that a reset has finished.

A reset increments the epoch even when it returns the same heads. Work prepared against
an old epoch or parent is rejected before it can change execution. Opaque build tokens
carry that context through retrieval and canonicalization.

## Scheduling and recovery

Acknowledged commands use a bounded mailbox. Unsafe payloads have a separate bounded
FIFO and one retained active attempt. Reset control has its own bounded lane, so an
unsafe backlog cannot prevent reset admission. Commands and eligible unsafe attempts
alternate, and commands continue during unsafe retry backoff.

The actor completes an in-flight Engine API call before processing reset control. It
reconciles uncertain forkchoice responses through reset before the next mutation. A
failed idempotent `newPayload` call can instead retry the same payload. Temporary reset
dependencies retain the reset and its bounded waiters; an invariant failure stops the node.

The engine initializes itself from actual execution heads, even on an idle validator. It
probes EL sync through the shared bounded client and publishes ready only after a fresh
`VALID` forkchoice response. A fresh EL waiting for its first forkchoice can confirm the
configured genesis when it advertises no later sync target. While EL sync is active, it preserves the accepted unsafe
sync target. Missing dependencies retry without requiring a new L1 event or admin request.

Initialization preserves Kona's bounded trusted-resume assumption when the EL has no
reusable safe checkpoint beyond genesis: a canonical recent-history epoch boundary supplies
a trusted resume checkpoint. Canonical origins and elapsed sequencing windows do not prove
local derivation. This exception does not advance finalized or create local finality records,
never overrides a known reusable checkpoint, and is consumed only after successful initialization.
Later resets use the prior completed-safe head as a ceiling and select an eligible epoch's
parent without crossing finalized. Pending span progress is never that ceiling.

The owner observes L1 head changes and checks applied heads' origins by canonical L1 number.
A missing historical read retries; a conflicting canonical hash initiates recovery. Sequencing
waits for a consistent context instead of independently requesting startup or origin resets.

## Derivation outcomes

Consolidation reports `Applied`, `Replaced` or `Dropped`. Before Holocene, an incomplete
span advances only pending-safe; a rejected later element rewinds it to completed safe.
Finalization never consumes a pending prefix. Holocene selection uses the L1
inclusion source's timestamp. A rejected pre-Holocene batch is dropped; a rejected
Holocene batch is replaced once with deposits only. A successful replacement advances the
actual safe state and instructs derivation to flush its channel before continuing. A
rejected deposits-only block is fatal. `ACCEPTED` and `SYNCING` are temporary responses
for derived imports and do not trigger replacement.

The owner records accepted completed-safe blocks and their actual L1 inclusion sources
before replying to consolidation. It considers records on new safe work and independent
L1 finality observations, so an idle derivation pipeline cannot strand finality. Before
moving finalized forkchoice it checks the epoch, completed-safe bound, canonical L2 hash,
canonical inclusion source and the observed finalized L1 signal itself. Temporary reads
retry independently; engine epoch invalidation clears the records.

Trusted delegation carries an explicit finalized claim alongside its safe update, without
local provenance. That claim waits through EL synchronization until the owner is ready.
Only a `VALID` response publishes proposed finality; `SYNCING` or an ambiguous forkchoice
response initiates recovery.

## Queries and observability

RPC handlers read configuration and the owner's accepted state and pending-work watches
directly. Output reads use the L2 provider independently, so a slow proof request cannot
stall other RPC reads. Before Isthmus, the proof is pinned to the fetched block's canonical
hash; after Isthmus, its withdrawals root comes from the same header. Pending work includes
admitted mailbox entries and active attempts, including while an execution RPC is stalled.
Owner-generated automatic finality has no mailbox admission and does not affect that count.

Existing engine operation metrics retain their wire names and labels. Block-label gauges
reflect published accepted state, including partial changes made before a later error.
Engine API versions follow the configured rollup hardfork schedule.

Admin reset and validated unsafe submission go directly to the engine handle when the
admin API is enabled, in both validator and sequencer modes. Unsafe submission acknowledges
bounded admission. Reset acknowledges the completed forkchoice recovery after publishing
its new epoch and accepted heads; it does not wait for derivation to consume that snapshot.
