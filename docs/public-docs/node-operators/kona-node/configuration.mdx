This document lists all CLI flags for the `kona-node node` subcommand, grouped by category. All flags can be provided as command-line arguments or via environment variables.

<Note>
For more details on each flag, see the inline help (`kona-node node --help`) or the source code.
</Note>

Flags that take a duration accept a number and a unit, such as `500ms`, `5s`, `30m` or `1h`.

<Unreleased component="kona-node" />

| Flag | Env | Description | Required | Default |
|------|-----|-------------|----------|---------|
| `--chain <ID/NAME>` | `KONA_NODE_CHAIN` | L2 chain ID (numeric) or chain name (string) to load the rollup config for from the superchain registry | One of these two | - |

`kona-node` does not run a supervisor RPC server, so there is no `--supervisor.*`
flag group.

### Chain ID Support

The `--chain` flag supports flexible chain identification using the `alloy_chains` crate:

**Numeric Chain IDs:**
```bash
kona-node node --chain 10 [args...]      # OP Mainnet
kona-node node --chain 8453 [args...]    # Base mainnet
```

**String Chain Names:**
```bash
kona-node node --chain optimism [args...]
kona-node node --chain base [args...]
```

**Environment Variable:**
```bash
export KONA_NODE_CHAIN=optimism && kona-node node [args...]
```

Supported chain names include all those recognized by `alloy_chains` (e.g., `optimism`, `base`). The chain must be in the superchain registry; for a custom network, use `--chain.rollup-config-path` instead.

## RPC Arguments

The RPC server starts once. If it stops unexpectedly, the node shuts down with an error.

<Unreleased component="kona-node" />

The node serves RPC only with `--rpc.enabled`. A sequencer requires it: its sequencer starts stopped, and is started through the admin API. The address and port apply only while RPC is enabled.

The RPC server always serves the [admin API](/node-operators/kona-node/rpc/admin), which can stop the sequencer and reset the node. Keep the RPC port off untrusted networks.

| Flag | Env | Description | Default |
|------|-----|-------------|---------|
| `--rpc.enabled[=<BOOL>]` | `KONA_NODE_RPC_ENABLED` | Serve the RPC API, including the admin API. The flag alone means `true` | `false` |
| `--rpc.addr <IP>` | `KONA_NODE_RPC_ADDR` | RPC listening address. Set it to `0.0.0.0` to reach the RPC from outside a container | `127.0.0.1` |
| `--rpc.port <PORT>` | `KONA_NODE_RPC_PORT` | RPC listening port | `9545` |

## Sequencer Arguments

<Unreleased component="kona-node" />

A node run with `--sequencer.enabled` can sequence. It requires `--rpc.enabled` and a block signer: `--sequencer.signer.key-path`, or `--sequencer.signer.url` with `--sequencer.signer.address`. Its sequencer starts stopped: call `admin_startSequencer` to begin block production. A node without `--sequencer.enabled` does not serve the sequencer's admin methods. The other sequencer flags apply only with `--sequencer.enabled`, and are ignored without it, so `--sequencer.enabled=false` turns a sequencer into a follower without unsetting them.

| Flag | Env | Description | Default |
|------|-----|-------------|---------|
| `--sequencer.enabled[=<BOOL>]` | `KONA_NODE_SEQUENCER_ENABLED` | Run the sequencer. Requires a block signer. The flag alone means `true` | `false` |
| `--sequencer.signer.key-path <PATH>` | `KONA_NODE_SEQUENCER_SIGNER_KEY_PATH` | Path to a file holding the hex-encoded private key that signs the sequencer's blocks. The file must exist | - |
| `--sequencer.signer.url <URL>` | `KONA_NODE_SEQUENCER_SIGNER_URL` | Remote op-signer that signs the sequencer's blocks, instead of a local key. Requires `--sequencer.signer.address` | - |
| `--sequencer.signer.address <ADDRESS>` | `KONA_NODE_SEQUENCER_SIGNER_ADDRESS` | Address of the remote op-signer's key | - |
| `--sequencer.signer.header <NAME=VALUE>` | `KONA_NODE_SEQUENCER_SIGNER_HEADER` | Header to send to the remote op-signer. Pass the flag once per header; the environment variable sets a single header | - |
| `--sequencer.signer.tls.ca-path <PATH>` | `KONA_NODE_SEQUENCER_SIGNER_TLS_CA_PATH` | CA certificates that verify the remote op-signer | - |
| `--sequencer.signer.tls.cert-path <PATH>` | `KONA_NODE_SEQUENCER_SIGNER_TLS_CERT_PATH` | Client certificate presented to the remote op-signer. Requires `--sequencer.signer.tls.key-path` | - |
| `--sequencer.signer.tls.key-path <PATH>` | `KONA_NODE_SEQUENCER_SIGNER_TLS_KEY_PATH` | Private key of the client certificate. Requires `--sequencer.signer.tls.cert-path` | - |
| `--sequencer.l1-confs <N>` | `KONA_NODE_SEQUENCER_L1_CONFS` | L1 block confirmations for sequencer | `4` |
| `--sequencer.conductor.url <URL>` | `KONA_NODE_SEQUENCER_CONDUCTOR_URL` | RPC endpoint URL of an external conductor service. Supplying it enables the conductor integration | - |
| `--sequencer.conductor.timeout <DURATION>` | `KONA_NODE_SEQUENCER_CONDUCTOR_TIMEOUT` | How long a conductor request may take before it fails and the sequencer tries again later | `1s` |

## Logging Arguments

<Unreleased component="kona-node" />

`kona-node` logs to stdout only. Redirect stdout to keep its logs in a file.

| Flag | Env | Description | Default |
|------|-----|-------------|---------|
| `--logs.enabled[=<BOOL>]` | `KONA_NODE_LOGS_ENABLED` | Print logs to stdout. The flag alone means `true` | `false` |
| `--logs.level <LEVEL>` | `KONA_NODE_LOGS_LEVEL` | The most detailed level to log: `error`, `warn`, `info`, `debug` or `trace` | `info` |
| `--logs.format <FORMAT>` | `KONA_NODE_LOGS_FORMAT` | The format of the logs: `full`, `json`, `pretty`, `compact` or `logfmt` | `full` |

## RPC Response Verification

`kona-node` does not trust the L1 RPC: every L1 header and block it fetches by hash is checked
to hash to the hash it asked for, so an RPC cannot serve different block contents under a
requested hash. It trusts the L2 execution client given by `--l2.engine.url`, which should be
the node's own, authenticated with the JWT secret. Neither behavior is configurable.

## Default Behavior

Unless overridden by the flags above, a `kona-node node` run has the following defaults:

- P2P is disabled: the node follows the chain by deriving it from L1.
  With `--p2p.enabled`, the libp2p swarm listens on TCP `9222` to
  receive and gossip blocks, with peer scoring. Peer discovery is
  disabled even then; with `--p2p.discovery.enabled`, the `discv5`
  discovery service runs on UDP port `9223`.
- No RPC is served. Enable it with `--rpc.enabled`; it is then served at
  `127.0.0.1:9545`, configurable via the `--rpc.addr` and `--rpc.port` flags.
- Logs are disabled. Enable them with `--logs.enabled`; they are then
  printed to stdout.
- Prometheus metrics are disabled. Enable them with the
  `--metrics.enabled` flag; metrics are then served on `0.0.0.0:9090`,
  configurable via the `--metrics.port` and `--metrics.addr` flags.

## Rollup Configuration Loading

The rollup config comes from exactly one of two sources:

- `--chain` loads it from the [superchain registry][scr].
- `--chain.rollup-config-path` loads it from a file, for a chain that is not in the registry.

`kona-node` exits with an error if neither or both are set.

Override flags (`--chain.hardfork.<NAME>-time` and `--chain.keep-karst-upgrade-gas`) change values in
the rollup config from either source. They can be viewed in the help
menu by running `kona-node node --help`. They override hardfork
activation timestamps, in seconds, and `keep_karst_upgrade_gas`.

[scr]: https://github.com/ethereum-optimism/superchain-registry/tree/main
