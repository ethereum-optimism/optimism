This document lists all CLI flags for the `kona-node node` subcommand, grouped by category. All flags can be provided as command-line arguments or via environment variables.

<Note>
For more details on each flag, see the inline help (`kona-node node --help`) or the source code.
</Note>

Flags that take a duration accept a number and a unit, such as `500ms`, `5s`, `30m` or `1h`.

## Chain Arguments

<Unreleased component="kona-node" />

| Flag | Env | Description | Required | Default |
|------|-----|-------------|----------|---------|
| `--chain <ID/NAME>` | `KONA_NODE_CHAIN` | L2 chain ID (numeric) or chain name (string) to load the rollup config for from the superchain registry | One of these two | - |
| `--chain.rollup-config-path <PATH>` | `KONA_NODE_CHAIN_ROLLUP_CONFIG_PATH` | Path to an L2 rollup configuration file, for a chain that is not in the superchain registry | One of these two | - |

| `--chain.hardfork.<NAME>-time <TIMESTAMP>` | `KONA_NODE_CHAIN_HARDFORK_<NAME>_TIME` | Overrides a hardfork's activation timestamp: `canyon`, `delta`, `ecotone`, `fjord`, `granite`, `holocene`, `pectra-blob-schedule`, `isthmus`, `jovian`, `karst` or `lagoon` | No | - |

`kona-node` does not run a supervisor RPC server, so there is no `--supervisor.*`
flag group.

### Chain ID Support

The `--chain` flag supports flexible chain identification using the `alloy_chains` crate:

**Numeric Chain IDs:**
```bash
kona-node node --chain 10 [args...]      # OP Mainnet
kona-node node --chain 8453 [args...]    # Base mainnet
```

**String Chain Names:**
```bash
kona-node node --chain optimism [args...]
kona-node node --chain base [args...]
```

**Environment Variable:**
```bash
export KONA_NODE_CHAIN=optimism && kona-node node [args...]
```

Supported chain names include all those recognized by `alloy_chains` (e.g., `optimism`, `base`). The chain must be in the superchain registry; for a custom network, use `--chain.rollup-config-path` instead.

## P2P Arguments

The other P2P flags apply only with `--p2p.enabled`.

| Flag | Env | Description | Default |
|------|-----|-------------|---------|
| `--p2p.enabled[=<BOOL>]` | `KONA_NODE_P2P_ENABLED` | Receive and gossip blocks over P2P. When disabled, the node only follows the safe chain (unless it is a sequencer, when it also produces the ungossiped unsafe chain) | `false` |
| `--p2p.priv-path <PATH>` | `KONA_NODE_P2P_PRIV_PATH` | Path to a file holding the hex-encoded 32-byte private key of the node's peer ID, created with a new key if it does not exist. Keep it across restarts to keep the peer ID | A new peer ID at each start |
| `--p2p.listen.addr <HOST>` | `KONA_NODE_P2P_LISTEN_ADDR` | IP address or DNS hostname to listen for peers on. A hostname is resolved when the node starts | `0.0.0.0` |
| `--p2p.listen.tcp-port <PORT>` | `KONA_NODE_P2P_LISTEN_TCP_PORT` | TCP port to listen for peers on. `0` picks any free port | `9222` |
| `--p2p.listen.udp-port <PORT>` | `KONA_NODE_P2P_LISTEN_UDP_PORT` | UDP port for discovery to listen on. `0` picks any free port | `9223` |
| `--p2p.advertise.addr <HOST>` | `KONA_NODE_P2P_ADVERTISE_ADDR` | IP address or DNS hostname for discovery to advertise to peers, such as a public address behind a NAT. Setting it stops discovery from updating the advertised address from what peers report. Used only with `--p2p.discovery.enabled` | The listen address |
| `--p2p.advertise.tcp-port <PORT>` | `KONA_NODE_P2P_ADVERTISE_TCP_PORT` | TCP port for discovery to advertise to peers | The listen TCP port |
| `--p2p.advertise.udp-port <PORT>` | `KONA_NODE_P2P_ADVERTISE_UDP_PORT` | UDP port for discovery to advertise to peers | The listen UDP port |
| `--p2p.gossip.mesh.d <N>` | `KONA_NODE_P2P_GOSSIP_MESH_D` | GossipSub mesh target degree: how many peers to keep in the mesh and send blocks to | `8` |
| `--p2p.gossip.mesh.lo <N>` | `KONA_NODE_P2P_GOSSIP_MESH_LO` | GossipSub mesh low watermark: with fewer peers in the mesh, the node adds more | `6` |
| `--p2p.gossip.mesh.dhi <N>` | `KONA_NODE_P2P_GOSSIP_MESH_DHI` | GossipSub mesh high watermark: with more peers in the mesh, the node prunes it | `12` |
| `--p2p.gossip.mesh.dlazy <N>` | `KONA_NODE_P2P_GOSSIP_MESH_DLAZY` | GossipSub gossip target: how many peers outside the mesh to announce blocks to, without sending them the blocks | `6` |
| `--p2p.gossip.mesh.flood-publish.enabled[=<BOOL>]` | `KONA_NODE_P2P_GOSSIP_MESH_FLOOD_PUBLISH_ENABLED` | Publish the node's own blocks to every known peer on the topic, not only to its mesh | `false` |
| `--p2p.peer-scoring <LEVEL>` | `KONA_NODE_P2P_PEER_SCORING` | How to score peers by their behavior: `off` or `light` | `light` |
| `--p2p.topic-scoring.enabled[=<BOOL>]` | `KONA_NODE_P2P_TOPIC_SCORING_ENABLED` | Also score peers by their behavior on each gossip topic. Kept for compatibility and debugging: op-node is phasing topic scoring out | `false` |
| `--p2p.ban.enabled[=<BOOL>]` | `KONA_NODE_P2P_BAN_ENABLED` | Ban peers whose score falls below `--p2p.ban.threshold`, for `--p2p.ban.duration` | `false` |
| `--p2p.ban.threshold <SCORE>` | `KONA_NODE_P2P_BAN_THRESHOLD` | The score below which a peer is banned | `-100` |
| `--p2p.ban.duration <DURATION>` | `KONA_NODE_P2P_BAN_DURATION` | How long to ban a peer for | `1h` |
| `--p2p.redial.max-attempts <N>` | `KONA_NODE_P2P_REDIAL_MAX_ATTEMPTS` | How many times to redial a peer that disconnects, within each `--p2p.redial.period`. `0` redials it indefinitely | `500` |
| `--p2p.redial.period <DURATION>` | `KONA_NODE_P2P_REDIAL_PERIOD` | How long after a peer was last dialed its count of redials resets | `1h` |
| `--p2p.discovery.enabled[=<BOOL>]` | `KONA_NODE_P2P_DISCOVERY_ENABLED` | Find peers with discv5. Without it, the node keeps only the peers it is told to connect to, and those that connect to it, and ignores the other discovery flags | `false` |
| `--p2p.discovery.bootnodes <ENR,...>` | `KONA_NODE_P2P_DISCOVERY_BOOTNODES` | Comma-separated ENRs or enode URLs of nodes to start discovery from, in addition to the chain's built-in bootnodes | - |
| `--p2p.discovery.interval <DURATION>` | `KONA_NODE_P2P_DISCOVERY_INTERVAL` | How often discovery looks for new peers | `5s` |
| `--p2p.discovery.randomize <DURATION>` | `KONA_NODE_P2P_DISCOVERY_RANDOMIZE` | How often to drop a random peer from discovery, so that it finds a wider set of peers | Never |
| `--p2p.discovery.bootstore.enabled[=<BOOL>]` | `KONA_NODE_P2P_DISCOVERY_BOOTSTORE_ENABLED` | Keep the peers discovery finds in a bootstore, to find them again after a restart | `false` |
| `--p2p.discovery.bootstore.path <PATH>` | `KONA_NODE_P2P_DISCOVERY_BOOTSTORE_PATH` | Path to the bootstore file | `~/.kona/<CHAIN_ID>/bootstore.json` |

## RPC Arguments

The RPC server starts once. If it stops unexpectedly, the node shuts down with an error.

<Unreleased component="kona-node" />

The node serves RPC only with `--rpc.enabled`. A sequencer requires it: its sequencer starts stopped, and is started through the admin API. The address and port apply only while RPC is enabled.

The RPC server always serves the [admin API](/node-operators/kona-node/rpc/admin), which can stop the sequencer and reset the node. Keep the RPC port off untrusted networks.

| Flag | Env | Description | Default |
|------|-----|-------------|---------|
| `--rpc.enabled[=<BOOL>]` | `KONA_NODE_RPC_ENABLED` | Serve the RPC API, including the admin API. The flag alone means `true` | `false` |
| `--rpc.addr <IP>` | `KONA_NODE_RPC_ADDR` | RPC listening address. Set it to `0.0.0.0` to reach the RPC from outside a container | `127.0.0.1` |
| `--rpc.port <PORT>` | `KONA_NODE_RPC_PORT` | RPC listening port | `9545` |

## Sequencer Arguments

<Unreleased component="kona-node" />

A node run with `--sequencer.enabled` can sequence. It requires `--rpc.enabled`, and with `--p2p.enabled` a block signer: see [Signer Arguments](#signer-arguments). Its sequencer starts stopped: call `admin_startSequencer` to begin block production. A node without `--sequencer.enabled` does not serve the sequencer's admin methods. The other sequencer flags apply only with `--sequencer.enabled`, and are ignored without it, so `--sequencer.enabled=false` turns a sequencer into a follower without unsetting them.

| Flag | Env | Description | Default |
|------|-----|-------------|---------|
| `--sequencer.enabled[=<BOOL>]` | `KONA_NODE_SEQUENCER_ENABLED` | Run the sequencer. Requires `--rpc.enabled`, and with `--p2p.enabled` a block signer. The flag alone means `true` | `false` |
| `--sequencer.l1-confs <N>` | `KONA_NODE_SEQUENCER_L1_CONFS` | How many blocks behind the L1 head the sequencer picks its L1 origins | `4` |
| `--sequencer.conductor.url <URL>` | `KONA_NODE_SEQUENCER_CONDUCTOR_URL` | URL of the op-conductor RPC API. Setting it puts the sequencer behind the conductor | - |
| `--sequencer.conductor.timeout <DURATION>` | `KONA_NODE_SEQUENCER_CONDUCTOR_TIMEOUT` | How long a conductor request may take before it fails and the sequencer tries again later | `1s` |

## Signer Arguments

<Unreleased component="kona-node" />

The block signer signs the blocks a sequencer builds, so that it can gossip them. A node uses and requires one only when `--sequencer.enabled` and `--p2p.enabled`: give `--signer.key-path`, or `--signer.remote.url` with `--signer.remote.address`. Any other node ignores the signer flags: it still parses each value, but does not check how they combine, nor read the key file.

| Flag | Env | Description | Default |
|------|-----|-------------|---------|
| `--signer.key-path <PATH>` | `KONA_NODE_SIGNER_KEY_PATH` | Path to a file holding the hex-encoded private key that signs the sequencer's blocks. The file must exist. Give this or `--signer.remote.url` | - |
| `--signer.remote.url <URL>` | `KONA_NODE_SIGNER_REMOTE_URL` | Remote op-signer that signs the sequencer's blocks. Give this or `--signer.key-path` | - |
| `--signer.remote.address <ADDRESS>` | `KONA_NODE_SIGNER_REMOTE_ADDRESS` | Address of the remote op-signer's key. Requires `--signer.remote.url` | - |
| `--signer.remote.header <NAME=VALUE>` | `KONA_NODE_SIGNER_REMOTE_HEADER` | Header to send to the remote op-signer. Pass the flag once per header; the environment variable sets a single header. Requires `--signer.remote.url` | - |
| `--signer.remote.tls.ca-path <PATH>` | `KONA_NODE_SIGNER_REMOTE_TLS_CA_PATH` | CA certificates that verify the remote op-signer. Requires `--signer.remote.url` | - |
| `--signer.remote.tls.cert-path <PATH>` | `KONA_NODE_SIGNER_REMOTE_TLS_CERT_PATH` | Client certificate presented to the remote op-signer. Requires `--signer.remote.url` and `--signer.remote.tls.key-path` | - |
| `--signer.remote.tls.key-path <PATH>` | `KONA_NODE_SIGNER_REMOTE_TLS_KEY_PATH` | Private key of the client certificate. Requires `--signer.remote.url` and `--signer.remote.tls.cert-path` | - |

## RPC Response Verification

`kona-node` does not trust the L1 RPC: every L1 header and block it fetches by hash is checked
to hash to the hash it asked for, so an RPC cannot serve different block contents under a
requested hash. It trusts the L2 execution client given by `--l2.engine.url`, which should be
the node's own, authenticated with the JWT secret. Neither behavior is configurable.

## Default Behavior

Unless overridden by the flags above, a `kona-node node` run has the following defaults:

- P2P is disabled: the node follows the chain by deriving it from L1.
  With `--p2p.enabled`, the libp2p swarm listens on TCP `9222` to
  receive and gossip blocks, with peer scoring. Peer discovery is
  disabled even then; with `--p2p.discovery.enabled`, the `discv5`
  discovery service runs on UDP port `9223`.
- No RPC is served. Enable it with `--rpc.enabled`; it is then served at
  `127.0.0.1:9545`, configurable via the `--rpc.addr` and `--rpc.port` flags.
- Logs are disabled. Enable them with `--logs.enabled`; they are then
  printed to stdout.
- Prometheus metrics are disabled. Enable them with the
  `--metrics.enabled` flag; metrics are then served on `0.0.0.0:9090`,
  configurable via the `--metrics.port` and `--metrics.addr` flags.

## Rollup Configuration Loading

The rollup config comes from exactly one of two sources:

- `--chain` loads it from the [superchain registry][scr].
- `--chain.rollup-config-path` loads it from a file, for a chain that is not in the registry.

`kona-node` exits with an error if neither or both are set.

Override flags (`--chain.hardfork.<NAME>-time` and `--chain.keep-karst-upgrade-gas`) change values in
the rollup config from either source. They can be viewed in the help
menu by running `kona-node node --help`. They override hardfork
activation timestamps, in seconds, and `keep_karst_upgrade_gas`.

[scr]: https://github.com/ethereum-optimism/superchain-registry/tree/main
