This guide shows how to run `kona-node` in **sequencer mode** from the command line. For how sequencer mode works internally and how to configure it programmatically through the Node SDK, see the [sequencer mode design](/node-operators/kona-node/design/sequencer) page.

<Info>
Sequencer mode is an advanced configuration primarily used by rollup operators. Most users will run nodes in the default validator mode.
</Info>

## Basic Sequencer Setup

To run a Kona node in sequencer mode:

```bash
kona-node node \
  --mode=Sequencer \
  --rpc.enable-admin \
  --l1-eth-rpc=http://l1-node:8545 \
  --l1-beacon=http://l1-beacon:5052 \
  --l2-engine-rpc=http://l2-execution:8551 \
  --l2-engine-jwt-secret=./jwt.hex \
  --p2p.sequencer.key.path=./p2p-sequencer.key \
  --l2-config-file=./rollup.json
```

Sequencers start stopped after every restart. Once the node is running, start block production through the admin API:

```bash
curl http://localhost:9545 \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":1,"method":"admin_startSequencer","params":[]}'
```

A conductor can issue the start request for managed sequencers. The admin API must be enabled for it to control sequencing.

## Required Arguments

<Warning>
**Required Configuration**

Sequencer mode requires all standard node arguments plus the `--mode=Sequencer` flag and a block signer. Missing any required argument will prevent the node from starting.
</Warning>

| Argument | Flag | Environment Variable | Description |
|----------|------|---------------------|-------------|
| **Mode** | `--mode` | `KONA_NODE_MODE` | Must be set to `Sequencer` |
| **L1 RPC** | `--l1-eth-rpc` | `KONA_NODE_L1_ETH_RPC` | L1 execution client RPC URL |
| **L1 Beacon** | `--l1-beacon` | `KONA_NODE_L1_BEACON` | L1 beacon API URL |
| **L2 Engine** | `--l2-engine-rpc` | `KONA_NODE_L2_ENGINE_RPC` | L2 engine API endpoint |
| **JWT Secret** | `--l2-engine-jwt-secret` | `KONA_NODE_L2_ENGINE_AUTH` | Path to JWT secret file |
| **Rollup Config** | `--l2-config-file` or `--chain` | `KONA_NODE_ROLLUP_CONFIG` or `KONA_NODE_L2_CHAIN_ID` | Exactly one: the rollup config file, or the chain to load it for from the superchain registry |
| **Block Signer** | `--p2p.sequencer.key.path`, `--p2p.sequencer.key`, or `--p2p.signer.endpoint` with `--p2p.signer.address` | `KONA_NODE_P2P_SEQUENCER_KEY_PATH`, `KONA_NODE_P2P_SEQUENCER_KEY`, `KONA_NODE_P2P_SIGNER_ENDPOINT`, `KONA_NODE_P2P_SIGNER_ADDRESS` | Signs the blocks the sequencer gossips: a local key, or a remote op-signer |

## Sequencer-Specific Flags

| Flag | Environment Variable | Default | Description |
|------|---------------------|---------|-------------|
| `--sequencer.l1-confs` | `KONA_NODE_SEQUENCER_L1_CONFS` | `4` | L1 confirmations for origin selection |
| `--conductor.rpc` | `KONA_NODE_CONDUCTOR_RPC` | - | Conductor service RPC endpoint |

The full flag catalogue, including the standard node arguments shared with validator mode, lives in the [Kona node CLI reference](/node-operators/kona-node/configuration).

## Example Configurations

### Basic Sequencer
```bash
kona-node node \
  --mode=Sequencer \
  --rpc.enable-admin \
  --l1-eth-rpc=http://localhost:8545 \
  --l1-beacon=http://localhost:5052 \
  --l2-engine-rpc=http://localhost:8551 \
  --l2-engine-jwt-secret=./jwt.hex \
  --p2p.sequencer.key.path=./p2p-sequencer.key \
  --l2-config-file=./rollup.json
```

### Sequencer with Conductor
```bash
kona-node node \
  --mode=Sequencer \
  --rpc.enable-admin \
  --conductor.rpc=http://conductor:8080 \
  --sequencer.l1-confs=6 \
  --l1-eth-rpc=http://l1-node:8545 \
  --l1-beacon=http://l1-beacon:5052 \
  --l2-engine-rpc=http://l2-execution:8551 \
  --l2-engine-jwt-secret=./jwt.hex \
  --p2p.sequencer.key.path=./p2p-sequencer.key \
  --l2-config-file=./rollup.json
```

## Key Considerations

<Tip>
**Sequencer Operation**

- **L1 Confirmations**: The `--sequencer.l1-confs` setting determines how many L1 blocks the sequencer waits before using an L1 block as an origin. Higher values provide more safety but increase latency.
- **Conductor Integration**: For multi-sequencer deployments, configure the conductor service for proper leader election.
</Tip>

Running a sequencer in production requires careful consideration of infrastructure, monitoring, and failover procedures. Ensure proper JWT secret management and secure network configuration.
