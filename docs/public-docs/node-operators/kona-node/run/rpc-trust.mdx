The `--l1-trust-rpc` and `--l2-trust-rpc` flags control whether Kona performs additional verification on RPC responses to protect against malicious or faulty RPC providers. This guide helps you choose the right setting for your infrastructure and shows how to configure it.

## Trust Modes

The defaults match op-node: L1 trust is disabled (`false`), while L2 engine trust is enabled (`true`). To retain the previous L1 trust behavior, set `--l1-trust-rpc=true` or `KONA_NODE_L1_TRUST_RPC=true`.

**Trust Mode (trust enabled, `true`):**
- RPC responses are used without verification
- Optimized for performance
- Suitable for local nodes and trusted infrastructure
- Assumes the RPC provider is reliable and honest

**Verification Mode (trust disabled, `false`):**
- Every L1 header is checked against its block hash, and every L1 block found by number must be at that number
- Each L1 block's transactions and receipts are checked against the header's transactions and receipts roots
- The unsafe block signer, read from the `SystemConfig` contract on L1, is proven against the block's state root with `eth_getProof`
- L2 blocks looked up by hash are checked against their block hashes
- Protects against malicious or faulty RPC providers returning incorrect data
- Recommended for public or third-party RPC endpoints
- Small performance overhead from the checks

<Note>
With `--l1-trust-rpc=false`, the L1 RPC must serve `eth_getProof` for recent blocks. Without it, `kona-node` cannot read the unsafe block signer and fails to start. At startup, `kona-node` reads the signer at the L1 head and makes up to five attempts, 10 seconds apart, each at the then-current head.

By default, Reth serves `eth_getProof` only for its head block (`--rpc.eth-proof-window` is 0), so a read fails whenever a new L1 block arrives before it completes. If your L1 RPC is Reth, set `--rpc.eth-proof-window` to a few blocks or more.
</Note>

## Examples

**Using trusted local RPCs:**
```bash
kona-node node \
  --l1-eth-rpc http://localhost:8545 \
  --l1-trust-rpc=true \
  --l2-engine-rpc http://localhost:8551 \
  # L2 trust-rpc defaults to true
```

**Using untrusted public RPCs:**
```bash
kona-node node \
  --l1-eth-rpc https://public-eth-rpc.com \
  --l1-trust-rpc=false \
  --l2-engine-rpc https://public-l2-rpc.com \
  --l2-trust-rpc=false
```

**Mixed trust configuration:**
```bash
kona-node node \
  --l1-eth-rpc https://public-eth-rpc.com \
  --l1-trust-rpc=false \
  --l2-engine-rpc http://localhost:8551 \
  # L2 trust-rpc defaults to true for local engine
```

## Security Recommendations

1. **Local Infrastructure**: Use trust mode (`true`) only for RPCs you control
2. **Public RPCs**: Use `--l1-trust-rpc=false` and `--l2-trust-rpc=false` for third-party endpoints
3. **Shared Infrastructure**: Consider disabling trust for both RPCs
4. **Performance Testing**: The verification overhead is minimal but can be measured in high-throughput scenarios
