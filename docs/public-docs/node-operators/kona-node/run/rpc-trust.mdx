The `--l1-trust-rpc` flag controls whether Kona performs additional verification on L1 RPC responses to protect against malicious or faulty RPC providers. This guide helps you choose the right setting for your infrastructure and shows how to configure it.

The L2 engine is not covered by a trust flag. It is the node's own execution client, reached over the authenticated Engine API, and an execution client that misreports blocks already controls the node's view of the chain. Kona therefore always trusts it, as op-node does.

## Trust Modes

The default matches op-node: L1 trust is disabled (`false`). To retain the previous L1 trust behavior, set `--l1-trust-rpc=true` or `KONA_NODE_L1_TRUST_RPC=true`.

**Trust Mode (trust enabled, `true`):**
- RPC responses are used without verification
- Optimized for performance
- Suitable for local nodes and trusted infrastructure
- Assumes the RPC provider is reliable and honest

**Verification Mode (trust disabled, `false`):**
- Every L1 header is checked against its block hash, and every L1 block found by number must be at that number
- Each L1 block's transactions and receipts are checked against the header's transactions and receipts roots
- The unsafe block signer, read from the `SystemConfig` contract on L1, is proven against the block's state root with `eth_getProof`
- Protects against malicious or faulty RPC providers returning incorrect data
- Recommended for public or third-party RPC endpoints
- Small performance overhead from the checks

<Note>
With `--l1-trust-rpc=false`, the L1 RPC must serve `eth_getProof` for recent blocks. Without it, `kona-node` cannot read the unsafe block signer and fails to start.
</Note>

## Examples

**Using a trusted local L1 RPC:**
```bash
kona-node node \
  --l1-eth-rpc http://localhost:8545 \
  --l1-trust-rpc=true \
  --l2-engine-rpc http://localhost:8551
```

**Using an untrusted public L1 RPC:**
```bash
kona-node node \
  --l1-eth-rpc https://public-eth-rpc.com \
  --l1-trust-rpc=false \
  --l2-engine-rpc http://localhost:8551
```

## Security Recommendations

1. **Local Infrastructure**: Use trust mode (`true`) only for an L1 RPC you control
2. **Public RPCs**: Use `--l1-trust-rpc=false` for third-party endpoints
3. **Shared Infrastructure**: Consider disabling trust when the L1 RPC is shared
4. **Performance Testing**: The verification overhead is minimal but can be measured in high-throughput scenarios
