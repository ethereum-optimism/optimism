The `kona-node` supports JSON-RPC for interacting with the node.

By default, `kona-node` exposes JSON-RPC over HTTP and WebSocket on the same
listening address and port. All registered methods are available over both
transports. IPC transport is not supported.

### Namespaces

JSON-RPC methods are grouped into namespaces, which are listed below:

| Namespace                    | Description                                                                                            | Sensitive |
| ---------------------------- | ------------------------------------------------------------------------------------------------------ | --------- |
| [`p2p`](/node-operators/kona-node/rpc/p2p)        | The `p2p` API allows you to configure the p2p stack.                                                   | Maybe     |
| [`rollup`](/node-operators/kona-node/rpc/rollup)  | The `rollup` API provides OP Stack specific rpc methods.                                               | No        |
| [`admin`](/node-operators/kona-node/rpc/admin)    | The `admin` API allows you to configure your node.                                                     | **Yes**   |


### Interacting with the RPC

Kona always serves these RPC methods, including the `admin` namespace. The RPC binds `127.0.0.1` by default; see [RPC arguments](/node-operators/kona-node/configuration#rpc-arguments) before binding another address.

You can interact with the RPC using any JSON-RPC client, such as `curl`, `httpie`, or a custom client in your preferred programming language.
