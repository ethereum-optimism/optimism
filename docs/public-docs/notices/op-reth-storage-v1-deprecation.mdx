op-reth storage layout v1 is deprecated in favor of storage v2.
New datadirs use storage v2 by default. Upgrading the op-reth binary does not migrate an existing v1 database.

<Warning>
  **Support for storage v1 ends on January 26, 2027.**
  Operators with an existing storage v1 datadir must move to storage v2 before that date, either by restoring a storage v2 snapshot or by running `op-reth db migrate-v2`.
</Warning>

## What this means

*   **Announcement date: October 26, 2026.** **End of life (EOL): January 26, 2027**, three months after the announcement.
*   **Support for storage v1 ends at EOL.**
*   **Affected:** operators running op-reth with an existing storage v1 datadir, including datadirs restored from a v1 snapshot.
*   **Not affected:** new datadirs, which use storage v2 by default, and datadirs already on storage v2.
*   **Separate from historical proofs.** This notice covers the execution database storage layout. It does not change the historical proofs storage version (`--proofs-history.storage-version`).

## Action required

### Node operators

Operators using storage v1 should move to storage v2 before the EOL date, either by restoring a storage v2 snapshot or by migrating in place with `op-reth db migrate-v2`.

**Option 1: use a storage v2 snapshot.** Storage v2 snapshots are available at [snapshots.optimism.io](https://snapshots.optimism.io/) and [datadirs.optimism.io](https://datadirs.optimism.io/). For snapshot usage, see [how to use snapshots](/op-mainnet/network-information/snapshots).

**Option 2: migrate in place.** Use this when a snapshot is not an option. Run the steps below with the node stopped.

<Steps>
  <Step title="Identify your storage version">
    Stop the node and inspect its database settings, using the same datadir and chain configuration as your node:

    ```bash
    op-reth db --datadir <datadir> --chain <chain-or-genesis-path> settings get
    ```

    `storage_v2: true` means the database already uses v2.
    `storage_v2: false`, or `No storage settings found`, indicates v1.
  </Step>

  <Step title="Prepare backups and capacity">
    Take a restorable snapshot of the entire datadir before starting.
    Keep free disk space of approximately 1.4 to 2 times the current datadir size.
    Keep the node stopped throughout the procedure.
  </Step>

  <Step title="Migrate the database">
    ```bash
    op-reth db --datadir <datadir> --chain <chain-or-genesis-path> migrate-v2
    ```

    <Warning>
      The migration cannot be resumed if interrupted. Restore the backup before starting again.
    </Warning>
  </Step>

  <Step title="Verify completion">
    Inspect the database settings again, and the stage checkpoints with `op-reth db --datadir <datadir> --chain <chain-or-genesis-path> stage-checkpoints get`.
    Restart the node and confirm it resumes following the chain.
  </Step>
</Steps>
