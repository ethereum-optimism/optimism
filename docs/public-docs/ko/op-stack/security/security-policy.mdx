## Optimism 버그 바운티 프로그램

Optimism 버그 바운티 프로그램은 OP Mainnet 코드베이스에서 발견된 치명적인 취약점에 대해 최대 [$2,000,042](https://immunefi.com/bounty/optimism/)를 지급합니다.
아래에서 이용 가능한 여러 버그 바운티 프로그램에 대한 정보와, 기존 바운티의 대상이 아닌 버그를 보고하는 방법을 확인할 수 있습니다.

### 메인 바운티 페이지

Optimism은 매우 상세한 [Immunefi 버그 바운티 페이지](https://immunefi.com/bounty/optimism/)를 운영하고 있습니다. 이 목록에서 대상 범위에 포함된 구성 요소, 보고 및 지급 절차에 관한 모든 정보를 확인할 수 있습니다.

### 범위 외 버그

OP Stack 스마트 컨트랙트, 인프라 등에서 중대한 버그나 취약점을 발견했다고 생각되면, 해당 구성 요소가 기존 버그 바운티의 대상이 아니더라도 [Immunefi 프로그램](https://immunefi.com/bounty/optimism/)을 통해 보고해 주십시오. 보고된 모든 문제의 영향은 검토되며, 이 프로그램은 과거에도 명시된 범위에 포함되지 않은 버그에 대해 보안 연구자에게 보상을 지급한 바 있습니다.

## 기타 취약점 보고

OP Stack 내의 웹사이트, 이메일 서버 또는 기타 비핵심 인프라의 취약점은 [Immunefi의 Optimism 버그 바운티 프로그램](https://immunefi.com/bug-bounty/optimism/information/)을 통해 보고하고, 취약점을 확인하고 재현하기 위한 상세한 지침을 포함해 주십시오.

### 취약점 공개

각 OP Stack 구성 요소의 유지 관리자는 취약점 공개 절차를 자체적으로 정할 수 있습니다. 다만, 아래에서는 권장되는 공개 절차를 설명합니다.

OP Stack 구성 요소 유지 관리자가 치명적인 보안 취약점을 알게 된 경우, 유지 관리자는 취약점의 존재나 성격을 즉시 공개하지 않고 조용히 수정할 권리를 가집니다.

이러한 경우 다음과 같은 공개 절차를 따릅니다.

1.  취약점을 조용히 수정하고 해당 수정 사항을 릴리스 X에 포함합니다.
2.  4~8주 후, 릴리스 X에 보안 수정 사항이 포함되었음을 공개합니다.
3.  추가로 4~8주 후, 보고자에 대한 크레딧(보고자의 명시적 허가가 있는 경우)과 함께 취약점의 세부 정보를 게시합니다.

### 유지 관리자의 권리

이 정책과 함께, 유지 관리자는 다음과 같은 권리도 가집니다.

*   이 정책을 따르지 않고 더 짧은 일정으로 세부 정보를 게시할 권리.
*   공개 발표 전에 일부 다운스트림 사용자에게 직접 통지할 권리.

이 정책은 [Geth](https://geth.ethereum.org/) 팀의 [사일런트 패치 정책](https://geth.ethereum.org/docs/developers/geth-developer/disclosures#why-silent-patches)을 기반으로 합니다.
