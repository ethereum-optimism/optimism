이 문서의 일부 페이지는 **큐레이션 산출물(curated artifact)**입니다. 이러한 페이지는 하나의
컴포넌트를 문서화하지 않고, 여러 대상 중에서 선택하거나, 순서를 정하거나, 추천합니다. 솔루션 가이드는
링크와 의사결정의 연쇄이고, 라우터 페이지는 선별된 진입점의 모음이며,
선택 페이지는 계속 발전하는 옵션들을 비교합니다. 큐레이션 콘텐츠는
가장 가치 있는 유형의 페이지이면서 가장 빨리 낡는 페이지이기도 합니다. 오래되어도
아무것도 깨지지 않기 때문입니다. 이 페이지는 큐레이션 콘텐츠를 최신으로 유지하기 위한
상시 정책입니다.

## 큐레이션 산출물에 해당하는 것

문서화보다 선택이나 순서 정하기가 주된 역할인 모든 페이지가 해당합니다.

*   **솔루션 가이드**(`content-type: solution-guide`): 각각 링크의 연쇄와
    의사결정 표로 구성됩니다.
*   **라우터 및 랜딩 페이지**(`content-type: router-landing`): 무엇을 노출할지
    선택하는 섹션 인덱스를 포함합니다.
*   **커리큘럼 허브 및 학습 트랙 인덱스**(`content-type:
    curriculum-hub`): 기존 페이지들을 하나의 경로로 순서를 정합니다.
*   **선택 및 비교 페이지**: 대안에 관한 날짜가 있는 사실을 제시하는 모든 페이지
    (클라이언트 선택, 도구 매트릭스).
*   **프롬프트 라이브러리 및 AI 온보딩 페이지**: 특정 제품 인터페이스를 참조하는
    큐레이션된 프롬프트와 통합 지침.

일반적인 튜토리얼, how-to 가이드, 레퍼런스 페이지, 설명 문서는 큐레이션
산출물이 아닙니다. 이러한 페이지는 해당 컴포넌트의 일반 리뷰 흐름에 따라
관리됩니다.

## `last-reviewed:` 계약

모든 큐레이션 산출물은 프런트매터에 리뷰 스탬프를 포함합니다.

```yaml
last-reviewed: YYYY-MM-DD
```

이 스탬프는 다음을 의미합니다. 해당 날짜에 리뷰어가 페이지의 링크가 정상적으로 연결되고,
핵심 주장이 여전히 소스와 일치하며, 추천 내용이 여전히 우리가 할 추천임을
확인했다는 것입니다. 새 페이지의 경우 병합 시 설정되며, 페이지를 실제로 재검증한
리뷰에 의해서만 갱신됩니다. 관련 없는 편집이 지나가면서 갱신해서는 안 됩니다.

프런트매터는 오래된 정도를 기계적으로 확인할 수 있도록 의도적으로 grep하기 쉽게
되어 있습니다.

```bash
# from docs/public-docs/
grep -rn "last-reviewed:" --include="*.mdx" .
```

## 산출물 유형별 점검 주기

| 산출물 유형                                             | 점검 주기 | 근거                                                                                     |
| ------------------------------------------------------------ | ---------------- | ------------------------------------------------------------------------------------------------ |
| 솔루션 가이드, 선택 및 비교 페이지            | 90일          | 의사결정 로직과 버전에 민감한 사실을 담고 있어, 오래된 추천은 독자를 직접 오도합니다. |
| 프롬프트 라이브러리 및 AI 온보딩 페이지                   | 90일          | 예고 없이 바뀌는 구체적인 제품 인터페이스(URL, 서버 엔드포인트)를 명시합니다.         |
| 라우터/랜딩 페이지, 커리큘럼 허브, 학습 트랙 인덱스 | 180일      | 주로 링크의 순서를 정하며, 링크된 페이지가 각자의 정확성을 책임집니다.                    |

주기를 넘긴 페이지가 자동으로 틀린 것은 아니지만 검증되지 않은 상태이며,
검증되지 않은 큐레이션은 결함으로 취급됩니다. 이러한 페이지는 다음 점검에서
가장 먼저 처리됩니다.

## 점검에서 하는 일

각 점검 단계에서는 유형별 주기 대비 `last-reviewed:`가 가장 오래된
큐레이션 산출물을 골라 재검증합니다.

1.  **연쇄 무결성**: [링크 정책](/ko/op-stack/contribute/link-policy)에 따라
    외부 사이트로 나가는 링크를 포함하여 페이지의 모든 링크가 정상적으로 연결되는지 확인합니다.
    솔루션 가이드의 경우 가이드 페이지만이 아니라 가이드가 순서를 정한 연쇄 전체가
    대상입니다. 죽은 링크 하나가 잘 닦인 경로를 끊어 놓기 때문입니다.
2.  **핵심 주장**: 기본값, 임계값, 버전 번호, "기준 시점(as of)" 표시를
    소스와 대조하여 재확인합니다. 모든 "기준 시점" 날짜는 재확인(및 날짜 갱신)하거나
    해당 주장을 수정합니다.
3.  **스탬프**: 같은 변경에서 `last-reviewed:`를 점검 날짜로 갱신하여
    스탬프와 검증이 서로 어긋나지 않게 합니다.

점검은 예약된, 리뷰 게이트가 있는 문서 자동화로 실행되며, 결과는
일반적인 리뷰 가능한 pull request로 올라옵니다. 모든 병합은 여전히 사람이 책임집니다.

## 목록 제외 규칙

큐레이션 페이지는 무언가를 추천합니다. 더 이상 지지할 수 없는 추천은
단서를 달아 남겨 두지 않고 제거합니다.

*   점검 중 큐레이션 항목(외부 링크, 나열된 도구,
    추천 옵션)이 죽었거나, 지원 중단되었거나, 더 이상 문서가
    추천할 만한 것이 아니라고 판단되면, 해당 항목은 경고를 달아 그대로 두지 않고
    **그 점검의 변경에서 제거하거나 교체합니다**.
*   큐레이션 페이지 전체를 더 이상 검증할 수 없는 경우(주제가
    지원 중단되었거나, 해당 여정이 더 이상 존재하지 않는 경우), 페이지를 내비게이션에서 제거하고
    [리디렉션 지침](https://github.com/ethereum-optimism/optimism/blob/develop/docs/public-docs/REDIRECTS_GUIDE.md)에 따라
    리디렉션하며, 제거 사실을 pull request에 기록합니다.

목록에 올리는 것은 유지 관리에 대한 약속입니다. 일정대로 아무도 재검증하지 않는
큐레이션 항목은 자리를 잃습니다. 이는
[콘텐츠 가이드](/ko/op-stack/contribute/content-guide)가 정식 위치에 대해 맺는 것과
같은 약속을 큐레이션에 적용한 것입니다.

## 새 큐레이션 페이지 추가

새 큐레이션 산출물은 병합 시점에 점검 순환에 들어갑니다.

1.  리뷰 주기 내의 날짜(일반적으로 병합 날짜)로 설정된 `last-reviewed:`와
    [콘텐츠 유형 계약](/ko/op-stack/contribute/choose-a-content-type)이
    요구하는 `content-type:`을 포함합니다.
2.  pull request에 산출물 유형을 명시하여, 리뷰어가 어떤 주기를
    적용받기로 했는지 알 수 있게 합니다.
3.  예외는 없습니다. 해당 유형의 점검 주기를 지킬 수 없는 큐레이션 페이지는
    큐레이션 페이지로 배포해서는 안 됩니다.
