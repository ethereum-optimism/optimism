이 페이지는
[Learn the OP Stack](/ko/op-stack/learn/index) 트랙의 강의 계획서(syllabus)입니다. 유지 관리자를 위한
기록으로, 트랙이 무엇을 다루는지, 각 단계가 왜 그 위치에 있는지, 누가
커리큘럼을 책임지는지, 트랙이 어떻게 변경되는지를 담고 있습니다. 독자를 위한 정문은
[트랙 인덱스](/ko/op-stack/learn/index)입니다. 이 페이지는 트랙이 표류하지 않고
책임자와 변경 이력을 갖도록 하기 위해 존재하며, 자체 변경 이력을 갖춘 공개 강의 계획서라는
MDN 커리큘럼 패턴을 따릅니다.

## 범위 계약

이 트랙은 독자를 **입문자에서 익숙한 수준까지** 이끕니다. 트랙을 마친 사람은
테스트 체인을 배포하고, 트랜잭션이 제출부터 Ethereum에서의 최종성(finality)까지
이동하는 과정을 따라가 보고, 레이어 간에 양방향으로 자산을 옮기고, node를 실행해 보았으며,
더 깊은 자료가 어디에 있는지 압니다. 철저한 세부 사항은 설계상
범위 밖입니다. 깊이 있는 내용은 레퍼런스 섹션과
[OP Stack 스펙](https://specs.optimism.io/)에 있으며, 트랙은
그곳으로 나가는 출구를 제공합니다.

이 문장이 곧 거버넌스 모델입니다. 진행이 아니라 깊이를 더하는 단계 제안은
페이지가 아무리 좋아도 범위 테스트를 통과하지 못합니다. 대신 인덱스의
"After the track" 출구를 통해 안내합니다.

## 강의 계획서

총 14개 단계로, 세 개의 개념 블록 사이사이에 세 개의 실습 프로젝트가 배치되어
각 개념 블록을 직접 사용하며 다지게 됩니다. 단계는 기존
페이지이며, 트랙은 [학습 단위 계약](/ko/op-stack/contribute/learning-unit)에 따라
단계마다 프레이밍 노트만 추가합니다.

| 단계 | 페이지 | 종류 | 이 위치에서 더하는 것 |
| ---- | ---- | ---- | ----------------------------- |
| 1 | [OP Stack](/ko/op-stack/introduction/op-stack) | 개념 | 멘탈 모델: 스택이 무엇인지, 무엇을 구동하는지, 무엇을 만들 수 있는지. |
| 2 | [OP Stack 아키텍처](/ko/op-stack/architecture) | 개념 | 시스템 관점: 컴포넌트, 각각을 누가 운영하는지, 트랜잭션이 컴포넌트를 거쳐 어떻게 이동하는지, 신뢰가 어디에 있는지. 개별 부분을 살펴보기 전에 학습자에게 전체 시스템 모델을 제공합니다. |
| 3 | [설계 철학 및 원칙](/ko/op-stack/protocol/design-principles) | 개념 | 스택이 지금의 모습을 갖게 된 이유와, 나머지 문서가 전제하는 어휘. |
| 4 | [Ethereum과의 차이점](/ko/op-stack/protocol/differences) | 개념 | 실습에 앞서 "EVM 동등성"의 의미를 다지고, Ethereum 경험을 잘못 적용하는 것을 방지합니다. |
| 5 | [OP Stack 컴포넌트](/ko/op-stack/protocol/components) | 개념 | 학습자가 프로젝트 1에서 배포할 레이어와 모듈의 이름을 알려 줍니다. |
| 6 | [나만의 L2 rollup testnet 만들기](/ko/chain-operators/tutorials/create-l2-rollup) | 프로젝트 | 1부를 다집니다: op-deployer로 rollup testnet을 배포하고 앞서 소개한 각 컴포넌트를 시작합니다. |
| 7 | [트랜잭션 흐름](/ko/op-stack/transactions/transaction-flow) | 개념 | 학습자가 방금 실행한 컴포넌트를 하나의 트랜잭션 생애의 단계로 다시 해석합니다. |
| 8 | [OP Mainnet의 트랜잭션 수수료](/ko/op-stack/transactions/fees) | 개념 | 트랜잭션의 수수료 구성 요소로, 트랜잭션 흐름 단계의 경제적 귀결입니다. |
| 9 | [입금 흐름](/ko/op-stack/bridging/deposit-flow) | 개념 | 레이어 간 이동의 첫 번째 방향: L1에서 트리거되는 L2 트랜잭션. |
| 10 | [출금 흐름](/ko/op-stack/bridging/withdrawal-flow) | 개념 | 두 번째 방향: 시작, 증명, 최종 확정 순서와 그것이 존재하는 이유. |
| 11 | [L1에서 트랜잭션 제출하기](/ko/app-developers/tutorials/bridging/cross-dom-bridge-eth) | 프로젝트 | 2부를 다집니다: Viem을 사용해 코드로 입금과 출금을 직접 수행합니다. |
| 12 | [결함 증명 설명](/ko/op-stack/fault-proofs/explainer) | 개념 | 학습자가 방금 증명한 출금을 신뢰할 수 있는 이유: 무허가(permissionless) 제안과 이의 제기. |
| 13 | [OP Stack 상호운용성 설명](/ko/op-stack/interop/explainer) | 개념 | 스택이 나아가는 방향: 하나의 블록체인처럼 느껴지는 체인 네트워크. |
| 14 | [Docker로 node 실행하기](/ko/node-operators/tutorials/node-from-docker) | 캡스톤 프로젝트 | 실제 인프라를 운영하며 트랙을 마무리합니다: 공식 이미지로 라이브 네트워크에서 node를 실행합니다. |

## 설계 규칙

1.  **단계는 기존 페이지이며, 결코 포크하지 않습니다.** 문구 수정이 필요한 단계는
    트랙 전용 사본을 만들지 않고 해당 페이지에 이슈를 등록합니다. 트랙이
    소유하는 산출물은 [인덱스](/ko/op-stack/learn/index), 이 강의 계획서,
    그리고 프레이밍 노트뿐입니다.
2.  **프레이밍 노트는
    [학습 단위 계약](/ko/op-stack/contribute/learning-unit)을 따릅니다**(프레이밍
    헤더 형태): 트랙 이름, 단계 위치, 도착 시점의 맥락 한 문장,
    이 단계가 더하는 것 한 문장, 다음 단계 링크.
    페이지의 다른 부분은 바뀌지 않습니다.
3.  **상한: 15단계.** 이를 넘으면 트랙은 더 이상 선형이 아니며
    두 번째 내비게이션이 되어 버립니다. 대신 자료를 "After the
    track" 출구로 분리합니다.
4.  **프로젝트는 끝에 몰아 두지 않고 간격을 둡니다.** 각 개념 블록은 그 개념을 사용하는
    실습 단계로 끝납니다(Rust Book의 리듬). 두 프로젝트가 인접하게 되거나
    개념 블록이 실습으로 다져지지 않게 되는 순서 변경은 책임자의 명시적 승인이
    필요합니다.
5.  **순서 변경 절차:** 인덱스를 업데이트하고, 영향을 받는 모든
    프레이밍 노트의 번호("stop N of M")를 다시 매기고, 모든 다음 단계 링크를 확인한 뒤,
    아래에 변경 이력 항목을 추가합니다. 위치 정보는 프레이밍 노트와
    인덱스에만 있고 페이지 제목에는 절대 넣지 않으므로, 제목을 바꾸지 않고도 단계를 옮길 수 있습니다.
6.  **모든 변경에는 변경 이력 항목이 함께 들어갑니다.** 변경 이력은
    커리큘럼의 기억입니다. 각 항목은 무엇이 왜 바뀌었는지를 각각 한 줄로
    기술합니다.

## 변경 이력

| 날짜 | 변경 |
| ---- | ------ |
| 2026-07-21 | 최초 강의 계획서: 13단계(세 개의 개념 블록, 세 개의 프로젝트: 체인 배포, 양방향 브리지, node 실행). 커리큘럼 책임자: Matthew Cruz ([@sbvegan](https://github.com/sbvegan)). |
| 2026-09-11 | [OP Stack 아키텍처](/ko/op-stack/architecture)를 2단계로 삽입하여 13단계가 14단계가 됨. 트랙에 전체 시스템을 다루는 단계가 없었음: 1단계는 스택이 무엇인지, 4단계는 레이어의 이름을 다뤘지만, 그 사이에 각 부분이 어떻게 상호작용하는지나 누가 각각을 운영하는지를 보여 주는 단계가 없었음. 프로젝트는 6, 11, 14단계로 간격을 유지하며(설계 규칙 4), 14단계는 15단계 상한 이내임(설계 규칙 3). 설계 규칙 5에 따라 순서를 변경했으며, 책임 섹션에 따라 커리큘럼 책임자의 리뷰가 필요함. |
