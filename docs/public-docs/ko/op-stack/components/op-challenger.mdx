op-challenger는 OP Stack의 분쟁 게임(dispute game) 이의 제기 서비스로, L1의 결함 분쟁 게임(fault
dispute game)을 모니터링하고, 유효한 output 제안을 방어하며, 유효하지 않은 제안에 이의를
제기합니다.

## 개요

op-challenger는 `DisputeGameFactory`를 통해 생성된 게임을 감시합니다(결함 증명 체인에서는 모든
output 제안이 분쟁 게임입니다). 신뢰할 수 있고 동기화된 rollup node와 각 주장을 비교하여, 동의하는
제안은 방어하고, 동의하지 않는 제안에는 반박 주장(counterclaim)을 게시하며, 게임 시계가 만료되면
주장과 게임을 해결(resolve)하고, 자신에게 지급되는 본드(bond)를 수령합니다. 분쟁이 이분 탐색을 통해
단일 VM 명령어까지 좁혀지면, op-challenger는 결함 증명 VM인 [cannon](/ko/op-stack/components/cannon)을
실행하여(kona-host가 preimage 데이터를 제공하는 상태에서 kona-client를 실행) 해당 명령어를 온체인에서
증명합니다. 이 동작에 대한 자세한 설명은
[OP-Challenger 설명](/ko/op-stack/fault-proofs/challenger)을 참조하십시오.

op-challenger가 존재하는 이유는 게임 시계가 만료되기 전에 누군가가 유효하지 않은 주장에 실제로
대응해야만 결함 증명이 출금을 보호할 수 있기 때문입니다. op-challenger는 분쟁 프로토콜의
*정직한 행위자(honest actor)*를 구현한 것입니다. 게임이 올바른 상태로 해결되도록 보장하여 체인을
방어하며, `OptimismPortal`은 출금 시 궁극적으로 이 결과를 신뢰합니다.

**운영 주체:** 체인 운영자는 자신의 체인을 방어하기 위해 최소 하나의 challenger를 운영하며, 무허가
결함 증명 체인에서는 누구나 운영할 수 있습니다. challenger에는 주장을 검증하기 위한 동기화되고
신뢰할 수 있는 rollup node와, 본드를 게시할 자금이 있는 계정이 필요합니다.

## 사용 방법 가이드

*   [체인에 맞게 challenger를 구성하는 방법](/ko/chain-operators/guides/configuration/op-challenger-config-guide):

*   [절대 prestate 및 preimage 파일 생성](/ko/chain-operators/tutorials/absolute-prestate):

    마이그레이션의 일부로 op-challenger를 업그레이드하고 테스트합니다.
