op-reth는 Rust로 작성되고 [reth](https://github.com/paradigmxyz/reth)를 기반으로 구축된 OP Stack의
실행 계층 클라이언트입니다. rollup node가 파생한 L2 블록을 실행하고 그 결과 체인 상태를 유지합니다.

## 개요

op-reth는 OP Stack 체인에 EVM 실행 환경을 제공합니다. rollup node([op-node](/ko/op-stack/components/op-node)
또는 [kona-node](/ko/op-stack/components/kona-node))가 L1 데이터로부터 정식 체인을 파생하고 Engine API를
통해 op-reth를 구동하면, op-reth는 페이로드를 실행하고, 체인 상태를 유지하며, JSON-RPC를 제공합니다.
op-reth는 입금(디파짓) 트랜잭션 유형과 L2 수수료 처리 등 OP Stack 프로토콜 변경 사항으로 업스트림
reth를 확장하며, [Superchain Registry](https://github.com/ethereum-optimism/superchain-registry)의 체인
구성을 바이너리에 내장하므로 레지스트리에 등록된 체인은 `--chain` 플래그로 이름만 지정하면 동작합니다.

op-reth가 존재하는 이유는 머지(merge) 이후의 Ethereum처럼 모든 OP Stack node가 합의 절반과 실행
절반으로 나뉘며, 실행 클라이언트가 EVM을 실행하는 절반이기 때문입니다. op-reth는 주로 지원되는 실행
클라이언트이자 Optimism이 유지 관리하는 구현입니다. 하드포크 지원을 포함한 새로운 OP Stack 기능
개발은 op-reth에서 이루어집니다. 선택 근거는
[node 스택 선택](/ko/use-cases/choose-your-node-stack)을 참조하십시오.

**운영 주체:** 모든 노드 운영자가 rollup node와 일대일로 짝지어 운영합니다. 체인 운영자는 sequencer의
실행 절반으로 op-reth를 운영하며, 여기서 op-reth는 sequencing rollup node가 요청하는 새 블록을
생성합니다.

## 사용 방법 가이드

*   [실행 클라이언트 구성](/ko/node-operators/guides/configuration/execution-clients):
    op-reth를 설치하고, 합의 클라이언트에 연결하며, OP Stack 전용 rollup 플래그를 설정합니다.
*   [OP Mainnet 동기화](/ko/node-operators/op-reth/run/faq/sync-op-mainnet): Bedrock 상태를 가져오고
    OP Mainnet을 처음부터 동기화합니다.
*   [아카이브 node 구축](/ko/node-operators/guides/management/archive-node):
    아카이브 node와 풀 node의 차이, 그리고 op-reth를 안전하게 pruning하는 방법을 다룹니다.
*   [과거 증명(historical proofs)과 함께 op-reth 실행](/ko/node-operators/tutorials/reth-historical-proofs):
    결함 증명 인프라에 필요한 과거 증명 저장소를 프로비저닝합니다.
