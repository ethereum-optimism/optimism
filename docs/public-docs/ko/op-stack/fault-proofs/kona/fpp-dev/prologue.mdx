프로그램의 프롤로그 단계는 일반적으로 [Host-Client 통신](/ko/op-stack/fault-proofs/kona/fpp-dev/env#host-and-client-communication) 구현을 통해
외부 소스에서 가져온 입력으로 프로그램을 부트스트래핑하는 역할을 합니다.

경험적으로, 프롤로그 구현은 최소한으로 유지해야 하며, [실행 단계](/ko/op-stack/fault-proofs/kona/fpp-dev/execution)의 입력을
준비하는 것 이상의 작업은 하지 않는 것이 좋습니다.

## 예시

예를 들어, `kona-client` 프로그램의 프롤로그 단계는 다음과 같은 여러 단계를 거칩니다.

1. [Preimage Oracle ABI][preimage-specs]를 통해 다음 내용을 포함하는 부트 정보를 가져옵니다.
   - 주장된 블록 높이에서 L2 safe chain을 재현하는 데 필요한 모든 데이터를 포함하는 L1 head hash
   - 합의된 safe [L2 output root][l2-output-root]
   - [L2 output root][l2-output-root] claim
   - [L2 output root][l2-output-root] claim의 블록 번호
   - L2 chain ID
1. 전달된 L2 chain ID에 해당하는 `RollupConfig`와 `L1ChainConfig`를 가져옵니다.
1. 이 값들을 검증합니다.
1. 부트 정보를 실행 단계로 전달합니다.
