결함 증명(fault proof)은 OP Stack 체인이 신뢰할 수 있는 제3자 없이
출금을 보호하는 방법입니다. 누구나 Ethereum에 체인 상태를 제안할 수 있고,
누구나 잘못되었다고 판단되는 제안에 이의를 제기할 수 있습니다. 분쟁은
bisection 게임을 통해 단일 실행 명령어로 좁혀지며, 그 하나의 명령어는
Ethereum의 onchain 가상 머신 내에서 증명됩니다.

이 페이지는 전체 주제에 대한 권장 읽기 순서를 안내합니다. 먼저
설명 문서로 개념 모델을 익히고, 컴포넌트 페이지를 차례로 읽으며
각 요소가 어떻게 맞물리는지 확인한 다음, 체인을 운영하거나 challenger를
실행하려는 경우 실습 가이드를 활용하십시오. bond 경제학과 규범적 명세는
깊이 있는 내용이 필요한 독자를 위해 전체 흐름을 마무리합니다. 각 단계는
모두 기존 페이지이며, 이 페이지가 그 내용을 대체하지는 않습니다.

## 규범적 명세

결함 증명 동작의 최종적인 정의는 OP Stack 명세에 있습니다.

*   [Fault proof](https://specs.optimism.io/fault-proof/index.html?utm_source=op-docs&utm_medium=docs):
    결함 증명 프로그램과 이 프로그램이 데이터를 읽어 오는 pre-image oracle입니다.
*   [Fault dispute game](https://specs.optimism.io/fault-proof/stage-one/fault-dispute-game.html?utm_source=op-docs&utm_medium=docs):
    bisection, 시계(clock), 해결을 포함한 게임 자체입니다.
*   [Honest challenger](https://specs.optimism.io/fault-proof/stage-one/honest-challenger-fdg.html?utm_source=op-docs&utm_medium=docs):
    정직한 challenger가 구현해야 하는 동작이며, `op-challenger`가 이를
    따릅니다.
*   [Bond incentives](https://specs.optimism.io/fault-proof/stage-one/bond-incentives.html?utm_source=op-docs&utm_medium=docs):
    위 FAQ 답변의 기반이 되는 규범적 bond 경제학입니다.
*   [Multithreaded Cannon fault proof VM](https://specs.optimism.io/fault-proof/cannon-fault-proof-vm.html?utm_source=op-docs&utm_medium=docs):
    Cannon이 구현하는 FPVM의 명세입니다.
