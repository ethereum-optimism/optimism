**op-node**는 [rollup-node 사양](https://specs.optimism.io/protocol/rollup-node.html)을 구현하며, OP Stack 체인의 합의 계층(consensus layer, CL) 클라이언트로 동작합니다. op-reth와 같은 실행 계층 클라이언트와 함께 정규(canonical) L2 체인을 구축하고, 전달하고, 검증합니다.

* **Go API 이동** ([#21650](https://github.com/ethereum-optimism/optimism/pull/21650)): `LoadOPStackRollupConfig`가 `op-node/rollup`에서 `op-node/superchain`으로 이동했습니다. 이를 사용하는 다운스트림 Go 코드는 import 경로를 업데이트해야 합니다. 운영자에게 영향을 주는 변경은 없습니다.

이 릴리스는 선택 사항이지만, 안정성 수정이 포함되어 있으므로 업데이트를 권장합니다.

⚠️  **Req/Res CL P2P 동기화 — 기본적으로 비활성화됨**

이전에 안내한 바와 같이, op-node의 Req/Res CL P2P 동기화 프로토콜은 지원 중단(deprecation) 절차를 밟고 있습니다.

이제 `--syncmode.req-resp` 플래그의 기본값은 `false`이며, 이는 Req/Res CL P2P 동기화가 **기본적으로 비활성화**됨을 의미합니다.

Req/Resp 동기화에 의존하는 운영자는 이 플래그를 명시적으로 `true`로 설정하고, 정상적인 EL p2p 네트워크를 갖추도록 인프라도 업데이트해야 합니다.

<Update label="2025년 12월 4일" description="v1.16.3" tags={["Stable"]}>

> [!IMPORTANT]
> **모든 OP Stack 체인에 반드시 적용해야 하는 릴리스입니다**

이 릴리스에는 동일한 내용을 가진(단, 블록 내 인덱스가 다른) 여러 blob이 요청되는 경우를 처리하도록 blob 가져오기 로직을 수정한 중요한 수정 사항이 포함되어 있습니다. 이 수정이 없으면 batcher가 동일한 내용의 blob을 여러 개 제출할 때 발생하는 오류로 인해 *safe head 정체*가 발생할 수 있습니다(#18492).

또한 겹치는 span batch의 첫 번째 단일 batch가 현재 safe head 이후에 있으면서 오래된 origin을 가지는 경우의 derivation 파이프라인 엣지 케이스도 수정되었습니다. 이는 자동 도출된 체인(시퀀싱 윈도우 경과로 인한)과 겹치는 대형 span batch가 게시될 때 발생할 수 있습니다. 이러한 span batch는 폐기되어야 하지만, 대신 derivation 파이프라인이 정체되었습니다. 이 문제는 최근 한 OP Stack testnet에서 발생했으며, 이전에는 관찰된 적이 없었습니다(#18283).

sequencer의 L1 origin 선택이 L1 reorg를 올바르게 처리하도록 수정되었습니다(#18233).
