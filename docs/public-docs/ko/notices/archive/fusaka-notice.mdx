# L1 Fusaka 업그레이드 준비

이 페이지는 OP Stack 체인을 위한 Fusaka 대비 업그레이드에 관한 외부 공개 정보를 제공합니다. 체인 운영자와 파트너를 위해 범위, 일정, 필수 조치 및 관련 자료를 요약합니다. 이 업그레이드는 Fusaka를 활성화할 예정인 L1 체인(Ethereum Mainnet 및 Sepolia 포함)에서 도출되는 모든 OP Stack 체인에 필요합니다.

이는 L2에서의 Fusaka 도입이 아닙니다. Fusaka 포크를 활성화하는 L1과 OP Stack 프로토콜이 호환되도록 하기 위한 대비 업그레이드입니다. L2 도입은 향후 업그레이드에서 이루어질 예정입니다.

<Info>
  아래의 모든 작업은 L1에서 Fusaka가 활성화되기 전에 수행해야 합니다.
</Info>

## Fusaka에 포함된 내용

Fusaka에는 여러 호환성을 깨는 변경 사항(breaking changes)이 포함되어 있습니다. 자세한 내용은 [EIP-7607: Hardfork Meta - Fusaka](https://eips.ethereum.org/EIPS/eip-7607)를 참조하십시오.

**중요 일정:**

* Ethereum Sepolia Fusaka 하드포크: 2025년 10월 14일(화) 07:36:00 UTC (`1760427360`)
* Sepolia BPO 1: 2025년 10월 21일(화) 03:26:24 UTC (`1761017184`)
* Sepolia BPO 2: 2025년 10월 27일(월) 23:16:48 UTC (`1761607008`)
* Ethereum Mainnet Fusaka 하드포크: 2025년 12월 3일(수) 21:49:11 UTC (`1764798551`)
* Ethereum Mainnet BPO 1: 2025년 12월 9일(화) 14:21:11 UTC (`1765290071`)
* Ethereum Mainnet BPO 2: 2026년 1월 7일(수) 01:01:11 UTC (`1767747671`)

### L1 beacon node 엔드포인트가 모든 blob을 제공할 수 있는지 확인

**외부 L1 Ethereum Beacon을 사용하는 운영자:**

Ethereum Fusaka 하드포크 이전에 외부 L1 Beacon Chain RPC 제공업체가 모든 서브넷을 구독하도록 node를 구성했는지 확인하십시오.
외부 L1 Beacon Chain RPC 제공업체가 모든 서브넷을 구독하지 않는 경우, 해당 기한 이전에 모든 서브넷을 구독하는 제공업체로 이전하십시오.

**자체 L1 Ethereum Beacon Chain Node를 운영하는 운영자:**

**자체 L1 node를 운영하는 경우 L1 실행 node와 beacon node가 모두 업그레이드**되고 Fusaka 포크에 맞게 구성되었는지 확인하십시오.

오래된 L1 node는 포크 이후 도출(derivation) 실패, blob 사용 불가 또는 체인 분기를 일으킵니다.

해당 Fusaka 하드포크 일자 이전에 Beacon Node를 새 플래그(아래 참조)로 구성하십시오.

L1 Beacon Chain Node 플래그:

*   Lighthouse:	`--supernode`
*   Teku:	`--p2p-subscribe-all-custody-subnets-enabled`
*   Grandine:	`--subscribe-all-data-column-subnets`
*   Lodestar:	`--supernode`
*   Nimbus:	`--debug-peerdas-supernode`

### permissionless 결함 증명이 활성화된 체인 대상

<Note>
  Superchain은 Fusaka 지원과 Mainnet [Jovian 하드포크](/ko/notices/archive/upgrade-17) 지원을 하나의 absolute prestate로 묶어 제공합니다.
</Note>

<Info>
  Optimism은 OP, Ink, Unichain의 Mainnet 및 Sepolia에서 온체인 prestate 업데이트(Dispute Game 배포 및 구현 세트 포함)를 완료할 예정입니다. 
  다만 오프체인 구성 요소(op-challenger)는 운영자가 직접 새 prestate를 사용하도록 구성해야 합니다.
  위 목록에 포함되지 않은 Permissionless FP 활성화 체인이라면 아래의 모든 단계를 직접 수행해야 합니다.
</Info>

permissionless 결함 증명(fault proof)을 운영하는 체인은 새로운 absolute prestate를 사용하는 새 분쟁 게임(dispute game) 컨트랙트를 배포해야 합니다.

<Steps>
  <Step title="새 absolute prestate 검증">

  absolute prestate는 [op-program/v1.8.0-rc.4](https://github.com/ethereum-optimism/optimism/tree/op-program/v1.8.0-rc.4)로 생성됩니다(`op-program/v1.8.0-rc.4` 기준). 다음 체인에는 새 absolute prestate `0x03caa1871bb9fe7f9b11217c245c16e4ded33367df5b3ccb2c6d0a847a217d1b`를 사용할 수 있습니다.

  *   Mainnet 및 Sepolia: `OP`, `Base`, `Ink`, `Unichain`

  `op-program/v1.8.0-rc.4` 태그에서 모노레포 루트에 다음 명령을 실행하여 이 absolute prestate를 검증할 수 있습니다.

  ```shell
  make reproducible-prestate
  ```

  이 명령은 계산된 prestate를 출력하며, 출력의 마지막 부분은 다음과 같습니다.

  ```shell
  -------------------- Production Prestates --------------------

  Cannon64 Absolute prestate hash: 
  0x03caa1871bb9fe7f9b11217c245c16e4ded33367df5b3ccb2c6d0a847a217d1b

  -------------------- Experimental Prestates --------------------

  Cannon64Next Absolute prestate hash: 
  0x03caa1871bb9fe7f9b11217c245c16e4ded33367df5b3ccb2c6d0a847a217d1b

  CannonInterop Absolute prestate hash: 
  0x03455f7f2179327853a989648c3ac9f2d58be45137bae603271660519b4d5245

  CannonInteropNext Absolute prestate hash: 
  0x03455f7f2179327853a989648c3ac9f2d58be45137bae603271660519b4d5245
  ```

  *   "Cannon64" 해시는 64비트 prestate입니다.

  대상 prestate가 예상대로 계산되었고
  [standard-prestates.toml](https://github.com/ethereum-optimism/superchain-registry/blob/main/validation/standard/standard-prestates.toml)의 해당 항목과 일치하는지 확인하십시오.
  </Step>

  <Step title="새 preimage 파일 업로드">
    이전 단계에서 absolute prestate의 preimage도 함께 생성되었습니다. 이는 op-program을 바이너리 파일로 직렬화한 것입니다. 새 파일은 `optimism/op-program/bin/prestate-mt64.bin.gz`에 있습니다. 파일 이름을 absolute prestate 해시로 변경하여 `PRESTATEHASH.bin.gz` 형식이 되도록 하십시오.

    이 파일을 다른 absolute preimage 파일을 저장하는 위치에 업로드하십시오. 이 위치는 `--cannon-prestates-url`이 가리키는 곳이어야 합니다. `op-challenger`는 게임에 이의를 제기해야 할 때 이 파일을 가져와 사용합니다.
  </Step>

  <Step title="업그레이드 실행">
    `op-challenger`가 새 preimage로 준비되면 업그레이드 트랜잭션을 실행할 수 있습니다. 이는 [레지스트리](https://github.com/ethereum-optimism/superchain-registry/blob/main/validation/standard/standard-versions-mainnet.toml)에 나열된 주소의 OP Contract Manager `upgrade()` 함수에 delegatecall을 수행하여 진행합니다.

    트랜잭션을 실행하기 전에 예상 결과를 시뮬레이션하고 검증하십시오.
  </Step>
</Steps>
