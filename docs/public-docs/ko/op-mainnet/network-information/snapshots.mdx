# 노드 스냅샷 {#node-snapshots}

이 페이지에서는 OP Mainnet, OP Sepolia, 그리고 Optimism이 스냅샷을 게시하는 그 밖의 OP Enterprise Fully Managed 네트워크의 node 스냅샷을 다운로드할 수 있는 위치를 안내합니다.
스냅샷은 미리 동기화된 실행 클라이언트 데이터 디렉터리로, genesis부터 재실행하는 대신 최근 체인 상태에서 node를 시작할 수 있게 해 줍니다.
스냅샷 다운로드, 검증, 압축 해제에 대한 단계별 안내는 [스냅샷에서 노드 복원 가이드](/ko/node-operators/guides/management/restore-from-snapshot)를 따르십시오.

<Info>
  다음과 같은 경우에는 스냅샷이 **필요하지 않습니다**.

  *   OP Sepolia 및 대부분의 다른 OP Stack 체인에서 [실행 레이어 동기화(execution-layer sync)](/ko/node-operators/reference/consensus-layer-sync)로 `op-reth`를 실행하는 경우
  *   스냅샷을 자동으로 처리하는 [Nethermind](https://docs.nethermind.io/get-started/running-node/l2-networks#op-stack)를 사용하는 경우

  스냅샷은 archive node를 부트스트랩하는 가장 빠른 방법이며, OP Mainnet에서는 `op-reth`의 [Bedrock 이전 상태 요구 사항](#op-mainnet-pre-bedrock-data)을 충족하는 가장 간단한 방법입니다.
</Info>

## Optimism 스냅샷 {#optimism-snapshots}

Optimism은 [snapshots.optimism.io](https://snapshots.optimism.io/)에 `op-reth` 스냅샷을 게시합니다.
사이트에서 네트워크와 동기화 유형을 선택하십시오. 사이트에는 각 스냅샷마다 생성에 사용된 `op-reth` 버전, 스냅샷 날짜, 크기, SHA256 체크섬이 표시됩니다.
**Snapshot** 선택기를 사용해 최신 스냅샷 또는 날짜가 지정된 이전 스냅샷을 선택한 다음, 다운로드 명령이나 스냅샷 URL을 복사하십시오.
스냅샷은 `.tar.zst` 아카이브이며, 각 스냅샷에는 일치하는 `.sha256sum` 체크섬 파일이 있습니다.

<Info>
  [aria2](https://aria2.github.io/)를 사용하면 스냅샷 다운로드 속도를 크게 높일 수 있습니다.
</Info>

현재 사이트에서는 아래 네트워크의 스냅샷을 제공합니다. [snapshots.optimism.io](https://snapshots.optimism.io/)의 목록이 기준이며, 목록은 늘어날 수 있습니다.

| 네트워크 | 클라이언트 | 동기화 유형 |
| ------- | ------ | ---------- |
| OP Mainnet | `op-reth` (storage v2) | Full(최근 30일의 상태 및 히스토리로 pruning됨) 및 archive(pruning되지 않은 전체 상태 및 히스토리) |
| OP Sepolia | `op-reth` | Full(최근 30일의 상태 및 히스토리로 pruning됨) 및 archive(pruning되지 않은 전체 상태 및 히스토리) |
| Ink Mainnet | `op-reth` | [snapshots.optimism.io](https://snapshots.optimism.io/) 참조 |
| Ink Sepolia | `op-reth` | [snapshots.optimism.io](https://snapshots.optimism.io/) 참조 |
| Collect Chain Testnet | `op-reth` | [snapshots.optimism.io](https://snapshots.optimism.io/) 참조 |

### OP Mainnet {#op-mainnet}

OP Mainnet 스냅샷은 새 `op-reth` 데이터 디렉터리의 기본 스토리지 레이아웃인 storage v2를 사용합니다. 두 가지 동기화 유형을 사용할 수 있습니다.

*   **Full**: 최근 30일의 상태 및 히스토리로 pruning됩니다. 압축 시 약 1.3 TB입니다.
*   **Archive**: pruning되지 않으며 전체 상태 및 히스토리를 포함합니다. 압축 시 약 1.7 TB입니다. [archive node](/ko/node-operators/guides/management/archive-node)를 실행할 때 사용하십시오.

압축 해제된 데이터 디렉터리는 압축된 다운로드 파일보다 큽니다. 복원하는 동안 두 가지를 모두 저장할 공간이 필요하므로 디스크 공간을 충분히 계획하십시오.

각 스냅샷은 이미 Bedrock 이후까지 동기화된 OP Mainnet `op-reth` node의 데이터 디렉터리입니다. 스냅샷을 복원하면 새 데이터 디렉터리에 필요한 [Bedrock 이전 상태 가져오기](/ko/node-operators/op-reth/run/faq/sync-op-mainnet)를 대신할 수 있습니다.

### OP Sepolia {#op-sepolia}

OP Sepolia `op-reth` 스냅샷은 [snapshots.optimism.io](https://snapshots.optimism.io/)에 동일한 두 가지 동기화 유형으로 게시됩니다.

*   **Full**: 최근 30일의 상태 및 히스토리로 pruning됩니다. 압축 시 약 265 GB입니다.
*   **Archive**: pruning되지 않으며 전체 상태 및 히스토리를 포함합니다. 압축 시 약 262 GB입니다.

OP Mainnet과 마찬가지로 압축 해제된 데이터 디렉터리는 압축된 다운로드 파일보다 큽니다.
OP Sepolia에서는 스냅샷이 필요하지 않습니다. `op-reth`는 빈 데이터 디렉터리에서 실행 레이어 동기화로 부트스트랩할 수 있습니다.

### Storage v1 스냅샷 {#storage-v1-snapshots}

`op-reth` storage v1은 지원 중단(deprecated)되었으며 2027년 1월 26일에 지원이 종료됩니다.
자세한 내용은 [op-reth storage v1 지원 중단 공지](/ko/notices/op-reth-storage-v1-deprecation)를 참조하십시오.
나중에 데이터 디렉터리를 마이그레이션할 필요가 없도록 새 node는 storage v2 스냅샷에서 시작하십시오.

Optimism은 OP Mainnet용 storage v1 스냅샷을 게시하지 않습니다.
OP Sepolia용 storage v1 `op-reth` 스냅샷은 당분간 [Data Directories](https://datadirs.optimism.io/) 웹사이트에 남아 있으며, storage v1 지원이 종료되면 더 이상 게시되지 않습니다.

## OP Mainnet Bedrock 이전 데이터 {#op-mainnet-pre-bedrock-data}

OP Mainnet은 2023년 [Bedrock 업그레이드](https://web.archive.org/web/20230608050602/https://blog.oplabs.co/introducing-optimism-bedrock/)의 일환으로 대규모 [데이터베이스 마이그레이션](https://web.archive.org/web/20240110231645/https://blog.oplabs.co/reproduce-bedrock-migration/)을 거쳤습니다.
OP Mainnet의 `op-reth` node는 Bedrock 상태에서 시작해야 합니다.
[OP Mainnet 스냅샷](#op-mainnet)을 복원하거나, [Sync OP Mainnet](/ko/node-operators/op-reth/run/faq/sync-op-mainnet)을 따라 직접 가져오십시오.

### Legacy Geth 데이터 디렉터리 {#legacy-geth-data-directory}

Bedrock 업그레이드 이전의 블록은 최신 OP Mainnet node에서 실행할 수 없습니다.
Bedrock 이전 블록에 대해 `eth_call`과 같은 상태 기반 쿼리를 실행하려면, Optimism이 관리하는 [Data Directories](https://datadirs.optimism.io/) 웹사이트의 Legacy Geth 데이터 디렉터리를 사용하여 최신 node와 함께 Legacy Geth(`l2geth`) node를 실행하십시오.
[Legacy Geth](/ko/node-operators/guides/configuration/legacy-geth)와 [소스에서 node 실행 튜토리얼의 Legacy Geth 단계](/ko/node-operators/tutorials/run-node-from-source#legacy-geth-pre-bedrock-optional)를 참조하십시오.
이는 Bedrock 이전 상태를 제공해야 하는 OP Mainnet archive node에만 필요합니다.

## Nethermind {#nethermind}

[Nethermind](https://docs.nethermind.io/get-started/running-node/l2-networks#op-stack)는 node를 시작할 때 필요한 스냅샷의 다운로드와 적용을 자동으로 처리합니다. 스냅샷을 수동으로 다운로드할 필요가 없습니다. node는 다음과 같이 동작합니다.

1.  빈 데이터베이스로 시작합니다
2.  필요한 ancient 데이터를 자동으로 다운로드합니다
3.  데이터를 적용하고 동기화를 계속합니다

이 과정은 완전히 자동화되어 있으며 추가 구성이 필요하지 않습니다.
`-c op-mainnet` 플래그와 함께 `Nethermind`를 실행하면 이 구성이 자동으로 사용됩니다.

## 서드파티 스냅샷 {#3rd-party-snapshots}

[Allnodes](https://www.allnodes.com)는 OP Mainnet 및 Testnet의 풀 노드 스냅샷을 제공합니다. [여기](https://www.publicnode.com/snapshots#optimism)에서 확인할 수 있습니다.
**참고:** Allnodes는 서드파티 제공업체이며, Optimism Foundation은 해당 스냅샷을 검증하지 않았습니다.
