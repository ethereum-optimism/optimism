# 노드 스냅샷

이 페이지에는 데이터 디렉터리와 노드 스냅샷의 다운로드 링크가 포함되어 있습니다.
상태 스냅샷(state snapshot)은 미리 동기화된 노드 데이터로, genesis부터 재실행하는 대신 최근 체인 상태에서 OP Stack 실행 클라이언트를 시작할 수 있게 해 줍니다. 스냅샷을 다운로드하고 이를 기반으로 노드를 실행하면 초기 동기화 시간이 크게 단축됩니다.
스냅샷 다운로드, 검증, 압축 해제에 대한 단계별 안내는 [스냅샷에서 노드 복원 가이드](/ko/node-operators/guides/management/restore-from-snapshot)를 따르세요.

<Info>
  다음과 같은 경우에는 데이터 디렉터리와 노드 스냅샷이 **필요하지 않습니다**.

  *   op-geth에서 [snap sync](/ko/node-operators/reference/consensus-layer-sync)를 사용하는 경우
  *   [Nethermind](https://docs.nethermind.io/get-started/running-node/l2-networks#op-stack)를 사용하는 경우(스냅샷을 자동으로 처리함)

  아카이브 노드를 실행하거나 `op-reth` 또는 `op-geth`로 전체 체인을 trace해야 하는 경우에는 여전히 필요합니다.
</Info>


OP Mainnet은 2023년 [Bedrock 업그레이드](https://web.archive.org/web/20230608050602/https://blog.oplabs.co/introducing-optimism-bedrock/)의 일환으로 대규모 [데이터베이스 마이그레이션](https://web.archive.org/web/20240110231645/https://blog.oplabs.co/reproduce-bedrock-migration/)을 거쳤습니다.
`op-reth` 또는 `op-geth`를 사용하는 노드 운영자가 아카이브 노드를 실행하려면 마이그레이션된 OP Mainnet 데이터베이스가 있어야 합니다.
마이그레이션된 OP Mainnet 데이터베이스는 직접 생성하거나, 아래 링크에서 미리 마이그레이션된 데이터베이스를 다운로드할 수 있습니다.


## 사용 가능한 OP Mainnet 스냅샷

<Info>
  [aria2](https://aria2.github.io/)를 사용하면 스냅샷 다운로드 속도를 크게 높일 수 있습니다.
</Info>

OP Mainnet의 모든 스냅샷은 OP Labs가 관리하는 [Data Directories](https://datadirs.optimism.io/) 웹사이트에서 확인할 수 있습니다.
모든 geth 스냅샷은 pebbleDB와 hash state scheme으로 구성되어 있습니다.


### Nethermind

[Nethermind](https://docs.nethermind.io/get-started/running-node/l2-networks#op-stack)는 노드를 시작할 때 필요한 스냅샷의 다운로드와 적용을 자동으로 처리합니다. 스냅샷을 수동으로 다운로드할 필요가 없습니다. 노드는 다음과 같이 동작합니다.

1.  빈 데이터베이스로 시작합니다
2.  필요한 ancient 데이터를 자동으로 다운로드합니다
3.  데이터를 적용하고 동기화를 계속합니다

이 과정은 완전히 자동화되어 있으며 추가 구성이 필요하지 않습니다.
`-c op-mainnet` 플래그와 함께 `Nethermind`를 실행하면 이 구성이 자동으로 사용됩니다.

## 서드파티 스냅샷

[Allnodes](https://www.allnodes.com)는 OP Mainnet 및 Testnet의 풀 노드 스냅샷을 제공합니다. [여기](https://www.publicnode.com/snapshots#optimism)에서 확인할 수 있습니다.
**참고:** Allnodes는 서드파티 제공업체이며, Optimism Foundation은 해당 스냅샷을 검증하지 않았습니다.
