## OP Stack은 어떻게 최신 혁신을 지속적으로 반영합니까?
    
OP Stack은 차세대 온체인 제품을 배포하기 위한 Optimism의 오픈소스 소프트웨어입니다. 이 소프트웨어는 MIT 라이선스를 따르므로 누구나 자유롭게 사용하고 포크할 수 있습니다. OP Stack에는 활발한 핵심 개발자 커뮤니티가 있으며, 이들은 스택에 기여하여 프로토콜 사용자가 중요하게 여기는 기능과 가치가 반영되도록 합니다. 

OP Enterprise는 OP Stack을 만든 팀이 제공하는 관리형 블록체인 인프라입니다. 운영, 보안, 업그레이드, 확장을 처리합니다. 고객은 체인의 구성, 경제 모델, 제품 로드맵에 대한 완전한 제어권을 유지합니다.

## OP Stack에는 새로운 기능이 어떻게 추가됩니까?
        
OP Labs와 외부 기여자는 OP Enterprise 고객과의 협의를 바탕으로 기능 로드맵을 결정합니다. 논의를 바탕으로 프로토콜 업그레이드 초안이 작성되며, 이는 프로토콜 업그레이드 프로세스를 거칩니다. 
        
## 프로토콜 업그레이드 프로세스란 무엇입니까?
        
프로토콜 업그레이드 프로세스는 OP Stack이 플랫폼 위에서 사업을 구축하는 기업의 이익에 반하여 변경되지 않도록 설계되었습니다. 이는 중앙화된 대안과 비교했을 때 크립토 시스템이 갖는 핵심 이점입니다. 플랫폼 리스크는 [Web 2 플랫폼](https://a16zcrypto.com/posts/article/when-is-decentralizing-on-a-blockchain-valuable/)에서 흔히 나타나는 리스크이며, OP Stack 위에서 구축하는 대형 파트너에게 중요한 고려 사항입니다.

![프로토콜 업그레이드 프로세스](/public/img/governance/protocol-upgrade-process.png)

프로토콜 업그레이드는 OP Labs 또는 OP Stack의 다른 핵심 기여자가 초안을 작성합니다. 구현되기 전에 업데이트는 여러 devnet에서 테스트되며, 필요한 경우 독립적인 보안 팀의 감사를 받습니다. Optimism의 감사 정책에 대한 자세한 내용은 [여기](https://gov.optimism.io/t/op-labs-audit-framework-when-to-get-external-security-review-and-how-to-prepare-for-it/6864)에서 확인할 수 있습니다.

업데이트가 프로덕션 준비가 되었음이 확인되면 7일간의 거부권(veto) 기간에 들어갑니다. 이를 통해 모든 토큰 보유자는 프로토콜 업그레이드가 자신의 이익에 불리하거나 플랫폼 전체에 해를 끼칠 수 있다고 판단하는 경우 이를 차단할 수 있습니다. 이것이 OP Stack의 주요 이해관계자에 대한 플랫폼 리스크를 줄이는 방법입니다. 

제안이 거부되면 이의 제기 및 논의 단계에 들어가며, 다시 제출할 수 있습니다. 

프로토콜 업그레이드 프로세스에 대한 전체 내용은 [Operating Manual](https://github.com/ethereum-optimism/OPerating-manual/blob/main/manual.md)을 참조하십시오. 
        
## 내 체인은 기능 로드맵에 구체적으로 어떻게 영향을 미칠 수 있습니까?
        
OP Labs와 핵심 개발자는 OP Enterprise 고객의 요구 사항이 반영되도록 기능 로드맵에 대해 고객과 적극적으로 협의합니다. 프로토콜 업그레이드 프로세스 동안 체인은 다양한 연구 개발 저장소에 참여하여 의견을 공유하도록 권장됩니다. 
        
## Optimism은 내 체인의 탈중앙화 달성을 어떻게 돕습니까?
        
업그레이드 키가 Optimism Security Council에 의해 관리되는 무허가형 결함 증명(Permissionless Fault Proof) OP Chain은 [L2Beat 프레임워크](https://l2beat.com/stages)에서 Stage 1로 분류됩니다. 이 분산된 그룹은 Optimism이 관리하는, 보안 검토를 거친 업그레이드라는 이점을 제공합니다.
