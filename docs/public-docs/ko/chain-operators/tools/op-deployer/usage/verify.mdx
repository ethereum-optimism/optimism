[`bootstrap`](/ko/chain-operators/tools/op-deployer/usage/bootstrap) 또는 [`apply`](/ko/chain-operators/tools/op-deployer/usage/apply)로 컨트랙트를 배포한 후에는 `verify` 명령을 사용하여 Etherscan 또는 Blockscout와 같은 블록 탐색기에서 소스 코드를 검증할 수 있습니다. 이 명령은 `forge verify-contract` 바이너리를 사용하며, 생성자 인수 감지와 소스 코드 검증을 자동으로 처리합니다.

## 사용법

`verify` 명령은 다음과 같이 호출할 수 있습니다.

```shell
op-deployer verify \
  --l1-rpc-url <l1 rpc url> \
  --input-file <filepath to input .json or state.json file> \
  --verifier-api-key <your api key> \
  --artifacts-locator <l1 forge-artifacts locator> \
  --verifier etherscan
```

Blockscout 검증의 경우(mainnet/sepolia의 기본 URL 사용, API 키 불필요):

```shell
op-deployer verify \
  --l1-rpc-url <l1 rpc url> \
  --input-file <filepath to input .json or state.json file> \
  --artifacts-locator <l1 forge-artifacts locator> \
  --verifier blockscout
```

커스텀 블록 탐색기 검증의 경우(Etherscan v2 호환, API 키가 필요할 수 있음):

```shell
op-deployer verify \
  --l1-rpc-url <l1 rpc url> \
  --input-file <filepath to input .json or state.json file> \
  --artifacts-locator <l1 forge-artifacts locator> \
  --verifier custom \
  --verifier-url <custom etherscan v2 compatible api url>
```

## CLI 인수

### `--l1-rpc-url`

배포할 L1 체인의 RPC URL을 정의합니다(현재 mainnet과 sepolia만 지원).

### `--input-file`

입력 파일의 전체 경로입니다. 다음 중 하나일 수 있습니다.

*   컨트랙트 이름/주소 쌍이 포함된 단순 JSON 파일(`bootstrap superchain|implementations`의 출력)
*   전체 `state.json` 파일(`apply`의 출력)

verifier는 파일 형식을 자동으로 감지하고 모든 컨트랙트를 추출합니다. `--contract-name` 플래그를 전달하지 않으면 입력 파일의 모든 컨트랙트가 검증됩니다.

### `--contract-name`(선택 사항)

검증할 단일 컨트랙트 이름을 지정하며, 입력 파일 내의 컨트랙트 키와 일치해야 합니다. 지정하지 않으면 입력 파일의 모든 컨트랙트가 검증됩니다.

### `--artifacts-locator`

`forge build` 명령의 출력(즉, 컴파일된 바이트코드와 solidity 소스 코드)이 포함된 forge-artifacts의 locator입니다. 로컬 경로(`file://` 접두사), 원격 URL(`http://` 또는 `https://` 접두사), 또는 표준 컨트랙트 태그(`tag://op-contracts/v` 접두사)를 사용할 수 있습니다.

### `--verifier`

검증에 사용할 블록 탐색기입니다. 쉼표로 구분하여 여러 verifier를 지정할 수 있습니다.

옵션:

*   `etherscan`(기본값): mainnet/sepolia에 Etherscan을 사용합니다
*   `blockscout`: mainnet/sepolia의 기본 Blockscout URL을 사용합니다
*   `custom`: 커스텀 Etherscan v2 호환 인스턴스용입니다(`--verifier-url` 필요)

예시:

*   단일 verifier: `--verifier etherscan`
*   여러 verifier: `--verifier etherscan,blockscout`(둘 다에서 검증)

### `--verifier-url`

verifier API URL입니다. 사용 방법은 verifier 유형에 따라 다릅니다.

*   `etherscan`: 무시됩니다(chain ID에서 자동으로 결정됨)
*   `blockscout`: 선택 사항입니다(기본값은 mainnet/sepolia의 표준 Blockscout URL)
*   `custom`: 필수입니다. 예: `https://etherscanv2.compat-api.example.com/api`

## 자동 검증

`apply` 또는 `bootstrap` 명령에 `--verify` 플래그를 사용하면 배포 후 컨트랙트를 자동으로 검증할 수 있습니다.

```shell
op-deployer apply \
  --workdir ./.deployer \
  --l1-rpc-url <l1 rpc url> \
  --private-key <deployer private key> \
  --verify \
  --verifier-api-key <your api key>
```

이렇게 하면 배포 프로세스가 끝날 때 배포된 모든 컨트랙트가 검증됩니다.

### 다중 verifier 배포

여러 블록 탐색기에서 동시에 검증할 수 있습니다.

```shell
op-deployer bootstrap superchain \
  --l1-rpc-url <l1 rpc url> \
  --private-key <deployer private key> \
  --outfile ./superchain.json \
  --superchain-proxy-admin-owner <owner address> \
  --guardian <guardian address> \
  --verify \
  --verifier etherscan,blockscout \
  --verifier-api-key <etherscan api key>
```

이 명령은 다음을 수행합니다.

1.  공유 컨트랙트를 배포합니다
2.  Etherscan에서 검증합니다(API 키 사용)
3.  Blockscout에서 검증합니다(API 키 불필요)
4.  두 verifier의 결과를 합쳐 보고합니다

## 지원되는 컨트랙트 번들

verify 명령은 이제 모든 컨트랙트 번들을 지원합니다.

*   **Shared** 컨트랙트(`bootstrap superchain`에서 배포)
*   **Implementations** 컨트랙트(`bootstrap implementations`에서 배포)
*   **OpChain** 컨트랙트(`apply`에서 배포, 모든 체인별 컨트랙트 포함)

`apply`의 `state.json` 파일을 사용하면 verifier가 모든 배포 단계의 컨트랙트를 자동으로 추출하고 검증합니다.

## 블록 탐색기 지원

verify 명령은 forge 바이너리를 통해 Etherscan 및 Blockscout 블록 탐색기를 모두 지원하며, 모든 Etherscan v2 호환 API도 지원합니다.
