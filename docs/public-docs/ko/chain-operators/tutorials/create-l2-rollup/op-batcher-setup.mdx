<Info>

</Info>

<Info>
  **자동 설정 제공**

  모든 구성 요소를 포함한 완전한 작동 설정은 코드 디렉터리의 [자동화된 방식](https://github.com/ethereum-optimism/optimism/tree/develop/docs/public-docs/create-l2-rollup-example/)을 확인하십시오.
</Info>

## batcher의 역할 이해하기

batcher(`op-batcher`)는 L2 체인 데이터를 L1에 연결하는 핵심 구성 요소입니다. 주요 역할은 다음과 같습니다.

*   **배치 제출**: L2 트랜잭션을 수집하여 배치로 L1에 제출합니다.
*   **데이터 가용성**: 검증을 위해 L2 트랜잭션 데이터를 L1에서 사용할 수 있도록 보장합니다.
*   **비용 최적화**: L1 비용을 최소화하기 위해 트랜잭션 데이터를 압축하고 효율적으로 패킹합니다.
*   **채널 관리**: 최적의 배치 제출 시점을 위해 데이터 채널을 관리합니다.

batcher는 sequencer에서 트랜잭션 데이터를 읽고 압축된 배치를 L1의 `BatchInbox` 컨트랙트에 제출합니다.

## 사전 요구 사항

batcher를 설정하기 전에 다음이 준비되어 있는지 확인하십시오.

**실행 중인 인프라:**

*   작동 중인 sequencer node
*   L1 RPC 엔드포인트에 대한 접근 권한

**네트워크 정보:**

*   L2 체인 ID 및 네트워크 구성
*   L1 네트워크 세부 정보(체인 ID, RPC 엔드포인트)
*   배포에서 얻은 `BatchInbox` 컨트랙트 주소

batcher 설정에는 일관되고 격리된 환경을 제공하는 Docker 사용을 권장합니다. 고급 사용자는 소스에서 빌드할 수도 있습니다.

    컨테이너 기반 배포를 선호한다면 공식 Docker 이미지를 사용하여 다음을 수행할 수 있습니다.

    <Steps>

      <Step title="디렉터리 구조 설정 및 구성 파일 복사">

      ```bash
      # Create your batcher directory inside rollup
      cd ../    # Go back to rollup directory if you're in sequencer
      mkdir batcher
      cd batcher

      # Copy configuration files from deployer
      cp ../deployer/.deployer/state.json .

      # Extract the BatchInbox address
      BATCH_INBOX_ADDRESS=$(cat state.json | jq -r '.opChainDeployments[0].systemConfigProxyAddress')
      echo "BatchInbox Address: $BATCH_INBOX_ADDRESS"
      ```

      </Step>

      <Step title="환경 변수 파일 생성">

      <Info>
        **OP Stack 표준 변수**

        batcher는 OP Stack 규칙을 따르는 OP Stack 표준 환경 변수를 사용합니다. batcher 전용 설정에는 `OP_BATCHER_` 접두사가 붙습니다.
      </Info>

      ```bash
      # Create .env file with your actual values
      cat > .env << 'EOF'
      # L1 Configuration - Replace with your actual RPC URLs
      OP_BATCHER_L1_RPC_URL=https://sepolia.infura.io/v3/YOUR_ACTUAL_INFURA_KEY
      # Private key - Replace with your actual private key
      OP_BATCHER_PRIVATE_KEY=YOUR_ACTUAL_PRIVATE_KEY

      # L2 Configuration - Should match your sequencer setup
      OP_BATCHER_L2_ETH_RPC=http://op-reth:8545
      OP_BATCHER_ROLLUP_RPC=http://op-node:8547

      # Contract addresses - Extract from your op-deployer output
      OP_BATCHER_BATCH_INBOX_ADDR=YOUR_ACTUAL_BATCH_INBOX_ADDRESS

      # Batcher configuration
      OP_BATCHER_POLL_INTERVAL=1s
      OP_BATCHER_SUB_SAFETY_MARGIN=6
      OP_BATCHER_NUM_CONFIRMATIONS=1
      OP_BATCHER_SAFE_ABORT_NONCE_TOO_LOW_COUNT=3
      OP_BATCHER_MAX_CHANNEL_DURATION=1
      OP_BATCHER_DATA_AVAILABILITY_TYPE=calldata

      # RPC configuration
      OP_BATCHER_RPC_PORT=8548
      EOF
      ```

      **중요**: 모든 자리 표시자 값(`YOUR_ACTUAL_*`)을 실제 구성 값으로 바꾸십시오.

      </Step>

      <Step title="docker-compose.yml 파일 생성">

      <Info>
        이 구성은 sequencer가 동일한 `op-stack` 네트워크에서 `sequencer-node`라는 이름의 Docker 컨테이너로 실행 중이라고 가정합니다.
        batcher를 시작하기 전에 sequencer가 실행 중인지 확인하십시오.
      </Info>

      ```yaml

      services:
        op-batcher:
          image: us-docker.pkg.dev/oplabs-tools-artifacts/images/op-batcher:v1.16.11
          volumes:
            - .:/workspace
          working_dir: /workspace
          ports:
            - "8548:8548"
          env_file:
            - .env
          networks:
            - sequencer-node_default
          command: >
            op-batcher
            --rpc.addr=0.0.0.0
            --rpc.enable-admin
            --resubmission-timeout=30s
            --log.level=info
            --log.format=json
          restart: unless-stopped

      networks:
        sequencer-node_default:
          external: false
      ```

      </Step>

      ```bash
      # Make sure your sequencer network exists
      # Start the batcher
      docker-compose up -d

      # View logs
      docker-compose logs -f op-batcher
      ```

      </Step>

    ### Batcher 구성

    같은 디렉터리에 `scripts/start-batcher.sh`를 생성합니다.

    ```bash
    #!/bin/bash

    source .env

    # Path to the op-batcher binary we built
    ../../optimism/op-batcher/bin/op-batcher \
      --l2-eth-rpc=$L2_RPC_URL \
      --rollup-rpc=$ROLLUP_RPC_URL \
      --poll-interval=$POLL_INTERVAL \
      --sub-safety-margin=$SUB_SAFETY_MARGIN \
      --num-confirmations=$NUM_CONFIRMATIONS \
      --safe-abort-nonce-too-low-count=$SAFE_ABORT_NONCE_TOO_LOW_COUNT \
      --resubmission-timeout=$RESUBMISSION_TIMEOUT \
      --rpc.addr=0.0.0.0 \
      --rpc.port=$BATCHER_RPC_PORT \
      --rpc.enable-admin \
      --max-channel-duration=$MAX_CHANNEL_DURATION \
      --l1-eth-rpc=$L1_RPC_URL \
      --private-key=$BATCHER_PRIVATE_KEY \
      --batch-type=1 \
      --data-availability-type=blobs \
      --log.level=info
    ```

    ### Batcher 매개변수 설명

    *   **`--poll-interval`**: batcher가 배치할 새 L2 블록을 확인하는 주기
    *   **`--sub-safety-margin`**: L1 트랜잭션을 안전한 것으로 간주하기 전에 기다릴 확인(confirmation) 수
    *   **`--max-channel-duration`**: 채널을 열어 둘 최대 시간(L1 블록 단위)
    *   **`--batch-type`**: 배치 인코딩 유형(span batch는 1, singular batch는 0)
    *   **`--data-availability-type`**: 데이터 가용성에 blobs와 calldata 중 무엇을 사용할지 여부

    ### batcher 시작하기

      ### batcher 시작

      ```bash
      # Make the script executable
      chmod +x scripts/start-batcher.sh

      # Start the batcher
      ./scripts/start-batcher.sh
      ```

<Info>
  **일반적인 시작 메시지 이해하기**

  batcher를 시작하면 다양한 로그 메시지가 표시될 수 있습니다.

  *   `Added L2 block to local state`: 정상 동작이며, batcher가 블록을 처리하고 있음을 나타냅니다.
  *   `SetMaxDASize RPC method unavailable`: 사용 중인 실행 클라이언트 버전이 이 메서드를 지원하지 않는 경우 예상되는 메시지입니다.
  *   종료 중 `context canceled` 오류: 정상적인 정리 메시지입니다.
  *   `Failed to query L1 tip`: 정상 종료(graceful shutdown) 중에 발생할 수 있습니다.

  이러한 메시지 대부분은 정상 동작의 일부입니다. 구성 옵션 및 문제 해결에 대한 자세한 설명은 [Batcher 구성 레퍼런스](/ko/chain-operators/reference/batcher-configuration)를 참조하십시오.
</Info>
