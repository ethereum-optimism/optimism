이 가이드는 OP Stack의 Layer 1 컨트랙트를 `op-contracts/v1.3.0`에서 `op-contracts/v1.8.0`으로 업그레이드하는 구체적인 방법을 안내합니다. 이 업그레이드에는 시스템 구성에 대한 중요한 변경 사항이 포함되며 Fault Proof System이 도입됩니다.

## Holocene 업그레이드 개요

Holocene 업그레이드는 프로토콜 업그레이드입니다. 자세한 내용은 [Holocene 공지 페이지](https://docs.optimism.io/notices/holocene-changes)에서 확인하십시오. 이 가이드는 OP Stack 체인을 L2 Output Oracle System에서 Holocene 업그레이드와 연관된 허가형(permissioned) Fault Proof System 컨트랙트 버전으로 전환하는 방법을 보여 줍니다. 

OP Stack 컨트랙트 v1.8.0으로 업그레이드하고 허가형 결함 증명(fault proof)을 활성화하면, L1에서 생성된 대기 중인(최종 확정되지 않은) 모든 출금 증명이 무효화됩니다. 즉, 업그레이드 후 사용자가 출금을 수동으로 다시 증명해야 하며, 이 과정은 자동으로 이루어지지 않습니다.

## 단계별 업그레이드 과정

### 1. 작업 디렉터리 생성

작업 디렉터리를 생성합니다.

```shell
mkdir upgrade-dir
cd upgrade-dir
```

그런 다음 outputs 디렉터리를 생성합니다.

```shell
mkdir outputs
```

### 2. 구성 파일 복사

`deployments.json`과 `deploy-config.json`을 작업 디렉터리에 복사합니다.

### 3. 환경 구성 및 배포

필요한 정보로 `.env` 파일을 생성하고 업데이트합니다.

```json
##############################################
#               ↓  Required  ↓               #
##############################################

# Can be "mainnet" or "sepolia"
NETWORK=

# Etherscan API key used to verify contract bytecode
ETHERSCAN_API_KEY=

# RPC URL for the L1 network that matches $NETWORK
ETH_RPC_URL=

# Private key used to deploy the new contracts for this upgrade
PRIVATE_KEY=

# Base fee scalar for the SystemConfig
BASE_FEE_SCALAR=

# Blob base fee scalar for the SystemConfig
BLOB_BASE_FEE_SCALAR=

# Check if required files and folders exist
if [ ! -f "./deploy_config.json" ]; then
    echo "Error: deploy_config.json not found"
fi
if [ ! -f "./deployments.json" ]; then
    echo "Error: deployments.json not found"
fi
if [ ! -d "./outputs" ]; then
    echo "Error: outputs folder not found"
fi
```

### 4. 배포 프로세스 실행

다음 명령으로 배포 프로세스를 실행합니다.

```docker 
    docker run -t
    --env-file .env
    -v ./deploy_config.json:/deploy_config.json
    -v ./deployments.json:/deployments.json
    -v ./outputs:/outputs
    kfoplabs/upgrade-v1.3.0-v1.8.0-permissioned /deploy_config.json /deployments.json
```

`kfoplabs/upgrade-v1.3.0-v1.8.0-permissioned` 이미지의 소스 코드는 [Optimism 모노레포의 `perm/op-contracts/v1.8.0` 브랜치](https://github.com/ethereum-optimism/optimism/tree/perm/op-contracts/v1.8.0)에서 확인할 수 있습니다. 업그레이드 스크립트를 포크하거나 사용자 지정해야 하는 경우(예: L3 지원) 해당 브랜치에서 시작하십시오.

### 5. 출력 확인

배포 결과로 네 개의 파일이 출력되어야 합니다.

*   `deploy.log`는 배포 과정의 로그입니다
*   `deployments.json`에는 새로 배포된 컨트랙트 주소가 포함됩니다
*   `bundle.json`은 safe 트랜잭션 번들입니다
*   `transactions.json`은 실행된 배포 트랜잭션의 요약입니다
*   `standard-addresses.json`은 `SystemConfigImpl`, `OptimismPortal2Impl`, `L1CrossDomainMessengerImpl`, `L1StandardBridgeImpl`, `L1ERC721BridgeImpl`, `OptimismMintableERC20FactoryImpl`의 주소입니다
*   `validation.txt`는 Tenderly 상태 diff 검증에 사용됩니다. superchain-ops task에 필요한 일부 정보가 이 파일에 누락되어 있을 수 있으며, 이 정보는 대신 Tenderly 시뮬레이션 중에 생성됩니다. 

### 6. 출력 검증

이제 L1 컨트랙트 업그레이드를 수행하기 위해 온체인에서 실행할 수 있는 calldata가 준비되었습니다. 이 업그레이드를 시뮬레이션하여 변경 사항이 예상대로인지 확인해야 합니다. 예상되는 변경 사항은 [superchain-ops 저장소](https://github.com/ethereum-optimism/superchain-ops/blob/main/tasks/eth/022-holocene-fp-upgrade/NestedSignFromJson.s.sol)에 있는 이전에 실행된 업그레이드 task의 검증 파일을 참고하십시오. 상태 변경이 예상대로라고 확신하면 업그레이드에 서명하고 실행할 수 있습니다.
