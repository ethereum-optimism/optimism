<Info>
  Alt-DA 모드 기능은 현재 MIT 라이선스 OP Stack 내에서 <strong>베타</strong> 단계입니다. 베타 기능은 핵심 기여자들이 개발하고 검토하며, 개발자들에게 요청이 많은 구성을 조기에 사용할 수 있도록 제공합니다.
  이러한 기능은 안정성 문제가 발생할 수 있으며, 초기 사용자의 피드백을 환영합니다.
</Info>

이 가이드는 Alt-DA 모드 체인을 실행하려는 체인 운영자를 위한 안내서입니다. 이 OP Stack 구성에 대한 전반적인 개요는 [Alt-DA 모드 설명서](/ko/op-stack/features/experimental/alt-da-mode)를 참고하십시오.
Alt-DA 모드 OP Stack 체인을 사용하면 체인 운영자는 정상 동작하는 OP Stack DA Server를 구축한 모든 대체 데이터 가용성 레이어에 데이터를 게시하고 읽을 수 있습니다.

<Info>
  이 페이지에는 아래에 설명된 특정 [포함 기준](#inclusion-criteria)을 충족하는 제공자가 포함되어 있습니다.
</Info>

## 사전 요구 사항

체인을 실행할 때는 최소한 다음과 같은 호환 op\* 버전을 사용해야 합니다.

*   op-node/v1.9.1
*   op-proposer/v1.9.1
*   op-batcher/v1.9.1
*   op-reth 최신 버전([실행 클라이언트 가이드](/ko/node-operators/guides/configuration/execution-clients) 참고)

<OpGethEol />

<Steps>
  <Step title="DA server 설정">
  <Info>
      DA Server는 핵심 기여자가 개발하거나 유지 관리하지 않습니다. DA server는 서드파티가 유지 관리하며, 실행에 따른 위험은 사용자 본인이 부담합니다. 질문이나 문제가 있으면 실행하려는 DA Server를 개발한 팀에 문의하십시오.
    </Info>
  
    *   [Celestia DA server](https://github.com/celestiaorg/op-plasma-celestia/blob/main/README.md) 실행 방법에 대한 Celestia 문서
    *   [EigenDA DA server](https://github.com/Layr-Labs/op-plasma-eigenda/blob/main/README.md) 실행 방법에 대한 EigenDA 문서
    *   [AvailDA DA Server](https://docs.availproject.org/docs/build-with-avail/deploy-rollup-on-avail/Optimium) 실행 방법에 대한 Avail 문서
    *   [0gDA DA Server](https://github.com/0glabs/0g-da-op-plasma) 실행 방법에 대한 0gDA 문서
    *   [Near DA Server](https://github.com/Nuffle-Labs/data-availability/blob/84b484de98f58a91bf12c8abe8df27f5e753f63a/docs/OP-Alt-DA.md) 실행 방법에 대한 Near DA 문서
  </Step>

  <Step title="`op-node` 구성">
  *   평소와 같이 OP 체인을 구동하되, `--altda.enabled=true`를 설정하고 `op-batcher`와 `op-node` 모두가 DA server를 가리키도록 하십시오.
    *   실행 클라이언트(`op-reth`)나 `op-proposer`에는 구성 변경이 필요하지 않습니다.
  
    ```
       Alt-DA (EXPERIMENTAL)
  
       
        --altda.da-server value                                               ($OP_NODE_ALTDA_DA_SERVER)
              HTTP address of a DA Server
       
        --altda.enabled                    (default: false)                   ($OP_NODE_ALTDA_ENABLED)
              Enable Alt-DA mode
       
        --altda.verify-on-read             (default: true)                    ($OP_NODE_ALTDA_VERIFY_ON_READ)
              Verify input data matches the commitments from the DA storage service
  
    ```
  </Step>

  <Step title="batcher 구성">
  *   `--altda.enabled=true`와 `--altda.da-service=true`를 설정하십시오.
    *   `--altda.da-server=$DA_SERVER_HTTP_URL`에 URL을 지정하십시오.
  
    ```
        --altda.da-server value                                               ($OP_BATCHER_ALTDA_DA_SERVER)
              HTTP address of a DA Server
       
        --altda.da-service                 (default: false)                   ($OP_BATCHER_ALTDA_DA_SERVICE)
              Use DA service type where commitments are generated by the DA server
       
        --altda.enabled                    (default: false)                   ($OP_BATCHER_ALTDA_ENABLED)
              Enable Alt-DA mode
       
        --altda.verify-on-read             (default: true)                    ($OP_BATCHER_ALTDA_VERIFY_ON_READ)
              Verify input data matches the commitments from the DA storage service
    ```
  
    위의 1-3단계를 완료하면 Alt-DA 모드 체인이 구동됩니다.
  </Step>

  <Step title="수수료 구성 설정">
  *   체인 운영자는 모든 데이터를 Ethereum에 게시하는 것이 아니라 commitment만 게시하므로, 사용자에게 부과할 fee scalar 값을 결정해야 합니다. fee scalar 값은 네트워크 처리량에 따라 달라지므로 체인 운영자가 필요에 따라 조정해야 합니다.
    *   Alt-DA 모드의 비용 구조: 트랜잭션 데이터는 128kb 청크로 분할되어 DA 레이어에 제출됩니다. 그런 다음 각 128kb 청크에 대해 32바이트 commitment가 L1에 제출됩니다(batch inbox 주소로 전송). 이후 체인이 처리하는 트랜잭션 수 대비 이 비용이 얼마인지 계산하십시오.
    *   deploy config 안에서 scalar 값을 설정하십시오. 아래 예시는 DA 레이어 비용이 무시할 만하다고 가정하고 계산한 fee scalar 값의 예이지만, 네트워크 처리량에 따라 높이거나 낮추어 조정해야 합니다. scalar 값을 설정하는 방법은 문서의 [이 섹션](/ko/chain-operators/guides/features/blobs#update-your-scalar-values-for-blobs)을 참고하십시오.
  
        ```
        // Set in Deploy Config
          "gasPriceOracleBaseFeeScalar": 7663, // Approximate commitment tx base cost
          "gasPriceOracleBlobBaseFeeScalar": 0, // blobs aren't used for submitting the small data commitments
        ```
  
    <Info>
      일부 초기 scalar 값은 [2단계](#configure-your-op-node)에서 deploy config에 미리 설정해야 합니다. 이후 체인 운영자는 L1 트랜잭션으로 scalar 값을 업데이트할 수 있습니다.
    </Info>
  </Step>
</Steps>

## 노드 운영자용(full node 및 아카이브 node)

*   [1단계](#setup-your-da-server)에 설명된 대로 DA server를 실행하십시오
*   [2단계](#configure-your-op-node)에 나열된 것과 동일한 `--altda.enabled=true, --altda.da-server...`를 `op-node`에 지정하십시오

## 포함 기준

이 페이지에 소개되기를 원하는 Alt DA 팀은 다음 기준을 충족해야 합니다.

*   자체 저장소에서 유지 관리되는, 정상 동작하는 [DA Server](https://specs.optimism.io/experimental/alt-da.html?utm_source=op-docs&utm_medium=docs#da-server)
*   [여기](#setup-your-da-server)에서 참조할 수 있는 상세한 지원 문서
*   구성, 컨트랙트 주소, RPC 주소가 연결된, 해당 DA server를 사용하는 정상 동작하는 OP Stack devnet

## 호환성을 깨는 변경 사항: Plasma Mode에서 Alt-DA 모드로 이름 변경

이 기능은 monorepo의 [0bb2ff5](https://github.com/ethereum-optimism/optimism/commit/0bb2ff57c8133f1e3983820c0bf238001eca119b)에서 Plasma Mode에서 Alt-DA 모드로 이름이 변경되었습니다. 알아 두어야 할 몇 가지 호환성을 깨는 변경 사항이 있습니다. 여기에는 구성 파일 파라미터, 환경 변수, CLI 명령의 변경이 포함됩니다.
마이그레이션을 진행하기 전에 [OP Stack v1.9.1](https://github.com/ethereum-optimism/optimism/releases/tag/v1.9.1) 이상을 사용하고 있는지 확인하십시오.

### `rollup.json` 구성 수정

기존 Plasma 구성을 새 Alt-DA 구성으로 교체하여 `rollup.json` 구성 파일을 업데이트하십시오.
기존 Plasma 구성에는 두 가지 형식이 있을 수 있습니다.

### 레거시 plasma 구성

구성이 다음과 같은 경우:

```json
"use_plasma": true,
"da_commitment_type": "GenericCommitment",
"da_challenge_contract_address": "0xAAA",
"da_challenge_window": 1000,
"da_resolve_window": 2000,
```

### 최신 plasma 구성

또는 다음과 같은 경우:

```json
"plasma_config": {
  "da_commitment_type": "GenericCommitment",
  "da_challenge_contract_address": "0xAAA",
  "da_challenge_window": 1000,
  "da_resolve_window": 2000
}
```

### 새 Alt-DA 구성

위의 구성 중 하나를 다음으로 교체하십시오.

```json
"alt_da": {
  "da_commitment_type": "GenericCommitment",
  "da_challenge_contract_address": "0xAAA",
  "da_challenge_window": 1000,
  "da_resolve_window": 2000
}
```

<Info>
  새 구성에는 기존 구성에 있던 필드만 포함하십시오.
</Info>

## OP Stack 런타임 구성 파라미터 업데이트

### CLI 파라미터

`op-node`와 `op-batcher` 모두에서 다음 CLI 파라미터를 업데이트하십시오.

| 이전 CLI 파라미터          | 현재 CLI 파라미터        |
| ------------------------- | ------------------------ |
| `--plasma.enabled`        | `--altda.enabled`        |
| `--plasma.da-server`      | `--altda.da-server`      |
| `--plasma.verify-on-read` | `--altda.verify-on-read` |
| `--plasma.da-service`     | `--altda.da-service`     |

### 환경 변수

#### op-node

| 이전 환경 변수                  | 현재 환경 변수                |
| ------------------------------- | ------------------------------ |
| `OP_NODE_PLASMA_ENABLED`        | `OP_NODE_ALTDA_ENABLED`        |
| `OP_NODE_PLASMA_DA_SERVER`      | `OP_NODE_ALTDA_DA_SERVER`      |
| `OP_NODE_PLASMA_VERIFY_ON_READ` | `OP_NODE_ALTDA_VERIFY_ON_READ` |
| `OP_NODE_PLASMA_DA_SERVICE`     | `OP_NODE_ALTDA_DA_SERVICE`     |

#### op-batcher

| 이전 환경 변수                     | 현재 환경 변수                   |
| ---------------------------------- | --------------------------------- |
| `OP_BATCHER_PLASMA_ENABLED`        | `OP_BATCHER_ALTDA_ENABLED`        |
| `OP_BATCHER_PLASMA_DA_SERVER`      | `OP_BATCHER_ALTDA_DA_SERVER`      |
| `OP_BATCHER_PLASMA_VERIFY_ON_READ` | `OP_BATCHER_ALTDA_VERIFY_ON_READ` |
| `OP_BATCHER_PLASMA_DA_SERVICE`     | `OP_BATCHER_ALTDA_DA_SERVICE`     |

#### op-alt-da(이전 명칭 op-plasma) daserver

| 이전 환경 변수                             | 현재 환경 변수                        |
| ------------------------------------------ | -------------------------------------- |
| `OP_PLASMA_DA_SERVER_ADDR`                 | `OP_ALTDA_SERVER_ADDR`                 |
| `OP_PLASMA_DA_SERVER_PORT`                 | `OP_ALTDA_SERVER_PORT`                 |
| `OP_PLASMA_DA_SERVER_FILESTORE_PATH`       | `OP_ALTDA_SERVER_FILESTORE_PATH`       |
| `OP_PLASMA_DA_SERVER_GENERIC_COMMITMENT`   | `OP_ALTDA_SERVER_GENERIC_COMMITMENT`   |
| `OP_PLASMA_DA_SERVER_S3_BUCKET`            | `OP_ALTDA_SERVER_S3_BUCKET`            |
| `OP_PLASMA_DA_SERVER_S3_ENDPOINT`          | `OP_ALTDA_SERVER_S3_ENDPOINT`          |
| `OP_PLASMA_DA_SERVER_S3_ACCESS_KEY_ID`     | `OP_ALTDA_SERVER_S3_ACCESS_KEY_ID`     |
| `OP_PLASMA_DA_SERVER_S3_ACCESS_KEY_SECRET` | `OP_ALTDA_SERVER_S3_ACCESS_KEY_SECRET` |

이러한 변경을 완료하면 새 Alt-DA 모드를 사용하도록 시스템이 올바르게 구성됩니다.

<Info>
  mainnet에 적용하기 전에 testnet에서 구성을 철저히 테스트하십시오.
</Info>
