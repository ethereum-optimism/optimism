snap sync는 OP Stack node의 동기화 경험을 크게 개선합니다. 합의 계층에서는 `op-node`가 `--syncmode=execution-layer` 플래그로 이를 활성화합니다.
실행 클라이언트는 제네시스부터 모든 블록을 다시 실행하는 대신, P2P를 통해 네트워크의 다른 node로부터 체인 및 상태 데이터를 다운로드하고 완성된 상태부터 실행을 시작합니다.
따라서 snap sync는 full sync보다 훨씬 빠릅니다.

*   snap sync를 사용하면 네트워크의 노드 운영자(node operator)가 더 빠르게 동기화할 수 있습니다.
*   snap sync를 사용하면 Ecotone 이후 네트워크의 node가 [blob archiver](/ko/node-operators/guides/management/blobs)를 실행할 필요가 없습니다.

## 체인에서 snap sync 활성화

snap sync를 활성화하려면 체인 운영자는 네트워크에 노출되어 있고 트랜잭션 gossip이 비활성화된 node를 실행해야 합니다.
이 node는 네트워크의 다른 node로부터 오는 실행 계층의 snap sync 요청을 처리합니다.

<Info>
snap sync를 위해 모든 node는 동기화할 다른 node를 쉽게 찾을 수 있도록 포트 `30303` TCP와 `30303` UDP를 노출해야 합니다. 이는 op-reth의 `--port`(TCP) 및 `--discovery.port`(UDP) 기본값입니다.
  *   [`--discovery.port`](/ko/node-operators/op-reth/cli/op-reth/node)로 포트를 설정한 경우, 지정한 UDP 포트를 열어야 합니다.
  *   [`--port`](/ko/node-operators/op-reth/cli/op-reth/node)를 설정한 경우, 지정한 TCP 포트를 열어야 합니다.
  *   유일한 예외는 sequencer와 트랜잭션 수신(ingress) node입니다.
</Info>

<Steps>
  <Step title="snap sync node 설정">
  *   포트 `30303`(op-reth의 기본 수신 및 discovery 포트)을 TCP와 UDP로 인터넷에 노출합니다.
    *   [`--rollup.disable-tx-pool-gossip`](/ko/node-operators/op-reth/cli/op-reth/node) 플래그로 트랜잭션 gossip을 비활성화합니다
  </Step>

  <Step title="네트워크에서 snap sync 활성화">
  *   노드 운영자가 체인 네트워크에서 snap sync(execution-layer sync)를 활성화하는 방법은 [동기화 모드 레퍼런스](/ko/node-operators/reference/consensus-layer-sync)를 참조하세요.
  </Step>
</Steps>
