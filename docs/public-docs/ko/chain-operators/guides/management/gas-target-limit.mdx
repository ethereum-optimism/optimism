이 가이드는 더 높은 gas limit에서 블록 처리 성능을 최적화하는 방법, 활성화 전에 인프라를 테스트하는 방법, 그리고 운영 중인 체인에서 gas target 및/또는 limit을 안전하게 변경하는 방법을 다룹니다.
이 가이드는 OP Stack 체인에 [Holocene 기능](/ko/notices/archive/holocene-changes)이 활성화되어 있다고 가정합니다. 

## 최적의 성능을 위한 권장 구성

블록 처리 성능을 개선하는 것으로 알려진 몇 가지 방법은 다음과 같습니다.

*   로컬 SSD나 기타 영구 디스크 대신 **스토리지로 NVMe 사용**
*   가능한 경우 아카이브 node 대신 **full node 사용**

## 활성화 전 테스트

체인과 지원 인프라가 gas limit까지의 블록을 일관되게 처리할 수 있는지 확인하려면 성능 테스트를 실행해야 합니다. 
벤치마크를 실행하고 결과를 신중하게 분석하여 실행 클라이언트가 증가한 gas 사용량을 처리할 수 있는지 확인해야 합니다.

## Gas target/limit 변경

운영 중인 체인에서 gas target/limit을 변경하는 방법입니다.

### 관련 구성 파라미터

OP Stack 체인의 gas 구성은 Ethereum과 동일한 EIP-1559 파라미터를 사용합니다. 
여기서 **gas target** = **gas limit** / **elasticity**입니다. 
이 값들은 `SystemConfig` 컨트랙트에서 확인할 수 있습니다.

### 절차

Holocene은 `SystemConfig`를 통해 EIP-1559 파라미터인 `elasticity`와 `denominator`를 변경하는 기능을 도입했습니다. 이를 통해 `elasticity`와 블록 `gasLimit`에 적절한 값을 설정할 수 있습니다.

**예시**: 블록 *limit*을 30Mgas/block으로 유지하면서 *target*을 두 배로 늘리려면:

<Steps>
  <Step title="기존 EIP-1559 값 조회">
    기존 `eip1559Elasticity` 및 `eip1559Denominator` 값을 조회합니다.

    ```solidity
    elasticity = SystemConfig.eip1559Elasticity() // 6
    denominator = SystemConfig.eip1559Denominator() // 50
    limit = SystemConfig.gasLimit() // 30_000_000 gas, 30Mgas    
    ```

    현재 target = `30Mgas / 6 = 5Mgas per block`
  </Step>

  <Step title="새 EIP-1559 파라미터 설정">
    이전 단계의 값을 입력으로 사용하여 새 파라미터를 설정하고 `elasticity`를 `6`에서 `3`으로 줄입니다.
    ```solidity
    SystemConfig.setEIP1559Params(denominator, 3)
    ```
    새 target = `30Mgas / 3 = 10Mgas per block`
  </Step>
</Steps>

## 활성화 후 모니터링

gas 변경을 실행한 후 모니터링해야 할 항목입니다.

### SystemConfig 컨트랙트 값

*   `SystemConfig.gasLimit()` 
*   `SystemConfig.eip1559Denominator()`
*   `SystemConfig.eip1559Elasticity()` 

### 블록 탐색기

예를 들어 [OP Mainnet](https://optimistic.etherscan.io/blocks)에서:

*   `gasUsed > gasTarget`인 블록은 base fee를 증가시켜야 합니다
*   `gasUsed < gasTarget`인 블록은 base fee를 감소시켜야 합니다

### Node 성능

*   node가 블록 주기보다 빠르게 블록을 처리하고 있는지 확인합니다
*   CPU/메모리 사용량과 블록 처리의 p99 tail latency를 모니터링합니다
