`--l1-trust-rpc` 플래그는 악의적이거나 결함이 있는 RPC 공급자로부터 보호하기 위해 Kona가 L1 RPC 응답에 대해 추가 검증을 수행할지 여부를 제어합니다. 이 가이드는 인프라에 적합한 설정을 선택하는 데 도움을 주고 설정 방법을 보여 줍니다.

L2 엔진에는 신뢰 플래그가 적용되지 않습니다. L2 엔진은 인증된 Engine API를 통해 연결되는 node 자체의 실행 클라이언트이며, 블록을 잘못 보고하는 실행 클라이언트는 이미 체인에 대한 node의 관점을 통제하고 있습니다. 따라서 Kona는 op-node와 마찬가지로 L2 엔진을 항상 신뢰합니다.

## 신뢰 모드 {#trust-modes}

기본값은 op-node와 동일하게 L1 신뢰가 비활성화(`false`)되어 있습니다. 이전의 L1 신뢰 동작을 유지하려면 `--l1-trust-rpc=true` 또는 `KONA_NODE_L1_TRUST_RPC=true`를 설정하십시오.

**신뢰 모드(신뢰 활성화, `true`):**
- RPC 응답을 검증 없이 사용합니다.
- 성능에 최적화되어 있습니다.
- 로컬 node와 신뢰할 수 있는 인프라에 적합합니다.
- RPC 공급자가 신뢰할 수 있고 정직하다고 가정합니다.

**검증 모드(신뢰 비활성화, `false`):**
- 모든 L1 헤더를 블록 해시와 대조하여 확인하며, 번호로 조회한 모든 L1 블록이 실제로 해당 번호에 있는지 확인합니다.
- 각 L1 블록의 트랜잭션과 영수증(receipt)을 헤더의 transactions root 및 receipts root와 대조하여 확인합니다.
- L1의 `SystemConfig` 컨트랙트에서 읽은 unsafe 블록 서명자(unsafe block signer)를 `eth_getProof`를 사용해 블록의 state root에 대해 증명합니다.
- 잘못된 데이터를 반환하는 악의적이거나 결함이 있는 RPC 공급자로부터 보호합니다.
- 공개 또는 서드파티 RPC 엔드포인트에 권장됩니다.
- 이러한 확인으로 인해 약간의 성능 오버헤드가 발생합니다.

<Note>
`--l1-trust-rpc=false`를 사용하는 경우 L1 RPC는 최근 블록에 대해 `eth_getProof`를 제공해야 합니다. 그렇지 않으면 `kona-node`는 unsafe 블록 서명자를 읽을 수 없어 시작에 실패합니다. 시작 시 `kona-node`는 L1 head에서 서명자를 읽으며, 10초 간격으로 최대 다섯 번 시도합니다. 각 시도는 그 시점의 최신 head를 기준으로 합니다.

기본적으로 Reth는 head 블록에 대해서만 `eth_getProof`를 제공하므로(`--rpc.eth-proof-window`가 0), 읽기가 완료되기 전에 새 L1 블록이 도착하면 읽기가 실패합니다. L1 RPC가 Reth라면 `--rpc.eth-proof-window`를 몇 블록 이상으로 설정하십시오.
</Note>

## 예시 {#examples}

**신뢰할 수 있는 로컬 L1 RPC 사용:**
```bash
kona-node node \
  --l1-eth-rpc http://localhost:8545 \
  --l1-trust-rpc=true \
  --l2-engine-rpc http://localhost:8551
```

**신뢰할 수 없는 공개 L1 RPC 사용:**
```bash
kona-node node \
  --l1-eth-rpc https://public-eth-rpc.com \
  --l1-trust-rpc=false \
  --l2-engine-rpc http://localhost:8551
```

## 보안 권장 사항 {#security-recommendations}

1. **로컬 인프라**: 신뢰 모드(`true`)는 직접 제어하는 L1 RPC에만 사용하십시오.
2. **공개 RPC**: 서드파티 엔드포인트에는 `--l1-trust-rpc=false`를 사용하십시오.
3. **공유 인프라**: L1 RPC를 공유하는 경우 신뢰를 비활성화하는 것을 고려하십시오.
4. **성능 테스트**: 검증 오버헤드는 최소한이지만 높은 처리량 시나리오에서는 측정될 수 있습니다.
