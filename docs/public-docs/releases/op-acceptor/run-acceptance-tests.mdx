This guide shows you how to run [op-acceptor](/releases/op-acceptor/explainer) against a network: define a gate in a `validators.yaml` file, run it once (the CI/CD model) or on an interval (continuous monitoring), and read the results.

## Before you begin

You need:

*   **Go** installed, since op-acceptor executes standard Go tests and is itself a Go program. Get op-acceptor from the [ethereum-optimism/infra repository](https://github.com/ethereum-optimism/infra/tree/main/op-acceptor), which also publishes [prebuilt release binaries](https://github.com/ethereum-optimism/infra/releases).
*   **A test directory** — a Go module containing the acceptance tests you want to run.
*   **A target network** to validate, such as a devnet, and its environment manifest if your tests consume one (see `DEVNET_ENV_URL` below).

## Run a gate

<Steps>
  <Step title="Define your gates in validators.yaml">
    op-acceptor discovers tests from a validator definitions file. A gate collects suites and tests; a suite groups related tests; each test maps to a Go test (or a whole package) in your test directory:

    ```yaml
    - id: alphanet
      description: "Alphanet validation gate"
      inherits: ["localnet"]
      suites:
        - id: interop
          description: "Interop suite"
          tests:
            - id: TestInteropSystem
    ```

    A test definition points at a Go test by name and package — or at a whole package, to run everything in it:

    ```yaml
    # Run a specific test in a specific package
    - name: TestInteropSystem
      description: "Test the interop system"
      package: github.com/ethereum-optimism/optimism/kurtosis-devnet/tests/interop

    # Run all tests in a package
    - package: github.com/ethereum-optimism/optimism/kurtosis-devnet/tests/interop
    ```

    Use `inherits` to build stricter gates on top of a baseline gate.
  </Step>

  <Step title="Run the gate once">
    Point op-acceptor at your gate, test directory, and validators file. The three flags are required:

    ```bash
    op-acceptor \
      --gate alphanet \
      --testdir ./path/to/tests/ \
      --validators validators.yaml
    ```

    If your tests read a devnet environment manifest, set `DEVNET_ENV_URL` to its location before running.

    By default the run executes the gate once and exits — ideal for CI/CD. Use the exit code to gate your pipeline: `0` means all tests passed, `1` means at least one test failed, and `2` means a runtime error such as a configuration problem.
  </Step>

  <Step title="Read the results">
    Each run writes its output under the log directory (default `logs/`, override with `--logdir`):

    ```text
    logs/
      testrun-<run-id>/
        results.html        # interactive summary with filtering and search
        summary.log         # counts by status, timeout warnings, duration
        all.log             # combined chronological output
        raw_go_events.log   # raw `go test -json` events (gotestsum-compatible)
        passed/             # per-test logs for successes
        failed/             # per-test logs for failures
    ```

    Open `results.html` in a browser for triage, or feed `raw_go_events.log` to tools that understand `go test -json` output.
  </Step>
</Steps>

## Useful variations

*   **Continuous monitoring** — add `--run-interval` (for example `--run-interval 1h`) to re-run the gate on a schedule instead of exiting after one run.
*   **Allow skips** — op-acceptor normally sets `DEVNET_EXPECT_PRECONDITIONS_MET`, so tests whose preconditions aren't met **fail** rather than skip. Pass `--allow-skips` to let them skip instead, which is useful while a network is still being brought up.
*   **Custom log location** — pass `--logdir /path/to/logs` to store results somewhere other than `./logs`.
