# Node snapshots

This page lists where to download node snapshots for OP Mainnet and OP Sepolia.
Snapshots are pre-synced execution client data directories that let you start a node from a recent chain state instead of replaying from genesis.
For step-by-step instructions on downloading, verifying, and extracting a snapshot, follow the [Restore a node from a snapshot guide](/node-operators/guides/management/restore-from-snapshot).

<Info>
  Snapshots are **not required** in the following cases:

  *   When running `op-reth` with [execution-layer sync](/node-operators/reference/consensus-layer-sync) on OP Sepolia and most other OP Stack chains
  *   When using [Nethermind](https://docs.nethermind.io/get-started/running-node/l2-networks#op-stack), which automatically handles snapshots

  A snapshot is the fastest way to bootstrap an archive node, and on OP Mainnet it is the simplest way to satisfy `op-reth`'s [pre-Bedrock state requirement](#op-mainnet-pre-bedrock-data).
</Info>

## OP Labs snapshots

OP Labs publishes `op-reth` snapshots at [snapshots.optimism.io](https://snapshots.optimism.io/).
Select your network on the site to see the snapshots currently available and their download links.

<Info>
  Using [aria2](https://aria2.github.io/) to download snapshots can significantly speed up the download process.
</Info>

| Network | Client | Storage layout | History |
| ------- | ------ | -------------- | ------- |
| OP Mainnet | `op-reth` | Storage v2 | Complete history (archive) |
| OP Sepolia | `op-reth` | See [snapshots.optimism.io](https://snapshots.optimism.io/) | See [snapshots.optimism.io](https://snapshots.optimism.io/) |

### OP Mainnet

The OP Mainnet snapshot is a complete-history `op-reth` data directory that uses storage v2, the default storage layout for new `op-reth` data directories.
Because it retains the full history, it is much larger than a pruned full node's data directory; plan disk space accordingly, including room for the compressed download during the restore.

The snapshot already contains the Bedrock state that `op-reth` needs on OP Mainnet, so no separate [pre-Bedrock state import](/node-operators/op-reth/run/faq/sync-op-mainnet) is required.

### OP Sepolia

OP Sepolia `op-reth` snapshots are published on [snapshots.optimism.io](https://snapshots.optimism.io/).
OP Sepolia does not require a snapshot: `op-reth` can bootstrap with execution-layer sync from an empty data directory.

### Storage v1 snapshots

`op-reth` storage v1 is deprecated and reaches end of support on January 26, 2027.
See the [op-reth storage v1 deprecation notice](/notices/op-reth-storage-v1-deprecation) for details.
Start new nodes from a storage v2 snapshot so that you do not need to migrate the data directory later.

OP Labs does not publish a storage v1 snapshot for OP Mainnet.
Storage v1 `op-reth` snapshots for OP Sepolia remain on the [Data Directories](https://datadirs.optimism.io/) website for now, and will stop being published as storage v1 reaches end of support.

## OP Mainnet pre-Bedrock data

OP Mainnet underwent a large [database migration](https://web.archive.org/web/20240110231645/https://blog.oplabs.co/reproduce-bedrock-migration/) as part of the [Bedrock Upgrade](https://web.archive.org/web/20230608050602/https://blog.oplabs.co/introducing-optimism-bedrock/) in 2023.
An `op-reth` node on OP Mainnet must start from the Bedrock state.
Either restore the [OP Labs OP Mainnet snapshot](#op-mainnet), which includes it, or import it yourself by following [Sync OP Mainnet](/node-operators/op-reth/run/faq/sync-op-mainnet).

### Legacy Geth data directory

Blocks from before the Bedrock Upgrade cannot be executed by modern OP Mainnet nodes.
To run stateful queries such as `eth_call` against pre-Bedrock blocks, run a Legacy Geth (`l2geth`) node alongside your modern node, using the Legacy Geth data directory from the OP Labs managed [Data Directories](https://datadirs.optimism.io/) website.
See [Legacy Geth](/node-operators/guides/configuration/legacy-geth) and the [Legacy Geth steps in the run a node from source tutorial](/node-operators/tutorials/run-node-from-source#legacy-geth-pre-bedrock-optional).
This is only needed for OP Mainnet archive nodes that must serve pre-Bedrock state.

## Nethermind

[Nethermind](https://docs.nethermind.io/get-started/running-node/l2-networks#op-stack) automatically handles downloading and applying the necessary snapshots when you start the node. No manual snapshot download is required. The node will:

1.  Start with an empty database
2.  Automatically download the required ancient data
3.  Apply the data and continue syncing

This process is fully automated and requires no additional configuration.
When you run `Nethermind` with the `-c op-mainnet` flag, it uses this configuration automatically.

## 3rd Party Snapshots

[Allnodes](https://www.allnodes.com) provides full node snapshots for OP Mainnet and Testnet. You can find them [here](https://www.publicnode.com/snapshots#optimism).
**Please note:** Allnodes is a 3rd party provider, and the Optimism Foundation hasn't verified the snapshots.
