Now that you have op-deployer configured, it's time to spin up the sequencer for your rollup. This involves running both `op-reth` and `op-node` to create a functioning sequencer.

<Info>
  **Step 2 of 5**: This tutorial builds on [Spin up op-deployer](./op-deployer-setup). Make sure you've completed that first.
</Info>

## What you'll set up

The sequencer node consists of two core components:

- `op-reth`: Execution layer that processes transactions and maintains state
- `op-node`: Consensus layer that orders transactions and creates L2 blocks

The sequencer is responsible for:

- Ordering transactions from users
- Building L2 blocks
- Signing blocks on the P2P network

<Note>
  **Coming from op-geth?** op-reth replaces op-geth as the execution layer (op-geth reached [end-of-support on 2026-05-31](/notices/op-geth-deprecation)). The op-node configuration is unchanged. Two differences in the execution-layer flow: op-reth takes your chain's genesis as a `--chain` path rather than `geth init`'s separate genesis file, and it keeps full history by default (no `--gcmode=archive`).
</Note>

## Software installation

For spinning up a sequencer, we recommend using Docker, as it provides a simpler setup and consistent environment. Building from source is provided as an alternative for those who need more control and easier debugging.

<Tabs>
  <Tab title="Use docker">
    <Steps>
      <Step title="Set up directory structure and copy configuration files">

      ```bash
      # Create your sequencer directory inside rollup
      cd ../    # Go back to rollup directory if you're in deployer
      mkdir sequencer
      cd sequencer

      # Copy configuration files from deployer
      cp ../deployer/.deployer/genesis.json .
      cp ../deployer/.deployer/rollup.json .

      # Generate JWT secret
      openssl rand -hex 32 > jwt.txt
      chmod 600 jwt.txt
      ```
      </Step>

      <Step title="Create environment variables file">

      ```bash
      # Create .env file with your actual values
      cat > .env << 'EOF'
      # L1 Configuration - Replace with your actual RPC URLs
      L1_RPC_URL=https://sepolia.infura.io/v3/YOUR_ACTUAL_INFURA_KEY
      L1_BEACON_URL=https://ethereum-sepolia-beacon-api.publicnode.com

      # Private keys - Replace with your actual private key
      PRIVATE_KEY=YOUR_ACTUAL_PRIVATE_KEY

      # P2P configuration - Replace with your actual public IP
      # Run `curl ifconfig.me` in a separate shell to obtain the value, then paste it below
      P2P_ADVERTISE_IP=YOUR_ACTUAL_PUBLIC_IP

      EOF
      ```

      **Important**: Replace ALL placeholder values (`YOUR_ACTUAL_*`) with your real configuration values.
      </Step>

      <Step title="Create the docker-compose file">

      Create a `docker-compose.yml` file in the same directory. op-reth reads your chain's genesis from `--chain /workspace/genesis.json` and initializes it automatically on first start.

      ```yaml
      services:
        op-reth:
          image: us-docker.pkg.dev/oplabs-tools-artifacts/images/op-reth:v2.2.5
          volumes:
            # Mount entire directory to avoid file mounting issues
            - .:/workspace
          working_dir: /workspace
          ports:
            - "8545:8545"
            - "8546:8546"
            - "8551:8551"
          command:
            - "node"
            - "--chain=/workspace/genesis.json"
            - "--datadir=/workspace/op-reth-data"
            - "--http"
            - "--http.addr=0.0.0.0"
            - "--http.port=8545"
            - "--http.api=eth,net,web3,debug,txpool,admin"
            - "--http.corsdomain=*"
            - "--ws"
            - "--ws.addr=0.0.0.0"
            - "--ws.port=8546"
            - "--ws.api=eth,net,web3,debug,txpool,admin"
            - "--authrpc.addr=0.0.0.0"
            - "--authrpc.port=8551"
            - "--authrpc.jwtsecret=/workspace/jwt.txt"
            - "--rollup.disable-tx-pool-gossip"

        op-node:
          image: us-docker.pkg.dev/oplabs-tools-artifacts/images/op-node:v1.13.5
          depends_on:
            - op-reth
          volumes:
            - .:/workspace
          working_dir: /workspace
          ports:
            - "8547:8547"
            - "9222:9222"
          environment:
            - L1_RPC_URL=${L1_RPC_URL}
            - L1_BEACON_URL=${L1_BEACON_URL}
            - PRIVATE_KEY=${PRIVATE_KEY}
            - P2P_ADVERTISE_IP=${P2P_ADVERTISE_IP}
          command:
            - "op-node"
            - "--l1=${L1_RPC_URL}"
            - "--l1.beacon=${L1_BEACON_URL}"
            - "--l2=http://op-reth:8551"
            - "--l2.jwt-secret=/workspace/jwt.txt"
            - "--rollup.config=/workspace/rollup.json"
            - "--sequencer.enabled=true"
            - "--sequencer.stopped=false"
            - "--sequencer.max-safe-lag=3600"
            - "--verifier.l1-confs=4"
            - "--p2p.listen.ip=0.0.0.0"
            - "--p2p.listen.tcp=9222"
            - "--p2p.listen.udp=9222"
            - "--p2p.advertise.ip=${P2P_ADVERTISE_IP}"
            - "--p2p.advertise.tcp=9222"
            - "--p2p.advertise.udp=9222"
            - "--p2p.sequencer.key=${PRIVATE_KEY}"
            - "--rpc.addr=0.0.0.0"
            - "--rpc.port=8547"
            - "--rpc.enable-admin"
            - "--log.level=info"
            - "--log.format=json"
      ```

      <Note>
        Unlike op-geth, op-reth runs as an **archive node by default** — there is no `--gcmode=archive` flag. To run a pruned node instead, add `--full`. Permissionless chains serving withdrawal proofs should stay on the archive default; see [Running op-reth with Historical Proofs](/node-operators/tutorials/reth-historical-proofs).
      </Note>
      </Step>

      <Step title="Initialize op-reth from your genesis">

      Initialize the database from your chain's genesis before starting the node:

      ```bash
      # Make sure you're in the rollup/sequencer directory with all files copied
      cd rollup/sequencer

      docker run --rm \
        -v $(pwd):/workspace \
        -w /workspace \
        us-docker.pkg.dev/oplabs-tools-artifacts/images/op-reth:v2.2.5 \
        init --chain=/workspace/genesis.json --datadir=/workspace/op-reth-data
      ```
      </Step>

      <Step title="Start the services">

      ```bash
      # Start both services
      docker-compose up -d

      # View logs
      docker-compose logs -f
      ```
      </Step>

      <Step title="Final directory structure">

      ```bash
      rollup/
      ├── deployer/              # From previous step
      │   └── .deployer/         # Contains genesis.json and rollup.json
      └── sequencer/             # You are here
          ├── jwt.txt            # Generated JWT secret
          ├── genesis.json       # Copied from deployer
          ├── rollup.json        # Copied from deployer
          ├── .env               # Environment variables
          ├── docker-compose.yml # Docker configuration
          ├── opnode_discovery_db/ # Created by Docker
          ├── opnode_peerstore_db/ # Created by Docker
          └── op-reth-data/      # Created by op-reth init
      ```

      Your sequencer node is now operational and ready to process transactions.
      </Step>
    </Steps>

    ### op-reth configuration for sequencer

    Initialize the database from your genesis once, then start the node:

    ```bash
    op-reth init --chain=./genesis.json --datadir=./op-reth-data
    ```

    ```bash
    #!/bin/bash
    source .env

    op-reth node \
      --chain=./genesis.json \
      --datadir=./op-reth-data \
      --http \
      --http.addr=0.0.0.0 \
      --http.port=$OP_GETH_HTTP_PORT \
      --http.api=eth,net,web3,debug,txpool,admin,miner \
      --http.corsdomain="*" \
      --ws \
      --ws.addr=0.0.0.0 \
      --ws.port=$OP_GETH_WS_PORT \
      --ws.api=eth,net,web3,debug,txpool,admin \
      --authrpc.addr=0.0.0.0 \
      --authrpc.port=$OP_GETH_AUTH_PORT \
      --authrpc.jwtsecret=$JWT_SECRET \
      --rollup.disable-tx-pool-gossip
    ```

    <Note>
      `--http.api` includes `miner` because op-batcher's data-availability throttling calls
      `miner_setMaxDASize` on the execution client (op-reth implements it). Omitting `miner` makes
      the batcher log "method miner_setMaxDASize does not exist".
    </Note>

    <Note>
      **If this node will back a fault-proof challenger** (the permissionless `cannon-kona` game type
      from Karst), it also needs to serve historical execution witnesses to `kona-host`. Add the
      historical-proofs sidecar — run `op-reth proofs init` once, then start the node with
      `--proofs-history --proofs-history.storage-version v2 --proofs-history.storage-path <path>` and
      `--rpc.eth-proof-window <N>` — and enable `--safedb.path` on `op-node` so the challenger can look
      up the safe head per L1 block. See the [op-challenger configuration guide](/chain-operators/guides/configuration/op-challenger-config-guide).
    </Note>

    ### op-node configuration for sequencer

    ```bash
    #!/bin/bash
    source .env

    ./op-node/bin/op-node \
      --l1=$L1_RPC_URL \
      --l1.beacon=$L1_BEACON_URL \
      --l2=http://localhost:$OP_GETH_AUTH_PORT \
      --l2.jwt-secret=$JWT_SECRET \
      --rollup.config=./rollup.json \
      --sequencer.enabled=$SEQUENCER_ENABLED \
      --sequencer.stopped=$SEQUENCER_STOPPED \
      --sequencer.max-safe-lag=3600 \
      --verifier.l1-confs=4 \
      --p2p.listen.ip=0.0.0.0 \
      --p2p.listen.tcp=$P2P_LISTEN_PORT \
      --p2p.listen.udp=$P2P_LISTEN_PORT \
      --p2p.advertise.ip=$P2P_ADVERTISE_IP \
      --p2p.advertise.tcp=$P2P_LISTEN_PORT \
      --p2p.advertise.udp=$P2P_LISTEN_PORT \
      --p2p.sequencer.key=$PRIVATE_KEY \
      --rpc.addr=0.0.0.0 \
      --rpc.port=$OP_NODE_RPC_PORT \
      --rpc.enable-admin \
      --log.level=info \
      --log.format=json
    ```

    ### Start the sequencer

    ```bash
    cd rollup/sequencer
    ./scripts/start-op-reth.sh
    ./scripts/start-op-node.sh
    ```

    ### Verify sequencer is running

    ```bash
    curl -X POST -H "Content-Type: application/json" \
      --data '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}' \
      http://localhost:8545

    curl -X POST -H "Content-Type: application/json" \
      --data '{"jsonrpc":"2.0","method":"admin_sequencerActive","params":[],"id":1}' \
      http://localhost:8547
    ```

    Your sequencer node is now operational and ready to process transactions.
