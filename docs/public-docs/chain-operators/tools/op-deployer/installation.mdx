OP Deployer can be installed both from pre-built binaries and from source. This guide will walk you through both
methods.

## Install From Binaries

Installing OP Deployer from pre-built binaries is the easiest and most preferred way to get started. To install from
binaries, download the latest release from the [releases page](https://github.com/ethereum-optimism/optimism/releases?q=op-deployer&expanded=true) and extract the binary to a directory in your
`$PATH`.

## Install From Source

To install from source, you will need Go, `just`, and `git`. Then, run the following:

```shell
git clone git@github.com:ethereum-optimism/optimism.git # you can skip this if you already have the repo
cd optimism/op-deployer
just build
cp ./bin/op-deployer /usr/local/bin/op-deployer # or any other directory in your $PATH
```

## Runtime Dependencies

OP Deployer runs its Solidity deploy scripts with [forge](https://getfoundry.sh). Live `apply` and `bootstrap`
produce transactions with a keyless forge dry run, then sign and send only forge's recorded transactions
with txmgr, preserving automatic rebroadcasts and fee bumps. The private key is not passed to forge.
Use an up-to-date L1 RPC endpoint: each dry run is pinned to the observed head and fails before replay if that block
is unavailable. OP Deployer pins one Foundry version, in
[`version.json`](https://github.com/ethereum-optimism/optimism/blob/develop/op-deployer/pkg/deployer/forge/version.json).

*   If `forge` of that version is on your `PATH`, OP Deployer uses it.
*   If it is not, OP Deployer downloads that Foundry release to its cache directory (`--cache-dir`, default
    `~/.op-deployer/cache`) on first use, and verifies the checksum of the download. It downloads only for Linux and
    macOS.
*   Without network access, install the pinned Foundry version and put `forge` on your `PATH`.

The OP Deployer Docker images include `forge`. Go programs that use the OP Deployer packages, such as
devstack tests, have the same runtime dependencies.
