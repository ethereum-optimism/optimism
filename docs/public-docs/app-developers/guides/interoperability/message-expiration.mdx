# Message expiration

[Messages](/app-developers/guides/interoperability/message-passing) referenced between OP Stack chains have a limited validity period called the expiry window. Once this window elapses, the referenced message becomes invalid and can no longer be referenced.

For messages using [`L2ToL2CrossDomainMessenger`](/app-developers/guides/interoperability/message-passing), a message that expires before being relayed can never be relayed. Its source chain can learn this and report it, so applications can undo the send.

## The expiry window

The expiry window is an offchain constant that defines how long a cross-chain message or event emitted remains valid. For any chain in the [Superchain interop cluster](/interop/explainer#superchain-interop-cluster), messages must be referenced within 7 days (604,800 seconds) of the log being created.

## Undoing an expired message

Anyone can call `exportUndeliveredMessage` on the destination chain's `UndeliveredMessageExporter` predeploy (`0x4200000000000000000000000000000000000030`). It checks that the message was not relayed there and tells the source chain, through L1. The source chain's `L2ToL2CrossDomainMessenger` reports the message in `expiredMessages` only if the export happened more than 8 days after the message was sent (the expiry window plus a day of margin), and applications can then undo the send: the `SuperchainETHBridge` returns the ETH to the sender with `refundETH`. An earlier export is harmless: it ends up as a failed message on the source chain that can never succeed, and the message can be exported again later.

## Limitations

*   Messages sent before this feature was introduced have no recorded send time. They can never expire, and they can no longer be resent.
*   Expiry is only safe once every node and the accepted fault proof program enforce an expiry window of at most 7 days.
*   Every chain in a cluster's dependency set must also be authorized in the cluster's `ETHLockbox` and run the `UndeliveredMessageExporter`. Otherwise messages to or from it can't be marked expired, and their sends can't be refunded.
