op-acceptor was the OP Stack's network acceptance tester: a tool that ran
validation checks, written as standard Go tests, against a network to
determine whether it was ready for production. It is retired: the component
was removed from the `ethereum-optimism/infra` repository in June 2026
([infra#651](https://github.com/ethereum-optimism/infra/pull/651)) after
op-devstack dropped the sysext support it relied on.

## Overview

op-acceptor executed Go test suites against a running devnet, either by
auto-discovering every test in a directory (gateless mode) or through
gate-based validation configs that grouped tests into named gates a network
had to pass. Its releases shipped from the Optimism infra repository as
`op-acceptor/vX.Y.Z`.

**Who ran it:** OP Stack developers and devnet operators, in CI pipelines and
release qualification runs. Nothing runs it today: acceptance testing now
lives in the monorepo's
[`op-acceptance-tests`](https://github.com/ethereum-optimism/optimism/tree/develop/op-acceptance-tests)
package, which runs against the in-process `sysgo` devstack as normal Go
tests.

## Get started

op-acceptor is retired and is not a supported starting point. To
acceptance-test an OP Stack devnet today, start from the
[op-acceptance-tests README](https://github.com/ethereum-optimism/optimism/blob/develop/op-acceptance-tests/README.md)
in the Optimism monorepo.
