# Kona-node and op-node feature comparison

This source audit evaluates `develop` at `3c49e02437` on 20 October 2026. Its purpose is to identify operator-visible work needed to replace op-node with the standalone kona-node. Code present only in an open pull request is recorded separately. This is a feature inventory, not a consensus or security audit, and source inspection does not establish runtime equivalence.

## Findings that block treating the clients as interchangeable

| Area | Behavior on the evaluated baseline | Evidence and existing work |
| --- | --- | --- |
| Conductor publication | Kona imports and canonicalizes a sequenced payload before calling conductor, then logs a failed commit and still schedules gossip. op-node requires conductor acceptance first. | [Kona sequencing](../../rust/kona/crates/node/service/src/actors/sequencer/actor.rs), [op-node sequencing](../../op-node/rollup/sequencing/sequencer.go). [#23264](https://github.com/ethereum-optimism/optimism/issues/23264); implementations in #23229 and #23492 remain unmerged. |
| Conductor activation | Kona's start RPC has no head-hash argument or leader check. Conductor configuration does not itself force stopped startup in the production actor. | [Kona admin routing](../../rust/kona/crates/node/rpc/src/jsonrpsee.rs), [actor admin operations](../../rust/kona/crates/node/service/src/actors/sequencer/admin_api_impl.rs). [#23323](https://github.com/ethereum-optimism/optimism/issues/23323), #23492. |
| Conductor recovery | Kona forwards `admin_overrideLeader` to the external conductor without its expected boolean parameter. op-node's override is local and also bypasses publication commits; proxy override is a separate operator action. | [Conductor client](../../rust/kona/crates/node/service/src/actors/sequencer/conductor.rs), [op-node recovery](../../op-node/rollup/sequencing/sequencer.go). [#23266](https://github.com/ethereum-optimism/optimism/issues/23266); #23493 preserves the stronger shared assertions. |
| Unsafe payload admission | Kona acknowledges a malformed advertised block hash before downstream validation. op-node rejects it at the admin boundary. | [Admin handler](../../rust/kona/crates/node/rpc/src/admin.rs). [#22250](https://github.com/ethereum-optimism/optimism/issues/22250) already has the independent PR #23484 against develop. |
| Reset checkpoint selection | Kona loads the current EL safe label but searches for safe from unsafe, behind a full sequencing window. A benign L1 replacement can therefore cause substantial replay. Retaining a checkpoint requires its batch-input provenance, not merely a canonical L2 origin. | [Sync-start search](../../rust/kona/crates/node/engine/src/sync/mod.rs), [derivation finalizer](../../rust/kona/crates/node/service/src/actors/derivation/finalizer.rs). #23488 and #23494 change recovery but retain conservative window-based selection. |
| Sequencer build rejection | The build path lacks the stale-parent guard and treats `-38002` like an ordinary temporary RPC failure. A dropped reply can terminate the sequencer. | [Build task](../../rust/kona/crates/node/engine/src/task_queue/tasks/build/task.rs), [build errors](../../rust/kona/crates/node/engine/src/task_queue/tasks/build/error.rs). | Version identity | Rollup version and health report `kona-rpc`'s package version instead of the binary release metadata used by the CLI and metrics. | [Rollup RPC](../../rust/kona/crates/node/rpc/src/rollup.rs), [health](../../rust/kona/crates/node/rpc/src/health.rs), [binary metadata](../../rust/kona/bin/node/src/version.rs). #23490 includes a fix, together with a broader RPC refactor. |
| Validator admin reset | Reset routes through the optional sequencer client, so validators return MethodNotFound. | [Admin handler](../../rust/kona/crates/node/rpc/src/admin.rs). #23491 routes it to the engine; it remains stacked and unmerged. |
| Sync-status observability | `current_l1` uses the latest L1 head rather than derivation's cursor. | [L1 watcher](../../rust/kona/crates/node/service/src/actors/l1_watcher/chain.rs). [#18673](https://github.com/ethereum-optimism/optimism/issues/18673), independent PR #23514. |
| Sequencer key loading | A missing configured sequencer key file uses the identity-key creation path, which can silently create an unusable signing key. | [Signer flags](../../rust/kona/bin/node/src/flags/signer.rs). [#23541](https://github.com/ethereum-optimism/optimism/issues/23541), independent PR #23515. |
| P2P RPC spelling | The advertised block-address method is registered as `opp2p_blocAddr`. | [RPC registration](../../rust/kona/crates/node/rpc/src/jsonrpsee.rs). [#23542](https://github.com/ethereum-optimism/optimism/issues/23542), independent PR #23516. |

## Acceptance evidence and remaining gates

The shared conductor fixture already launches actual Kona processes through the backend-neutral CL interface and stable conductor RPC proxies. Leadership-transfer coverage no longer skips Kona: PR #23220 is merged. Do not recreate that fixture or add another equivalent CI matrix.

The baseline still skips three Kona conductor scenarios: malformed unsafe payloads, exact-head stop/restart, and disaster recovery. Their product fixes must pass the same assertions against both clients. The existing Kona/op-reth acceptance matrix is a delivery path, not evidence that skipped cases pass.

Relevant sources:

- [Conductor runtime fixture](../../op-devstack/sysgo/singlechain_variants.go).
- [Shared conductor tests](../../op-acceptance-tests/tests/base/conductor).
- [Acceptance test execution](acceptance-tests.md).
- [Kona runtime and reorg tests](../../rust/kona/tests/node).

For each production parity fix, retain focused Rust regressions and run the affected real-node acceptance behavior. Reorg/checkpoint tests must invalidate batch input while leaving an L2 origin unchanged; otherwise they cannot distinguish safe retention from unsafe origin-only shortcuts. A long-lived mixed-client devnet and recorded chaos tests remain operational gates beyond this source audit.

## Boundaries and maintenance

This inventory intentionally does not prescribe identical internal architectures, identical CLI spellings, support for retired request/response CL sync, or identical behavior for every malformed derivation input. Consensus-edge behavior and fault-proof agreement require their own protocol review and shared vectors. Deployment dashboards, alerting, and production rollout readiness require live evidence.

Before marking a row complete, verify the implementation on develop and record its regression/runtime evidence. An open PR, parsed flag, registered method, or existing test skip is not completion evidence. Re-run this comparison after the pending changes land; the pinned baseline makes the distinctions above reviewable without depending on those PRs.
