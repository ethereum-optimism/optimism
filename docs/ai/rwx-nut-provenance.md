# NUT provenance shadow

The optional `optimism-nut-provenance-shadow` regenerates every locked NUT
bundle from its recorded source commit through shared `run-main` routing.
Complete original same-SHA Circle/RWX comparison passes at `ad48c5ad075d24e3ffa09ffa4213beab0eee655d`.
Circle continues to own all required gates.

The shared runner retains Circle's normal hash-changed selection against
`origin/develop`, including its missing-base fallback. The default-off setup
parameter `c-nut_provenance_full` requests a full Circle replay, bypassing only
this job's path check. Its effective alias passes through shared routing.
Native verdicts always select every fork and run the original
`go run ./ops/scripts/nut-provenance-verify FORK`. The verifier creates the
original detached worktree, executes `just generate-nut-bundle` there, compares
the regenerated bundle byte for byte and removes the temporary worktree.

A pilot API dispatch with `main_dispatch: false` and
`c-nut_provenance_full: true` selects the isolated `nut-provenance-replay`
workflow: the original module producer and original verifier. This benchmark
selects no publisher workflow. Normal pushes and the default Circle pipeline
retain their existing routing; replay occurrences are outside the PR denominator.

Both current recorded commits pin Forge 1.2.3 and Just 1.46.0. The adapter
selects these historical generators explicitly; the verifier uses the current
CI Go toolchain. Current Forge 1.8.3 compiles the older contracts but fails on
new lint diagnostics, so substituting the current toolchain does not reproduce
these recorded builds. Original failure logs remain retained.

An opt-in Go reporting hook copies original historical configuration,
complete Git indices, every initialized submodule's index and dirty state,
the locked bundle and the actual freshly generated bundle before cleanup.
Failed generation never exports the historical snapshot as regenerated output.
Uninitialized root repositories such as `op-rbuilder` and `rollup-boost` remain
explicitly recorded; every contract library and nested gitlink must be
initialized at its original parent-index revision. Source files, generator
versions and binary hashes, actual compiler partitions and Solidity compiler
versions and binary hashes are retained. Providers may use different absolute
tool paths; their binary identities must agree.

Discovery rejects corrupt locks, duplicate or unsafe bundle paths, unpinned
tools, missing historical sources and discovery errors. Runtime and comparison
reject missing, extra, duplicate, corrupt or mismatched originals, changed
source and tools, differing complete selections and different generated bytes.
A successful generator followed by report validation failure returns failure.
Intentional process failure and cancellation retain the real exit/signal and
partial original output. Circle's artifact service omits zero-byte files;
comparison reconstructs only bytes established by the original sealed manifest.

The full replay selects every entry from the current sealed lock regardless of
base hashes. Provider base refs, base locks and original discovery stderr remain
retained and recorded separately in the comparison: Circle fetches
`origin/develop`, while RWX's detached clone need not retain that ref. Those
observations do not affect a full selection. Changed-mode reports, omitted or
duplicate forks, exclusions, corrupt base provenance and selections that differ
from the actual current lock all fail comparison. Every effective full build
input, historical source, tool and generated byte still must agree.

RWX prepares verified shared Go modules and historical tools independently.
The historical-tools package keeps immutable generators and Solidity compilers
in a separate native tool cache. Verdicts run freshly on 8 CPUs / 16 GiB, restore
verified modules and use a separate Go compiler cache. Temporary Foundry build
outputs are fresh and removed by the original verifier. Results and logs are
excluded from reusable verdict outputs. Protected `develop` warming targets only
the two producers; it executes no helpers or regeneration verdicts. This build
validation job executes zero tests and creates no synthetic test results.

The [preflight evidence](rwx-nut-provenance-evidence/preflight.json) records
complete Linux regeneration, nine Git/discovery/report/failure/stream fixtures,
fresh Go reporting tests, routing and Circle-adapter fixtures, ShellCheck,
native lint and setup/merged/full-replay Circle compilation. These rehearsals
establish implementation behavior; hosted parity is a separate acceptance step.

The [first full hosted native run](rwx-nut-provenance-evidence/hosted-preflight.json)
at `94481c20a3` passes both actual regenerations and all hosted helper fixtures.
All 134 sealed originals validate, including 5,623 Karst and 5,930 Lagoon source
entries and their complete compiler partitions. The replay's 37 routing fixtures,
Circle adapter and compiled isolated workflow pass. A Main-only Go lint failure
in the same push correctly rejected an unwrapped report error; the fix preserves
both causes with `errors.Join`, verified by a real Git fixture and the configured
custom Go linter. That native pass alone added no coverage; the later isolated
cohort below resolves complete same-SHA parity.

The [full hosted comparison](rwx-nut-provenance-evidence/parity.json) passes at
`ad48c5ad07`: Circle pipeline 135598 / job 5636728 and native run `a8b24835`
both execute every locked fork freshly with zero retries. All 105 sealed Circle
originals and 134 native originals validate. The two complete historical Git and
submodule inventories, generator and compiler binaries, actual compiler
partitions, locked bundles and newly generated bytes agree. The different base
ref observations are retained explicitly and do not influence the full replay.
This resolves one Main occurrence, bringing verified coverage to 80/86 (93%).

Native preparation and verification retain actual positive task attempts when
RWX retries a task. Source/branch identity, complete historical selection,
verified module/tool inputs and original generated-byte checks decide success.
Eleven Git/process fixtures pass, including a second-attempt preparation report,
invalid attempt rejection and missing runtime dependency rejection after a
retry. A higher attempt does not bypass any required producer input.
