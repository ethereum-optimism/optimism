# Bytecode-level soundness of `relayUndeliveredMessage` in Lean (EquiVM / EVMLean)

Status: **all claimed theorems proved** (`lake build` passes; no `sorry`/`admit`; the headline
theorems depend only on `propext`, `Classical.choice`, `Quot.sound`, asserted at build time by
`L1cdmEvm/Axioms.lean`). Sibling of `../evm-lean/` (same toolchain pins), for the L1 side of the
expiry flow.

This directory proves, on the **deployed runtime bytecode** of `L1CrossDomainMessenger`
(PR #23259 branch, tip `52ff613e14`) executed by EVMLean's `Ξ`/`Θ`:

1. **Outer frame** (`relay_success`): if a call to `relayUndeliveredMessage(H, t)` succeeds, then
   the INTEROP feature is enabled, (a) the caller's portal's SystemConfig names the caller as its
   L1CrossDomainMessenger, (b) this chain's ETHLockbox authorizes the caller's portal, (c) the
   caller's `xDomainMessageSender()` is `Predeploys.UNDELIVERED_MESSAGE_EXPORTER`, and the final
   account map is the result of a successful self-call `this.sendMessage(...)` with the exact
   calldata `sendMessageCd H t`, made from an account map with the original storage and code.
2. **Inner frame** (`send_success`): if `sendMessage` runs on exactly that calldata (no value) and
   succeeds, the final account map is: the result of a successful call to its portal,
   `depositTransaction` with the exact envelope `depositCd …` (below), from the frame's starting
   account map, followed by `++msgNonce`.
3. **Composition** (`relay_deposit`): 1 + 2 through `Θ` when the executing account holds this code
   (not behind a proxy, see "Not covered").

External calls are explicit summaries ("if the call succeeds, its first returned word is `w`");
success is never assumed. Soundness is the claim; completeness is not claimed (see below).
The statements pin the final account map (storage, transient storage, code, balances, nonces of
every account); the substate (logs, refunds, access sets) is not described.

## What is proved

Main files: `L1cdmEvm/Outer.lean`, `Inner.lean`, `Compose.lean`; vocabulary in `Spec.lean`.

### Outer frame

```lean
theorem relay_success {σ σ₀ σ' : AccountMap} {A A' : Substate} {I : ExecutionEnv} {g g' : UInt256}
    {o : ByteArray} {v : Views}
    (hcode : I.code = l1cdmRuntime) (hsel : selectorWord I = relaySelector)   -- 0x372293c3
    (hcds : I.calldata.size < 2 ^ 256) (hS : Summaries σ σ₀ I v)
    (hres : Ξ σ σ₀ g A I = .ok (.success (σ', g', A') o)) :
    RelayConds I v ∧ RelayPost σ σ₀ I σ' ∧ o = ByteArray.empty

theorem relay_outcome … :
    Ξ σ σ₀ g A I = .error .OutOfGass ∨ (∃ g' o, Ξ σ σ₀ g A I = .ok (.revert g' o)) ∨
    (∃ σ' g' A', Ξ σ σ₀ g A I = .ok (.success (σ', g', A') ByteArray.empty) ∧
      RelayConds I v ∧ RelayPost σ σ₀ I σ')

theorem relay_no_other_error … (he : Ξ σ σ₀ g A I = .error e) : e = .OutOfGass
```

(`…` = the same hypotheses as `relay_success`, `Summaries` included.)

All are universally quantified over the account maps, the substate, gas, and the whole execution
environment `I` (caller `I.source`, value, calldata contents and length, depth, `perm`, code owner,
block header). `H = argHash I = CALLDATALOAD(4)`, `t = argTime I = CALLDATALOAD(36)`.

`RelayConds I v` (`v : Views` are the seven words the view calls return, see "Summaries"):

| field | meaning |
|---|---|
| `noValue` | `I.weiValue = 0` (non-payable) |
| `calldataLen` | `68 ≤ calldatasize < 2^255 + 4` (solc's signed ABI length check) |
| `interop` | `v.feat = 1`: `systemConfig.isFeatureEnabled(Features.INTEROP)` returned `true` |
| `callerPortalClean`, `callerSCClean`, `lockboxClean` | the returned addresses are clean 160-bit words (the decoder reverts otherwise) |
| `isMessenger` | **(a)** `v.callerMsgr = addrWord I.source`: `msg.sender.portal().systemConfig().l1CrossDomainMessenger() == msg.sender` |
| `authorized` | **(b)** `v.auth = 1`: `portal.ethLockbox().authorizedPortals(callerPortal)` returned `true` |
| `fromExporter` | **(c)** `v.xSender = exporterWord` (`0x4200…0030`, the compiled `PUSH20` at pc 2672) |

`RelayPost σ σ₀ I σ'`: there is an account map `σc` with the same storage, transient storage and
code as `σ` (the seven calls are `STATICCALL`s; that they change neither is **proved**, EVMLean
`Theta_static_*`), `extcodesize(address(this)) ≠ 0` in `σc`, and

```lean
SelfCall σ₀ I (sendMessageCd (argHash I) (argTime I)) σc σ' true o
-- ∃ A_in callGas g' A', (σ', g', A', true, o) = Θ σc σ₀ A_in I.codeOwner I.sender I.codeOwner
--   (toExecute σc I.codeOwner) callGas gasPrice 0 0 cd (I.depth + 1) … I.perm
```

i.e. the final account map is the result of one successful value-0 `CALL` from the contract to
itself with calldata

```
sendMessageCd H t = 0x3dbb202b ‖ w(0x4200…0023) ‖ w(0x60) ‖ w(100000) ‖ w(68)
                    ‖ 0x763a1cb7 ‖ w(H) ‖ w(t) ‖ 0^28                       (228 bytes)
```

(`w(x)` = 32-byte big-endian word: `sendMessage(L2_TO_L2_CROSS_DOMAIN_MESSENGER,
abi.encodeCall(expireMessage, (H, t)), EXPIRE_MESSAGE_GAS_LIMIT)`). In the trace the outer frame
executes no `SSTORE`, `LOG` or value-carrying `CALL` (a fact of the proof; the statement is the
final account map). Its memory reasoning is relative to solc's free memory pointer, which after
the seven calls depends on the callees' return data sizes.

### Inner frame (the self-call)

```lean
theorem send_success {σ σ₀ σ' : AccountMap} {A A' : Substate} {I : ExecutionEnv} {g g' : UInt256}
    {o : ByteArray} {H t : UInt256}
    (hcode : I.code = l1cdmRuntime) (hcd : I.calldata = sendMessageCd H t) (hv : I.weiValue = ⟨0⟩)
    (hres : Ξ σ σ₀ g A I = .ok (.success (σ', g', A') o)) :
    I.perm = true ∧ SendPost σ σ₀ I H t σ' ∧ o = ByteArray.empty

-- send_outcome: OOG ∨ revert ∨ (StaticModeViolation ∧ I.perm = false) ∨ (success ∧ perm ∧ SendPost)
```

`SendPost σ σ₀ I H t σ'`: `extcodesize(portal) ≠ 0`, and for some `σp`, `out`

```lean
DepositCall σ₀ I (depositCd (otherMessengerWord σ I.codeOwner)
    (versionedNonce (msgNonceWord σ I.codeOwner)) (addrWord I.source) H t) σ σp true out
σ' = sstoreAccountMap I.codeOwner σp 205 (bumpNonceWord (msgNonceWord σp I.codeOwner))
```

`DepositCall` is one successful value-0 `CALL` (EVMLean `Θ`) from the contract to
`addrOf(storage[252])` (`portal`), from the frame's starting account map `σ` (the frame changes no
state before the call). The envelope, byte for byte (`Spec.lean`):

```
depositCd to nonce sender H t =
  0xe9e05c42 ‖ w(to) ‖ w(0) ‖ w(412835) ‖ w(0) ‖ w(0xa0) ‖ w(324)        depositTransaction(to, 0, gas, false, data)
  ‖ 0xd764ad0b ‖ w(nonce) ‖ w(sender) ‖ w(0x4200…0023) ‖ w(0) ‖ w(100000) ‖ w(0xc0) ‖ w(68)
  ‖ 0x763a1cb7 ‖ w(H) ‖ w(t) ‖ 0^28                                       relayMessage(…, expireMessage(H, t))
  ‖ 0^28                                                                  (548 bytes)
```

with `to = otherMessenger` (slot 207, masked to an address), `nonce =
versionedNonce(msgNonce) = (1 << 240) | (slot205 mod 2^240)` (`Encoding.encodeVersionedNonce(…, 1)`),
`sender = msg.sender`, and `412835 = baseGas(expireMessage(H, t), 100000) = 21000 +
max(285000 + 100000·64/63 + 328·16, 328·40)` (the code computes it; the proof evaluates it).
`bumpNonceWord old = (old & ~(2^240−1)) | ((old & (2^240−1)) + 1) & (2^240−1)` is exactly the
packed `uint240` write the code does; it reads `msgNonce` **after** the deposit call (from `σp`).

### Composition

```lean
theorem relay_deposit … (hS : Summaries σ σ₀ I v)
    (hself : (σ.getD I.codeOwner default).code = l1cdmRuntime) (hnp : I.codeOwner ∉ π)
    (hres : Ξ σ σ₀ g A I = .ok (.success (σ', g', A') o)) :
    RelayConds I v ∧ I.perm = true ∧ o = ByteArray.empty ∧
    ∃ σc σp out, accountStorageStateEq σ σc ∧ accountCodeStateEq σ σc ∧
      DepositCall σ₀ (selfCallEnv I (sendMessageCd (argHash I) (argTime I)) l1cdmRuntime)
        (depositCd (otherMessengerWord σ I.codeOwner) (versionedNonce (msgNonceWord σ I.codeOwner))
          (addrWord I.codeOwner) (argHash I) (argTime I)) σc σp true out ∧
      σ' = sstoreAccountMap I.codeOwner σp (UInt256.ofNat 205) (bumpNonceWord (msgNonceWord σp I.codeOwner))
```

`selfCallEnv` is the frame `Θ` builds (code owner and `msg.sender` = the contract, value 0, depth
`I.depth + 1`, permission `I.perm`). Proved from the two frames by unfolding `Θ`
(`theta_self_success`: a value-0 self-call leaves the account map unchanged before `Ξ`, and
`z = true` only on `Ξ` success). So: **the final state of a successful `relayUndeliveredMessage`
is that of one successful call from this messenger to its portal with the envelope
`depositTransaction(otherMessenger, 0, 412835, false, relayMessage(nonce, this, 0x4200…0023, 0,
100000, expireMessage(H, t)))`, then `++msgNonce`**, and the run was not static. What the portal
does with that call (one `TransactionDeposited` event for an honest portal; anything, including
re-entry, for an arbitrary one) is the portal's code, which is not verified here.

## Hypotheses, summaries, axioms (complete list)

1. `hcode`, `hsel`, `hcds`: the pinned code runs, the selector, a calldata bound that always holds.
2. **Summaries** (`Summaries σ σ₀ I v`, one `ReturnsWord` per view call, with the target and
   calldata exactly as the code makes them):

   | call | target | calldata | value |
   |---|---|---|---|
   | `systemConfig.isFeatureEnabled(INTEROP)` | `addrOf(storage[254])` | `0x47af267b ‖ w("INTEROP")` | `v.feat` |
   | `msg.sender.portal()` | `I.source` | `0x6425666b` | `v.callerPortal` |
   | `callerPortal.systemConfig()` | `addrOf v.callerPortal` | `0x33d7e2bd` | `v.callerSC` |
   | `….l1CrossDomainMessenger()` | `addrOf v.callerSC` | `0xa7119869` | `v.callerMsgr` |
   | `portal.ethLockbox()` | `addrOf(storage[252])` | `0xb682c444` | `v.lockbox` |
   | `lockbox.authorizedPortals(callerPortal)` | `addrOf v.lockbox` | `0x0fd11077 ‖ w(v.callerPortal)` | `v.auth` |
   | `msg.sender.xDomainMessageSender()` | `I.source` | `0x6e296e45` | `v.xSender` |

   `ReturnsWord σ σ₀ I target cd w`: from **any** account map with the storage, transient storage
   and code of `σ`, with any gas and substate, if the static call (EVMLean `Θ`, `w = false`)
   *succeeds*, its return data is shorter than 2^32 bytes and, if it has at least 32 bytes, its
   first 32 bytes are `w32 w`. Failing calls and short return data are unconstrained (the compiled
   decoder reverts on them; the proof follows those paths to `REVERT`). Return data longer than 32
   bytes is allowed (only the first word is decoded, as in the code). The **2^32 bound** keeps
   solc's free-memory-pointer arithmetic `p + roundup(returndatasize)` below 2^256 over seven
   calls; real return data is bounded by the gas limit, but EVMLean's gas model is not used to
   derive it. A `ReturnsWord` summary exists only if the callee's answer does not
   depend on gas, balances or the substate; a caller (`msg.sender`) that answers `portal()` or
   `xDomainMessageSender()` depending on `gasleft()` has no summary, and then `relay_success` says
   nothing about that state. A summary-free version would need a bound on the actual forwarded
   call gas and gas reasoning about the callee, which EquiVM's `RD` invariant does not expose (an
   earlier draft with a global "returns < 2^32 bytes" hypothesis was vacuous, see the review log).
3. `relay_deposit` only: `hself` (the contract's account holds this code: an unproxied
   deployment) and `hnp` (its address is not a precompile, 1–10).
4. **Lean axioms**: `propext`, `Classical.choice`, `Quot.sound` only, for `relay_success`,
   `relay_outcome`, `relay_no_other_error`, `send_success`, `send_outcome`, `relay_deposit`,
   `mock_returnsWord`, `concrete_summaries`, `concrete_self`. `L1cdmEvm/Axioms.lean`
   (`#assert_std_axioms`) fails the build otherwise. **No `native_decide` in any of them** (count:
   0): every closed bytecode fact (6000+ instruction decodes and pc sums in the generated block
   summaries, JUMPDEST membership, the 11160-byte JUMPDEST table, the memory-descriptor equalities)
   is checked by the kernel, via `KernelDecide.lean`/`KernelRun.lean` copied from
   `../evm-lean-kernel/` (proved list reformulations of EVMLean's `decode`/`D_J`). The trust base
   is the Lean 4.29 kernel (with its GMP acceleration of closed `Nat` arithmetic), EVMLean's
   definitions and EquiVM's proved `Reasoning` library.
5. `Concrete.lean`'s six executable witnesses use `native_decide` (compiled evaluation of `Ξ`);
   they are tests, not dependencies (their footprint is printed by `Axioms.lean`).

## Memory reasoning (proved, not assumed)

`SymMem.lean` describes memory by byte descriptors (`Sym.c b` concrete byte, `Sym.v k i` byte `i`
of the `k`-th symbolic word, `Sym.u` unknown) and `Frame env m B D` ("bytes `B + i` of `m` are
`D[i]`", `B` possibly symbolic). `MSTORE`/`MLOAD`/`CALLDATACOPY`/call-output copies/call-input reads
commute with descriptor operations (`frame_write`, `frame_read`, `frame_memLoad`, `frame_copy_Mem`,
`frame_mstore_selmask`, …, all proved from EVMLean's `ByteArray.write`/`readWithPadding`). Facts
about the concrete descriptor lists ("the call input is exactly `depositCd …`") are decided by the
kernel (`decide +kernel`). This handles the unaligned writes after 4-byte selectors and solc's
`copy_memory_to_memory` loops (3 iterations in the outer frame, 11 in the inner one, all unrolled
in the proof since every length is fixed by the calldata).

## Bounds and modelling notes

* Symbolic: account maps, storage (all slots), caller, value, calldata (outer frame: contents and
  length), gas, depth, `perm`, the seven returned values, return data sizes (< 2^32), `msgNonce`,
  `otherMessenger`, `portal`, `systemConfig`, the deposit call's result. Concrete: the inner
  frame's calldata structure (fixed by the outer frame; `H`, `t` symbolic), hence all loop counts.
* Gas: out of gas is always a possible outcome (`RD` is "reached or OOG"); no gas bound for
  success is proved. `relay_no_other_error` (under `Summaries`): no other exceptional halt (no
  invalid jump, stack error, static violation) in the outer frame.
* Depth: a call at depth 1024 pushes 0 and the code reverts (proved, `RD.*DepthLimit`).
* Static mode: in the outer frame nothing is written; the inner frame raises
  `StaticModeViolation` at the first `LOG2` (pc 3671, proved) if `perm = false`; so `relay_deposit`
  concludes `I.perm = true`.
* Events (`SentMessage`, `SentMessageExtension1`) are executed (their memory and gas are in the
  trace) but their topics/data are not asserted; balances and nonces of accounts are not asserted
  (every transfer here has value 0).
* Order of the checks: as compiled (`isFeatureEnabled`, then `portal()`, `systemConfig()`,
  `l1CrossDomainMessenger()`, short-circuit, `ethLockbox()`, `authorizedPortals`, short-circuit,
  `xDomainMessageSender()`); a failing check reverts with `L1CrossDomainMessenger_NotInteropMessenger`.
* `I.source` is `msg.sender` (`CALLER`), `I.sender` is `tx.origin`.

## Non-vacuity

* **Reachability** (`Concrete.lean`, `native_decide`): with mocks (generic mock = "return the word
  `SLOAD(selector)`"; portal mock records `keccak256(calldata)` of `depositTransaction`), the real
  bytecode run by `Ξ` succeeds, the portal received calldata whose keccak equals
  `keccak256(depositCd …)` of the spec, and `msgNonce` goes 7 → 8 (`success_reachable`). The same
  keccak, `0xcfb16b2d…ecd6`, is what anvil (an independent EVM) records for the same world
  (`scripts/trace_anvil.py`).
* **Each check failing reverts**: `noInterop_reverts`, `notMessenger_reverts` (a),
  `unauthorized_reverts` (b), `badSender_reverts` (c), `other_caller_reverts`.
* **The hypotheses are satisfiable on that witness** (kernel-checked): `mock_returnsWord` proves
  `ReturnsWord` symbolically for the mock bytecodes (any account map with the same storage/code,
  any gas), and `concrete_summaries` instantiates all seven summaries in `Concrete.world .ok`;
  `concrete_self` gives `hself` and `hnp` (all kernel-checked). Together with `success_reachable`
  (compiled evaluation, `native_decide`) this shows `relay_deposit`'s hypotheses hold in a world
  where the call succeeds.
* **Mutations** (each made on a copy and reverted): `exporterWord := 0x4200…002E` makes
  `OuterCall5.lean` (check (c), `decide` proves the equation false) and `Concrete.lean` fail;
  `depositGasLimit := 412836` makes `InnerMid.lean` fail (the evaluated `baseGas` and the deposit
  envelope no longer match).

## Not covered

* **Proxies.** Deployed L1CrossDomainMessengers sit behind a proxy, so `this.sendMessage` first
  runs the proxy code, which `DELEGATECALL`s the implementation with the same calldata, caller,
  value 0 and storage. `relay_deposit` needs `hself` (unproxied). The proxy code is not verified;
  in a proxied deployment `relay_success` (outer) and `send_success` (applied to the
  implementation frame: any `ExecutionEnv` with this code, calldata `sendMessageCd H t`, value 0;
  its `I.source` is the proxy = the messenger's address) both hold, but their composition through
  the proxy's `DELEGATECALL` is not proved.
* **Callees.** SystemConfig, OptimismPortal, ETHLockbox and the caller (B's L1CrossDomainMessenger,
  whose `relayMessage` sets `xDomainMessageSender` to the withdrawal's L2 sender) are summarized,
  not verified. That B's messenger only reports `0x4200…0030` for withdrawals actually sent by B's
  exporter, and that the exporter is the real one, are protocol assumptions (see the brief's
  activation and governance assumptions), not bytecode facts.
* **Completeness / liveness** is not claimed: no theorem says the call succeeds when the
  conditions hold (EquiVM's `RD` is partial correctness modulo out-of-gas, and the forwarded call
  gas is existential). Revert paths are proved to revert but their cause is not stated.
* The deposit's effect inside the portal (the `TransactionDeposited` event) and the L2 side are
  out of scope here (`../evm-lean/` proves `expireMessage`).
* `Concrete.lean` runs by compiled evaluation (`native_decide`), as in `../evm-lean/`.

## Retargeting

`scripts/regen.sh` recompiles with the default profile, checks the init code against the semver
lock, deploys it on anvil to fill the immutable, regenerates `Bytecode.lean` and the block
summaries (switching their closed facts to `evm_kdecide`), and prints the `PUSH20 0x4200…`
operands. Then:

* If only operands change (same bytecode layout; e.g. `UNDELIVERED_MESSAGE_EXPORTER` moving from
  `0x…2E` to `0x…30`, which was done this way): update `exporterWord` in `Spec.lean` and the
  decimal literal of the exporter word in `OuterCall5.lean` (`seg_xsender`), rebuild. A stale
  constant fails the build (see "Mutations").
* If the layout changes (any source edit to `relayUndeliveredMessage`, `sendMessage`,
  `_sendMessage` or the ABI helpers), pcs move: rerun `scripts/trace_anvil.py <hex> <scenario>`
  to get the new block paths and update the `l1cdm_block_<pc>` names in the trace files. The
  memory and call lemmas (`SymMem`, `CallMem`, `Tails`) do not depend on pcs.

build of this project takes **7 min 27 s** wall (≈ 1500 s CPU): the 30 generated block shards
(≈ 6 min; kernel-checking their bytecode facts is most of it) and ≈ 65 s for everything else
(peak RSS 7.3 GB for one shard). The proof files take 2–20 s each (`InnerMid.lean` ≈ 20 s).
Building all 30 shards in parallel exceeds 16 GB, hence the batches in `build.sh`.

## Review log

R1 (fresh-context reviewer, read-only, during development):

1. **High, fixed.** A summary-free variant (`relay_success_raw`/`relay_deposit_raw`) assumed
