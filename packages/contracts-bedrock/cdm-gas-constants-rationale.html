CrossDomainMessenger gas constants: rationale and history

optimism-private PR #708, branch jm/glamsterdam-gas-constants at 1f1c04cc2a, compared with develop at d1323d722b. Updated 2026-10-13.

Evidence tags: verified read from code, commit messages or tests; inferred reasoned from EVM/EIP semantics or arithmetic; unverified not confirmed. changed marks a value that differs from develop.

Reading guide

baseGas is computed on the sending chain but budgets relayMessage on the receiving chain. On develop one set of constants served both purposes on both chains. L1 is getting Amsterdam (EIP-8037 state gas) and L2 is not, so the two chains now need different budgets.

  • Each per-chain value is defined once in GasConstants.sol, named for the chain the relay executes on: L1_RELAY_* and L2_RELAY_*. They are file-level constants rather than a library, because solc 0.8.15 can't initialize a contract constant from a library constant. verified
  • Each messenger maps them onto internal constants. LOCAL_* is this chain's values, used by its own relayMessage through the _localRelay* hooks (CrossDomainMessenger.sol:266, CrossDomainMessenger.sol:285). REMOTE_* is the other chain's values, used by baseGas (L1 baseGas, L2 baseGas). So the L1 messenger uses L1_* locally and L2_* remotely, and the L2 messenger the reverse. verified
  • The public interface is unchanged from develop. The four RELAY_* getters (abstract in CrossDomainMessenger.sol:339-352) return the REMOTE_* value, the budget baseGas uses. So L1CDM.RELAY_RESERVED_GAS() is 40,000 while L1 enforces 135,000 locally. verified

Net effect against develop: only the L1 relay reserve moved (40,000 to 135,000). L1-to-L2 messages carry develop's baseGas. L2-to-L1 messages carry 95,000 more, because the L2 messenger budgets L1's reserve. verified

How the constants combine

Receiving side (relayMessage): it proceeds to the call only if hasMinGas(_minGasLimit, LOCAL_RESERVED + LOCAL_BUFFER), that is gas*63 ≥ minGas*64 + 63*(40000 + reserved + buffer) (SafeCall.sol:98-104). It then forwards gasleft() - LOCAL_RESERVED to the target, so the CALL's own charges (value transfer, cold and delegate access) and everything after the call come out of the reserve. verified

Sending side (_baseGas): executionGas = CONSTANT + CALL_OVERHEAD + RESERVED + BUFFER + minGas*64/63; size = len(message) + 260; baseGas = 21000 + max(executionGas + size*16, size*40), with the four relay terms taken from REMOTE_*. verified

Design property: if the relay is given baseGas, then after intrinsic gas and the 200k constant overhead the hasMinGas check passes, so the target gets at least _minGasLimit, and a failure can always be recorded for replay. With gas between the two (enough to record but not to call), the message is recorded in failedMessages (CrossDomainMessenger.sol:266-283). verified

Per-constant sections

Relay reserved gas: L1 135,000, L2 40,000 (develop: 40,000 on both)

Used at
Local: CrossDomainMessenger.sol:266 (inside the hasMinGas reserve) and CrossDomainMessenger.sol:285 (subtracted from forwarded gas), via the hooks L1CrossDomainMessenger.sol:143 and L2CrossDomainMessenger.sol:107. Remote: L1 baseGas and L2 baseGas into _baseGas. Values at GasConstants.sol:17 and GasConstants.sol:30.
Budgets for
The CALL's own charges, because the forwarded amount is computed before the CALL. Then everything after the call: resetting xDomainMsgSender, writing successfulMessages[hash] or failedMessages[hash] (a fresh slot), and emitting the event. verified (natspec and code)
L2: 40,000
develop's value. Without EIP-8037 the post-call work is one cold zero-to-nonzero SSTORE (22,100) plus the event and the xDomainMsgSender reset, which fits in 40k. That value has been in production since 2023. Restored in 1599f61cd5 after review: L2 is not adopting Glamsterdam, and 125k charged every L1-to-L2 message about 85k of L2 gas for nothing. verified (develop value, commit) inferred (cost breakdown)
L1: 135,000
Under Amsterdam the fresh-slot write costs 97,920 state gas (64 bytes x 1,530) on top of the SSTORE. 37ce0f6928 measured about 113k and set 125k. Review on #708 found that a message carrying ETH also pays the value transfer and cold access out of the reserve. The minimum reserve, measured under Amsterdam with a cold target burning all forwarded gas, is: verified

History
40,000 as RELAY_RESERVED_GAS in 2bf225ae17 (Apr 2023, PR #5508). 125,000 on both chains in 37ce0f6928 (squashed into 6b1b243623, #681). Split into LOCAL/REMOTE in f4dde99251. L2 back to 40,000 in 1599f61cd5. L1 to 135,000 in b53a227b1f. Moved into GasConstants.sol in 4de74c6935. Made internal in 1f1c04cc2a.
Re-measure if
EIP-8037's constants change (cost per state byte, slot size), EIP-8038 reprices cold access, or an L2 adopts 8037. In the last case L2_RELAY_RESERVED_GAS rises to the L1 value, which is a one-line change. inferred

Relay gas check buffer: 5,000 on both chains (unchanged)

Used at
CrossDomainMessenger.sol:266 via L1CrossDomainMessenger.sol:148 and L2CrossDomainMessenger.sol:112. Remote: in baseGas. Values at GasConstants.sol:21 and GasConstants.sol:34.
Budgets for
Execution between the hasMinGas check and the CALL: the xDomainMsgSender = _sender SSTORE, the gasleft() read and argument setup. verified
Derivation
A conservative round number in 2bf225ae17 (inline comment "(Conservative)"). xDomainMsgSender goes from nonzero to nonzero (the default is 0xdead), so the warm SSTORE costs 2,900 to 5,000 and creates no new state. That means EIP-8037 adds no state gas here. inferred

Relay constant overhead: 200,000 on both chains (unchanged)

Used at
Only in baseGas; there is no local use. Values at GasConstants.sol:9 and GasConstants.sol:24.
Budgets for
Fixed cost of the receiving chain's relayMessage before the check: the pause check, nonce decode, V1 hashing, cold SLOADs of successfulMessages and failedMessages, _isOtherMessenger() (the portal l2Sender() call on L1) and _isUnsafeTarget. It also absorbs the cost of recording a failure from cold storage when the check fails. inferred
Derivation
Empirical. b7b77d6c86 (PR #3023, Jul 2022) doubled it from 100,000: "I've been able to use the SDK to successfully complete deposits with these values." verified
Glamsterdam
The L1 pre-call path creates no new state, so EIP-8037 doesn't touch it. EIP-8038's cold-access repricing (not final) could. It has not been measured under Amsterdam. unverified

Relay call overhead: 40,000 on both chains (unchanged)

Used at
Only in baseGas. Values at GasConstants.sol:12 and GasConstants.sol:27. There is no local constant, because SafeCall.hasMinGas hardcodes the 40,000.
Budgets for
The dynamic parts of the CALL opcode: address access (cold, 2,600), positive value (9,000) and value to an empty account (25,000), as in hasMinGas. verified
Glamsterdam
On L1 a value-carrying CALL to an empty account costs about 198k: 183,600 state gas plus about 11k for the value transfer and about 3k for cold access. The minimum measured was 198,701. The charge lands in the caller's frame before the 63/64 split. With 40k, such withdrawals fail at their stated gas limit. Since #693 the Portal reverts, so they can be retried with more gas rather than being lost. Open decision: either raise L1_RELAY_CALL_OVERHEAD to about 200k (about 160k more on every L2-to-L1 message), or add the extra only when the message carries ETH. verified (EIP arithmetic, research measurement) inferred (impact)

Shared formula constants (unchanged from develop)

MIN_GAS_DYNAMIC_OVERHEAD 64/63
EIP-150: a CALL forwards at most 63/64 of remaining gas. b7b77d6c86 used 1016/1000, and 2bf225ae17 made it exact. EIP-8037 applies the 63/64 rule to gas_left only; how that interacts with gasleft() when a reservoir exists is not verified here. unverified
16 / 21,000 / 40 / 260
The relay transaction's intrinsic cost on the destination chain: 21,000 base; 16 gas per non-zero calldata byte; the EIP-7623 floor of 40 per non-zero byte; and 260 bytes of relayMessage encoding beyond _message (4 + 7*32 = 228, plus up to 31 bytes of padding). Added in 8de0d08097. verified
Whose rules
The destination chain's. For L1-to-L2 that means L2's rules, which Glamsterdam doesn't change. EIP-7976 (64 per byte floor) is in Glamsterdam, but only for L1 transactions. An L2-to-L1 relay is an internal call inside the finalize transaction, so no transaction floor applies there. These only need to differ per chain if an L2 adopts 7976. inferred

Hardcoded 40,000 in SafeCall.hasMinGas (unchanged)

Used at
hasMinGas, and by callWithMinGas (SafeCall.sol:124) in OptimismPortal2.finalizeWithdrawalTransaction (OptimismPortal2.sol:628).
Budgets for
The worst-case CALL dynamic cost: 2,600 + 9,000 + 25,000 = 36,600, plus headroom. The natspec's "5,700 buffer" does not reconcile with these prices. inferred
Effect
It is added on every use, so the messenger's check needs minGas*64/63 plus 40,000 + reserve + buffer. On L1 that is 180,000 (develop: 85,000); on L2 it is 85,000. verified
Glamsterdam
It does not cover the 183,600 new-account state charge, which is paid in the caller's frame before the 63/64 split. The target can therefore get less than minGas; #781's Portal minGasInvariant fuzz test fails this way (cause inferred). A possible fix is to make the allowance a parameter that the Portal and the L1 messenger raise when sending value. inferred

OptimismPortal2 constants (related, unchanged)

minimumGasLimit
OptimismPortal2.sol:369-371: bytes*40 + 21000, the minimum gas limit of an L2 deposit, governed by L2's rules. The floor term in baseGas is this same formula applied to the full relay calldata. verified
RECEIVE_DEFAULT_GAS_LIMIT
100,000 at OptimismPortal2.sol:54, used only by receive() (OptimismPortal2.sol:378). verified
Revert on messenger failure
676ffde1d5 (#693) makes finalizeWithdrawalTransaction revert with OptimismPortal_L1CDMCallFailed when the L1 messenger call reverts (OptimismPortal2.sol:641-657). A relay that runs out of gas therefore never finalizes a withdrawal unrecorded; it can be retried instead. verified

Open questions

  1. L1_RELAY_CALL_OVERHEAD: a flat ~200k, or extra gas only when ETH is attached? And does the hasMinGas parameterisation belong in #708 or its own PR?
  2. Measure the L1 pre-call path (the 200k constant overhead) and PreimageOracle.PRECOMPILE_CALL_RESERVED_GAS (100k, followed by up to three fresh-slot writes) under Amsterdam.
  3. How do state gas and the reservoir interact with gasleft() - LOCAL_RELAY_RESERVED_GAS when tx gas exceeds the 2^24 cap? Forge never creates a reservoir, so the tests cover only the worst case.
